## Phase Goal

**As a** developer building Phases 2–7, **I want to** lock the wire protocol as a versioned, fixture-proven contract enforced by an OS-agnostic server core, **so that** every later feature builds on a tested pair/auth/dispatch foundation instead of renegotiating transport and auth semantics.

<objective>
Create the `protocol/` contract directory: the versioned prose spec (SPEC.md), documentation-grade JSON schema, and the golden fixture files that BOTH the Rust and Dart codecs will be tested against. This plan locks the two wire decisions research flagged as expensive to change later: the challenge-response auth construction (HMAC key = SHA-256(raw token) — the fix for spec §4's unimplementable literal text) and the grapheme-counted diff-ops `text` schema (per D-05..D-09).

Purpose: Single source of truth. Everything in Waves 2–6 is written against these files; no codec may adjust a fixture to match its own output.
Output: `protocol/SPEC.md`, `protocol/schema/`, 19 fixture files in three family directories, fixtures README.
</objective>

    Create `protocol/SPEC.md` (versioned prose spec, protoVersion "1.0") containing, concretely:

    1. **Envelope:** JSON text frames are `{"t": string, "seq": optional integer, "p": optional object}`. Unknown fields anywhere are IGNORED on decode (per D-05); missing required fields are hard decode errors. `seq` is client-assigned, opaque to the server.
    2. **Versioning (per D-06):** `protoVersion` is `"major.minor"` string, current `"1.0"`. `hello` carries it. Server parses major; on major mismatch server replies `err` with `code:"versionMismatch"` and payload fields `serverVersion` and `clientVersion`, then closes. Minor mismatch → accepted.
    3. **Handshake FSM:** connection states `AwaitingHello → AwaitingAuth → Authed`. On valid `hello`, server replies `challenge {p:{nonce:"<64 lowercase hex chars = 32 bytes>"}}` (fresh CSPRNG nonce per connection). From `AwaitingAuth` the client either: (a) pairs — sends `pin {p:{pin:"NNNNNN"}}` (6-digit zero-padded string); on success server replies `pairOk {p:{token:"<64 lowercase hex>"}}` and the session becomes Authed (the ONLY time the raw token crosses the wire — document as an accepted v1 tradeoff per RESEARCH Open Q3); or (b) reconnects — sends `auth {p:{mac:"<64 lowercase hex>"}}`, server verifies and replies `authOk {p:{}}` or `authFail {p:{reason}}`.
    4. **Auth construction (LOCK — fixes spec §4's literal text, per RESEARCH Pattern 2/Pitfall 1):** `mac = HMAC-SHA256(key = SHA-256(raw token bytes), message = nonce bytes)`, hex lowercase. Server stores ONLY `SHA-256(token)` and uses that stored hash directly as the HMAC key for verification. Write the sentence "HMAC key = SHA-256(raw token)" verbatim in the auth section. Document replay defense (fresh nonce per connection) and the residual live-MITM-relay risk as out of v1 LAN threat model.
    5. **PIN rules:** 60s expiry, 5 attempts, 5-minute per-source-IP lockout, plus a global cap of 20 total failures (discretionary hardening per RESEARCH Open Q2). `authFail` reasons enumerated: `pinInvalid` (with `attemptsRemaining`), `pinExpired`, `lockedOut` (with `retryAfterSecs`), `noPairing`, `badMac`.
    6. **Auth gating:** before Authed, the ONLY processed incoming types are `hello`, `pin`, `auth`; everything else (including binary frames and `ping`) is silently dropped.
    7. **Message family payload table** — for every type string list required fields, optional fields, direction: `click {button: "left"|"middle"|"right"}`; `drag {action:"start"|"end", button}`; `key {code: string, mods: array of "ctrl"|"alt"|"shift"|"win" (default empty), action:"tap"|"down"|"up"}`; `text {bs: int >= 0, ins: string}`; `media {action:"playpause"|"next"|"prev"|"volup"|"voldown"|"mute"|"setvol", value: 0-100 required iff setvol}`; `power {action:"lock"|"sleep"|"restart"|"shutdown"}`; `confirm {action}` (must match a pending power action within 10s or server replies err `noPendingAction`); `apps.list` (request p:{} / server reply carries `windows:[{id:int,title:string}]`); `apps.launch {path}`; `apps.focus {id}`; `apps.close {id}`; `apps.changed {windows}` (server push); `clip.set {text}` (both directions); `clip.get {}` (server replies clip.set); `clip.changed {text}` (server push); `browser {action:"back"|"forward"|"newtab"|"closetab"|"refresh"|"zoomin"|"zoomout"}`; `present {action:"next"|"prev"|"start"|"end"|"blank"}`; `ping {ts:int}` → `pong {ts}` (echo); `err {code: string, msg: string, plus code-specific fields}`. err codes table: `versionMismatch`, `unknownType`, `noPendingAction`, `bsTooLarge`, `internal`.
    8. **Diff-ops text semantics (per RESEARCH Pitfall 4):** `bs` counts EXTENDED GRAPHEME CLUSTERS (UAX #29), never UTF-16 units or bytes. Semantics: delete `bs` graphemes at end of committed text, then insert `ins`. Client computes `bs = graphemes(old) - graphemes(commonPrefix(old,new))`, `ins = suffix of new after common prefix`. Server rejects `bs > 10000` with err `bsTooLarge`.
    9. **Binary frames:** exactly 9 bytes `[opcode u8][dx f32 LE][dy f32 LE]`, opcodes 0x01 move / 0x02 scroll. Strict decode: wrong length → error; unknown opcode → error; non-finite f32 (NaN/±Inf) → error; errored frames are dropped and counted, never routed.
    10. **Unknown type `t` (per D-07):** post-auth → server replies `err {code:"unknownType"}` with human-readable msg naming the type; connection stays alive. Pre-auth → silently dropped.
    11. **Pause semantics:** while server-side pause is active, all executor-bound messages (binary frames, click, drag, key, text, media, power, confirm, apps.launch/focus/close, clip.set, browser, present) are silently dropped; ping/pong and the handshake family still work. Activating pause releases any held input immediately. Session end for ANY reason releases all held keys/buttons (CONN-07).
    12. **Transport limits:** WebSocket max_message_size and max_frame_size = 65536 bytes (64 KB), enforced pre- and post-auth.

    Create `protocol/schema/messages.schema.json`: one JSON Schema document (draft 2020-12) with a `$defs` entry per family payload mirroring the table above — documentation-grade, not consumed by code. Create `protocol/schema/mouse-binary.md` describing the 9-byte layout with a byte-offset table.
