# Phase 11 — UI Design Contract

> Visual and interaction contract for Browser bookmarks (view · open · star current tab · delete). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Design system is LOCKED and inherited.** The seven D-12 palette tokens in `app/remote_control/lib/theme/tokens.dart` are the only colors (`theme_tokens_guard_test` forbids additions). Spacing, typography, motion and component-state idioms carry forward from the approved 09-UI-SPEC and 10-UI-SPEC verbatim. This contract declares only the deltas the segmented Browser screen needs. **Nothing here is a redesign** — the tab section, `_GroupBlock`/`_GroupHeader`/`_TabRun` rendering and the 7-button macro grid keep their shipped look.
>
> **User-locked decisions (11-CONTEXT.md D-01…D-14) are the spine of this contract.** Everything else below exercises the granted discretion **prescriptively** — the executor should implement these values, not re-derive them.

## Screen Layout — Browser (restructured for D-01 / D-02)

D-02 is read as **pixel-pinned**: the macro grid must occupy the **same rect in both segments**. Under today's single `SingleChildScrollView` the grid would shift vertically when the list region's height changes, so the grid moves out of the scroll region.

```
Scaffold (kBg)
├─ AppBar: "Browser" 16/600 kText + ConnectionHeaderChip           (unchanged)
├─ ReconnectingBannerSlot                                          (unchanged)
└─ SafeArea > Column
   ├─ Padding(16, 32, 16, 0)
   │   └─ BrowserSegment  [ Tabs | Bookmarks ]                     ← NEW, fixed height
   ├─ Expanded                                                     ← the ONLY swapped region
   │   └─ SingleChildScrollView(padding 16, 8, 16, 8)
   │        └─ segment == tabs ? _TabsSection(...) : _BookmarksSection(...)
   └─ Container(kBg, 1px kHairline TOP border, padding 16)
        └─ BrowserMacroGrid(...)                                   ← PINNED, outside the scroll
```

**Binding rules:**
- The shipped `_SectionHeader('Tabs')` is **removed** — the segment control is the section header now.
- `_TabsSection`, `_TabRun`, `_GroupBlock`, `_GroupHeader` keep their internal structure and spacing byte-for-byte. The only edit inside the tab section is the star slot (below).
- `BrowserMacroGrid` and `kBrowserActions` are **byte-untouched**; the grid only moves in the tree. Its 1px `kHairline` top edge is the new boundary signal now that content scrolls above it.
- The pinned grid's rect must be **identical** in both segments (`tester.getRect()` equality is the literal acceptance test).

### Focal points (per segment)

The screen has **one fixed anchor pair** that never moves between segments, plus **one per-segment content focal point**:

- **Fixed anchors (both segments):** the segment control is the **top anchor** — the first thing read, and the only control that changes what the middle region means. The pinned macro grid is the **bottom anchor** — always present, always in the same rect, and the reason the screen still works when the extension is absent.
- **Tabs segment — primary visual anchor: the active tab row.** It is the only row carrying a `kAccent` border at rest, so the eye lands on "which tab the PC is showing" before reading any title. Nothing else in this segment may carry a resting accent.
- **Bookmarks segment — primary visual anchor: the current folder's row list, headed by the folder bar when depth > 0.** At depth 0 the anchor is the roots list itself (D-08); at depth > 0 it is the 16/600 folder title, which is the only Heading-sized text in the scroll region and answers "where am I" before any row is read.

There is **no resting accent anywhere in the Bookmarks segment** — accent appears only as a 100ms press flash. That asymmetry is deliberate: the Tabs segment has a true "current" item to anchor on, the Bookmarks segment does not, and inventing a highlighted row there would be a lie about PC state.

## Component 1 — Segment control (`Tabs | Bookmarks`)

- Clone of `_ScrollDirectionSegment` + `_SegmentButton`: two `Expanded` buttons, **8px** gap, `Material(color: kBg)` + `InkWell`, radius 8, `minHeight 40`, `Border.all(selected ? kAccent : kHairline)`, label **14/400** `kAccent` when selected else `kMuted`.
- **Do not use Material `SegmentedButton`/`ToggleButtons`/`TabBar`** — the app hand-rolls every segment affordance (3 precedents) and zero Material segment widgets exist in `lib/`.
- **Always interactive — no `enabled` parameter, no gated variant.** The segment is *navigation*, not a send (`KeyboardTabBar`'s explicit rule, `key_pads.dart:188-192`). It works offline and unauthed.
- Tap: `hapticTick()` + instant swap. **No cross-fade, no slide, no page animation** — D-02's "list swap, not a navigation" requires the switch to read as instantaneous.
- **Persistence (discretion resolved — persist).** New prefs key `browser.segment`, values `tabs` | `bookmarks`, default `tabs`, via the `KeyRowGroupStore`/`PrefsKv` pattern (unknown or corrupt read degrades to `tabs`, fire-and-forget save on change). Matches the shipped `keyboard.pad` precedent.
- **D-03 interaction with persistence:** `bm.list` primes the first time the Bookmarks segment is *displayed* in a screen mount — whether reached by tap or restored from prefs — guarded by a single `bool _bmPrimed` so it never re-sends on a second switch. `tabs.list` still primes on screen open, unchanged.

## Component 2 — Bookmarks list region

### Region structure

```
_BookmarksSection
├─ (only when snapshot.truncated) truncation-count line   12/400 kMuted
├─ (only when depth > 0) folder bar                        48px
├─ 8px
├─ body:  install hint | empty copy | rows
└─ (trailing, conditional) truncation line / delete hint   12/400 kMuted
```

### Body state selection (in order — first match wins)

| Condition | Renders |
|-----------|---------|
| `connected == false` | `_InstallHintCard` — **the exact same card and copy as the Tabs segment** (shared, D-fallback locked on the tabs side) |
| connected, zero nodes in the whole tree | Muted one-liner: `No bookmarks yet.` |
| connected, current folder has zero children | Muted one-liner: `This folder is empty.` |
| otherwise | Bookmark/folder rows |

### Folder bar (depth > 0 only)

`Row` at 48px height, no fill, no border:

```
[ 48×48 InkWell(CircleBorder) → Symbols.arrow_back_rounded 20px kMuted ]   ← Semantics(button: true, label: kBmBackSemantic)
[ 8px ]
[ Expanded Text(currentFolderTitle, 16/600 kText, maxLines 1, ellipsis) ]
```

- Tap back: `hapticTick()` + pop one level of the local back stack.
- **Accessibility:** the back button is icon-only and MUST carry a semantic label — see § Accessibility Labels.
- **Android system back** pops one folder level while depth > 0 (`PopScope`, `canPop: depth == 0`); at depth 0 it leaves the screen normally.
- Depth 0 (the roots level, D-08) renders **no** folder bar — the segment label already says `Bookmarks`. **No horizontal breadcrumb trail** (discretion resolved): a breadcrumb costs a scrolling row for a tree the phone rarely navigates more than 2–3 deep.

### Row anatomy (folder and link share one widget)

Chrome is the `_TabRow` contract: `Material(kSurface)`, radius **16**, 1px border, `minHeight 56`, 12px horizontal padding, `InkWell` with `borderRadius` matched.

```
Row(children: [
  Icon(leadingGlyph, size: 24, color: glyphColor),
  SizedBox(width: 8),
  Expanded(Text(title, 14/400, maxLines 1, ellipsis, color: titleColor)),
  // folder only:
  Text('· $count', 12/400 kMuted),
  SizedBox(width: 4),
  Icon(Symbols.chevron_right_rounded, size: 20, color: kMuted),
])
```

| Node kind | Leading glyph | Trailing | Tap action |
|-----------|---------------|----------|-----------------|
| Folder | `Symbols.folder_rounded` 24px | `· N` count + chevron | Drill in (local nav) + `hapticTick()` |
| Link | `Symbols.bookmark_rounded` 24px | none | `bm.open {nodeId}` + `hapticTick()` |

- **Sort within a folder (discretion resolved):** folders first, then links, each preserving wire order (the extension emits BFS, which preserves Chrome's own per-parent index order). Matches Chrome's bookmark manager.
- **No favicons** (D-07) — the glyph is the only leading art.
- **D-04:** opening a link never changes the segment and never changes the current folder. Consecutive opens are supported with zero position loss.
- **Stale-folder self-heal:** if the current folder id vanishes from a new snapshot, silently reset to the root level and clear the back stack. No toast, no dialog.

### Delete affordance (D-13 / D-14)

- **Gesture (discretion resolved): long-press a row → confirm dialog.** This keeps the screen's gesture vocabulary coherent — long-press already means "remove" on tab rows in the sibling segment — and keeps the row's only content (its title) free of a permanently-visible destructive button.
- **No swipe on bookmark rows.** Swipe-to-close stays exclusive to tab rows; a destructive bookmark action must not have a fast, undoable-looking gesture.
- Long-press is offered **only** when the row is deletable: a link, or a folder with `count == 0`, and in both cases `locked != true`. A non-empty folder, a locked (managed) node, and every root folder offer **no** long-press at all — `onLongPress: null`, no visual difference, nothing to discover.
- **Discoverability line:** when the current folder holds at least one deletable child, render a final muted line after the rows: `Long-press a bookmark or empty folder to delete it.` (12/400 `kMuted`, left-aligned, 8px above). If the folder is also truncated, the truncation line renders **above** the hint line with a 4px gap. The line names the empty-folder case because D-14 genuinely permits it — `hasDeletableChild` is true for a deletable link **or** a deletable empty unlocked folder, so a hint that mentions only bookmarks advertises less than the app actually does. Naming "empty" also teaches the D-14 rule, so a user who long-presses a non-empty folder and gets nothing reads it as the documented rule rather than a broken app.

### Truncation (D-06)

| Surface | When | Copy | Style |
|---------|------|------|-------|
| Header count line (top of the region) | snapshot `truncated == true` | `Showing the first 500 bookmarks.` | 12/400 `kMuted`, 8px below |
| Inline folder line (last row of a folder) | that folder node carries `truncated == true` | `Some bookmarks here aren't shown.` | 12/400 `kMuted`, 8px above |

A folder that is **both** empty and truncated shows the **truncation line only** — never `This folder is empty.` (that would be a lie).

## Component 3 — Star slot on tab rows (D-09 / D-11 / D-12)

Inserted in `_TabRow`'s `Row` **after** the `Expanded` title, as the last child.

```
SizedBox(width: 4),
SizedBox(
  width: 48, height: 48,
  child: Semantics(
    button: true,
    label: bookmarked ? kUnstarSemantic : kStarSemantic,   // state is announced, not just drawn
    child: InkWell(
      customBorder: const CircleBorder(),
      onTap: enabled ? () => onStar(tab.id, bookmarked) : null,
      child: Icon(Symbols.star_rounded, fill: bookmarked ? 1 : 0, size: 20, color: starColor),
    ),
  ),
)
```

- **Glyph:** `Symbols.star_rounded` for both states, differentiated by the **FILL axis** (`fill: 1` filled / `fill: 0` outline). `Symbols.star_outline_rounded` **does not exist** in the pinned package `4.2951.0` — verified. (`Symbols.star_border_rounded` exists as a fallback if the fill override ever misbehaves; the fill axis is the canonical, preferred form and overrides the app-wide FILL 0 pin.)
- **Tri-state rendering (D-11 truthfulness):**

| `TabEl.bookmarked` | Renders |
|---|---|
| `true` | 48×48 slot, `fill: 1`, color `kAccent` (connected) / `kMuted` (gated) |
| `false` | 48×48 slot, `fill: 0`, color `kMuted` |
| `null` (unknown) | **No slot at all** — the row is byte-identical to today's, and the row keeps its 12px right padding |

- The row's right padding drops to **4px** whenever a slot renders (see Spacing exceptions).
- **Gesture isolation (D-09):** the star's `InkWell` is a nested recognizer inside the row's `InkWell`; a star tap must fire `onStar` **exactly once** and produce **zero** `tabs.activate` sends. Pin with a test — do not rely on reasoning about `TapGestureRecognizer` deadlines.
- **Gated:** `onTap: null`, glyph `kMuted`, geometry unchanged — muted-not-red, layout never shifts.
- **Star (add) is instant** (D-12): flip the glyph on the tap instant, `hapticTick()` on the same instant (the send instant), send `bm.star {tabId}`.
- **Unstar is confirm-gated** (D-11): the tap opens the confirm dialog and changes **nothing** visually. The optimistic flip and `hapticTick()` both fire on the dialog's **Remove** press (the send instant). Cancel leaves the star filled.
- **No animation on the fill change** — the optimistic flip must read as immediate.

## Component 4 — Confirm dialogs

One shape, three copies. Clone of the shipped revoke dialog: `AlertDialog`, `backgroundColor: kSurface`, radius 16, title 16/600 `kText`, body 14/400 `kMuted`, `TextButton` Cancel (`kMuted` label) + `FilledButton` (`kError` background, `kBg` foreground, `minimumSize (0, 48)`).

**Not** the Power screen's slide-to-confirm and **not** its red countdown dialog — those are calibrated for irreversible machine state; a bookmark is a much lower-stakes action and the house already owns a lighter destructive gate.

| Trigger | Title | Body | Confirm label |
|---------|-------|------|---------------|
| Unstar a tab (D-11) | `Remove bookmark?` | `This removes every bookmark on your PC that points to this page. It can't be undone.` | `Remove` |
| Long-press a bookmark row (D-13) | `Delete this bookmark?` | `It will be removed from your PC's bookmarks. This can't be undone.` | `Delete` |
| Long-press an empty folder row (D-14) | `Delete this folder?` | `The empty folder will be removed from your PC's bookmarks. This can't be undone.` | `Delete` |

Cancel label is `Cancel` in all three. Dismissing by barrier tap sends nothing.

**No toasts, no snackbars anywhere in this phase.** The `bm.*` family is fire-and-forget with no `err` reply by design; every failure self-heals on the next pushed snapshot, and inventing a success toast would imply a confirmation the wire does not carry.

## Interaction / Gesture Map

The row gesture budget is the reason D-09 exists — this table is the contract.

| Surface | tap-down | tap | long-press | horizontal drag |
|---------|----------|-----|------------|-----------------|
| Segment button | — | switch segment + haptic (always enabled) | — | — |
| Tab row (existing) | activate + flash + haptic | no-op | close + haptic | `Dismissible` → close + spring back |
| **Tab row star (new)** | — | **star / open unstar dialog** — must NOT activate the tab | — | drag still belongs to the `Dismissible` (correct, unchanged) |
| **Bookmark link row (new)** | flash ONLY — no send | `bm.open` + haptic | confirm → delete | **none** |
| **Folder row (new)** | flash ONLY — no navigation | drill in + haptic | confirm → delete, **only when `count == 0` and unlocked** | **none** |
| **Folder back button (new)** | — | pop one level + haptic | — | — |
| Macro button (existing) | fire + flash + haptic | — | — | — |

### Why _BmRow fires on tap while _TabRow fires on tap-down (deliberate divergence)

This table originally put the drill-in on tap-down **and** a `long-press: confirm → delete` on the same folder row. Those two are mutually exclusive by construction, and plan 11-09 implemented the contradiction faithfully. The result was Failure B, observed on device 2026-07-30 (Comet 150.0.7871.115) and recorded in `11-UAT.md`.

**The mechanism.** `BaseTapGestureRecognizer.didExceedDeadline()` calls `_checkDown()`, so `onTapDown` fires at `kPressTimeout` (100ms) whether or not the tap won the arena. `LongPressGestureRecognizer` sets `deadline: kLongPressTimeout` (500ms) and only then calls `resolve(GestureDisposition.accepted)`. A side effect on `onTapDown` therefore runs on EVERY long press, 400ms before the long press can resolve.

- `_TabRow` **survives** this because activating a tab does not remove the row, so its long-press close still lands (UAT-11 passed). Its tap-down activate is LOCKED by 11-10/11-11 and stays.
- `_BmRow` **does not survive** it: a folder drill-in REPLACES the list, so the pressed row is gone before the long press resolves. That made D-14's empty-folder delete unreachable by any gesture, and made a link's D-13 delete force an unwanted `bm.open` first.

**The rule for any future row: a row whose tap action REPLACES or REMOVES the row must fire on `onTap`, never on `onTapDown`. Only a row that survives its own tap action may keep a tap-down send.**

**Corollary, and it is load-bearing: a NON-deletable row behaves differently under a hold than a deletable one, and that is intended.** A deletable row carries a `LongPressGestureRecognizer`, which wins the arena at 500ms and rejects the tap, so nothing navigates. A non-deletable row (`onLongPress: null` — a non-empty folder, a locked node, every root) registers no long-press recognizer at all, so the tap recognizer is unopposed, has no upper time bound, and fires `onTap` on pointer-up however long the hold was. **Holding a non-empty folder and releasing therefore DOES drill in.** The D-14 gate withholds the DELETE, never the navigation. Do not "fix" this with a dummy `onLongPress`, an `onTapCancel`, or a hold timer — all three would add unspecified, untested suppression to a row that is behaving correctly.

The two row kinds are visually and tactilely identical on a quick tap — both flash on tap-down at the press instant — and differ only under a held press. This divergence is intentional; do not "harmonise" it away.

`onTapCancel` is deliberately not wired on `_BmRow`: the 100ms relax clears `_pressed` at ~200ms, 300ms before a long press can resolve, so there is no stuck-flash state to clear.

## Component State Contract

"Gated" = `ChipStatus != connected`. **Layout never shifts between states.**

**Bookmark / folder / tab row:**

| State | Fill | Border | Glyph + title |
|-------|------|--------|---------------|
| Rest (online) | `kSurface` | `kHairline` | glyph `kMuted`, title `kText` |
| Pressed flash (100ms) | `kSurface` | `kAccent` | glyph + title `kAccent` |
| Active tab (existing) | `kSurface` | `kAccent` | title `kText` |
| Gated | `kSurface` | `kHairline` | glyph + title `kMuted`, every callback null (tap, tap-down, long-press) |

**Star slot:** filled/accent · filled/muted (gated) · outline/muted · absent — per the tri-state table above.

**Segment button:** selected (`kAccent` border + label) / unselected (`kHairline` border + `kMuted` label). **No gated variant.**

**Folder bar:** back glyph `kMuted` at rest and when gated (navigation is always live); title `kText` always.

**Extension disconnected:** **both** segments flip to the shared `_InstallHintCard` in the same frame — a stale bookmark tree next to a correct install hint is an incoherent screen and is the phase's most visible failure mode (Pitfall 2).

## Motion Budgets

| Element | Duration / curve |
|---------|------------------|
| Row press flash (bookmark, folder, tab) | 100ms relax, no easing — the shipped `_TabRow` pattern. The flash still STARTS on tap-down for all three row kinds; only the ACTION moved to tap on bookmark rows, so a quick tap is visually and tactilely identical across the two segments. |
| Macro button press flash (existing) | momentary, no easing — unchanged |
| Segment switch | **0ms — instant swap.** No cross-fade, no slide, no `PageView`. |

## Accessibility Labels

Two controls in this phase are **icon-only with no adjacent text**, and the star additionally encodes its state in the FILL axis alone — a purely visual signal a screen reader cannot infer. Both MUST be wrapped in `Semantics(button: true, label: ...)`. Labels ship as named consts like every other string.

| Control | Condition | Semantic label | Const |
|---------|-----------|----------------|-------|
| Tab row star | `bookmarked == false` | `Bookmark this tab` | `kStarSemantic` |
| Tab row star | `bookmarked == true` | `Remove bookmark` | `kUnstarSemantic` |
| Folder bar back button | always | `Back to parent folder` | `kBmBackSemantic` |

**Binding rules:**
- The star's label **flips with its state** — that label is the only channel through which the bookmarked/not-bookmarked distinction reaches a non-visual user, since both states render the same glyph.
- `bookmarked == null` renders no slot, therefore no `Semantics` node — the row's accessibility tree is byte-identical to today's.
- **Gated** (`onTap: null`): keep the `Semantics` wrapper and the same label; Flutter marks the node disabled via the null callback. Do not drop or reword the label when gated.
- Rows, folder rows and segment buttons carry visible text and need **no** extra `Semantics` — their `Text` children already supply the label. Do not add redundant wrappers there.
- The folder `· N` count is decorative alongside the folder title; it needs no separate label.
