<objective>
Restructure the Browser screen around a hand-rolled `Tabs | Bookmarks` segmented control, pin the
macro grid outside the scroll region so it occupies the same rect in both segments, wire the
finished `BookmarksSection` into the swapped region, and implement D-03's lazy prime.

list swap, not a navigation" selects that reading. Under today's single `SingleChildScrollView` the
grid WOULD shift vertically when the list region's height changes, so the layout must change; that
layout (fixed header, `Expanded` scroll, pinned footer) has no analog anywhere in `lib/` and is
genuinely new work, not a copy.

Output: `browser_segment.dart`, the restructured screen with `BrowserSegmentBar`, the lazy prime,
the `PopScope` folder back, and the D-01/D-02/D-03/D-04 widget tests.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user tap → sendReliable | `bm.open` and `bm.remove` leave the phone from these callbacks |
| prefs read → UI state | A corrupt or attacker-written prefs value could select a segment |
| gated state → command callbacks | The unauthed boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-09 | Elevation of Privilege | gated commands | mitigate | `BookmarksSection` receives `enabled: authed` from the existing `status.chip == ChipStatus.connected` derivation, so every send-bearing control is inert while unauthed. The segment bar deliberately has no gate because it issues no command |
| T-11-14 | Denial of Service | corrupt `browser.segment` prefs value | mitigate | `BrowserSegmentStore.load` degrades an unset, unknown, corrupt or throwing read to `BrowserSegment.tabs` — a bad preference can never take the Browser screen down (the `KeyboardPadStore` T-10-04 precedent) |
| T-11-12 | Information Disclosure | lazy prime | mitigate | `bm.list` is sent only when the Bookmarks segment is actually displayed, so a phone that never opens it never asks the PC for bookmark titles at all (D-03). Asserted by the zero-`BmListMsg`-on-open test |
| T-11-04 | Tampering | delete path | mitigate | The screen's `onDelete` callback is reached only after `BookmarksSection`'s confirm resolves; the screen adds no second entry point to `remove` |
| T-11-13 | Tampering | PC-supplied titles | mitigate | Titles flow into `BookmarksSection` unchanged and are rendered as ellipsized single-line `Text`; the screen never parses or interpolates them |
| T-11-SC | Tampering | supply chain | mitigate | Zero new pub packages; `pubspec.yaml` is not in `files_modified` |
</threat_model>
