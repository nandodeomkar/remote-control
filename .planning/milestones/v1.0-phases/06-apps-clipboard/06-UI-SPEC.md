# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: two new push-driven tool screens plus two new hub tiles. **Apps** (favorites launch grid + live running-window list with focus/close/pin, APPS-01/02/03) and **Clipboard** (send/fetch, opt-in auto-sync with a persistent platform-honesty note, last-5 history, CLIP-01..04). This phase **extends the Phase 3/4/5 design system verbatim** — all tokens (spacing, type, color roles, motion, 48px floor, tabular figures) are inherited from `03-UI-SPEC.md` / `04-UI-SPEC.md` / `05-UI-SPEC.md` and referenced, not restated. No new hex values, sizes, weights, or spacing tokens are introduced. The two new tiles insert into the existing data-driven `kHubTiles` registry with no grid rework (D — Claude's discretion; placement below).

## Spacing Scale

Inherited from `03-UI-SPEC.md` verbatim (8-point scale, multiples of 4). No new tokens. Phase-6 usage of the existing tokens:

| Token | Value | Phase-6 usage |
|-------|-------|---------------|
| xs | 4px | App-icon ↔ title gap inside a window row and a favorite tile; gap between a favorite's icon and name |
| sm | 8px | Gap between the two Send/Fetch action buttons; gap between favorite tiles in the favorites grid; vertical gap between history entries |
| md | 16px | Screen edge padding (Apps + Clipboard); gap between the favorites section and the running-window list; gap between the action row and the auto-sync row; corner radius on rows/tiles/buttons (sheet-family radius) |
| lg | 24px | Vertical gap between major sections (favorites → running; action row → auto-sync → history) |
| xl | 32px | Top padding above the first content block on both screens (carried tool-screen rule) |
| 2xl | 48px | **Minimum touch target** (carried hard rule from Phase 4) — every favorite tile, window row, Send/Fetch button, close button hit area, history entry, and the auto-sync switch row is ≥48px in its smallest tappable dimension |
| 3xl | 64px | Favorite tile size (square, icon-over-name); Send/Fetch action-button height |

Exceptions: none. Favorite tiles are ≥64px squares; window rows are ≥56px tall (icon + wrapped title comfortably clears the 48px floor); all dimensions land on multiples of 4.

Source: Phase 3 scale; 48px floor elevated to a hard rule in Phase 4 and carried forward.

## Color

Inherited from `03-UI-SPEC.md` / `04-UI-SPEC.md` / `05-UI-SPEC.md` verbatim. **No new hex values are introduced.** This phase introduces **no destructive-colored controls** — closing a PC window uses graceful `WM_CLOSE` (the app shows its own Save prompt) and is a benign single-tap action, so `#FF6B6B` is not used anywhere on these two screens. Everything stays two-tone neutral + reserved accent.

| Role | Value | Phase-6 usage |
|------|-------|---------------|
| Dominant (60%) | `#0E0F12` | Scaffold background on both screens |
| Secondary (30%) | `#16181D` fill, `#2A2D34` 1px borders | Favorite tiles, window rows, Send/Fetch buttons, history entries, auto-sync row surface, close-button rest; switch inactive track (`#2A2D34`) |
| Accent (10%) | `#4C8DFF` | Reserved list below only |
| Destructive / Error | `#FF6B6B` | **Not used this phase** — no destructive-colored control (see note above) |
| Reconnecting amber | `#E8A33D` | Inherited header chip/banner only — no new use |

Text colors (neutrals, not part of the 10%):
- Primary text / labels: `#E6E8EB` — window titles, favorite names, history text, button labels, section headers
- Muted text: `#6B7280` — the persistent honesty note, empty-state copy, favorite-icon fallback glyph, section headers' secondary weight is still `#E6E8EB` (muted is for de-emphasized/inert content), all controls in the not-connected gated state, and the close-button glyph at rest

Accent `#4C8DFF` reserved for (Phase-6 additions to the inherited list):
1. **Auto-sync switch ON** state: track + thumb `#4C8DFF` (the one continuously-accented control on these screens — it is the live readout of the CLIP-03 toggle, matching the Phase-5 "live state = accent" rule). OFF = inactive `#2A2D34` track, neutral thumb.
2. Send/Fetch button, favorite tile, window row, close button, and history-entry **pressed flash** (`#4C8DFF` 1px border + accent icon/label while the finger is down — the exact Phase-4/5 key-cap pressed pattern), since each tap fires a wire command.
3. **Pinned-favorite marker** (`Icons.push_pin`, `#4C8DFF`) — a small corner glyph distinguishing a favorite tile; the only decorative-ish accent, justified as a state signal (this app is pinned).

Accent is NOT used for: any surface fill or border at rest, screen titles, section headers, the honesty note, empty-state copy, app-icon content, or history text. A control at rest is always `#16181D` + `#2A2D34`; accent appears only to signal the live auto-sync state, a press, or the pinned marker.

Gated (not-connected) state (carried Phase-3/4/5 rule — muted, never red): all wire-bound controls (Send, Fetch, window rows, favorite tiles, history entries) render at `#6B7280` on `#16181D` and their sends are gated by the auth/SendPolicy seam; the header chip + banner carry the status (no per-control disabled copy). **The auto-sync switch is exempt from gating** — it is a local persisted preference, always toggleable regardless of connection.

| Element | Copy |

| Apps section headers | "Favorites" · "Open windows" |
| Favorites empty (inline hint, replaces the grid) | "Long-press an open window below to pin it here." |
| Open-windows empty (connected, no windows) | heading "No open windows" · body "Windows you open on your PC will show up here." |
| Window focus | icon+title row; no success copy (silent action). Failure toast: "That window is no longer open." (`err{windowGone}`) |
| Window close | trailing icon button; tooltip "Close window". Failure toast: "That window is no longer open." |

| Clipboard app-bar title | "Clipboard" |

| Secondary CTA | "Fetch from PC" (`Icons.arrow_downward`) |
| Send success | snackbar "Sent to PC." |
| Send — empty phone clipboard | toast "Your phone clipboard is empty." |
| Send — too large | toast "That's too large to send." (over the manual hard-cap, ~48 KiB) |

| Fetch — empty PC clipboard | toast "Your PC clipboard is empty." |
| Auto-sync toggle label | "Auto-sync clipboard" |

| History section header | "Recent" |
| History empty | heading "Nothing copied yet" · body "Text you copy will show up here." |
| History reuse (tap entry) | snackbar "Sent to PC." |

Empty states: three — the favorites-empty inline hint, the open-windows empty state, and the history empty state (all above). The screens are otherwise control surfaces; the inherited "Not connected" gating + reconnecting banner carry connection status.

Error states: all failures surface as transient toasts routed through the shared `_onFrame` `ErrMsg` arm (window-gone / launch-failed) or local pre-send checks (empty / too-large clipboard). No error dialogs, no inline persistent error copy. A transport drop mid-action shows only the inherited reconnecting banner — never a stacked error.

Destructive actions this phase: **none requiring confirmation.** Closing a PC window is a benign single tap — it sends a graceful `WM_CLOSE` (the PC app shows its own unsaved-changes prompt), so no slide-to-confirm or in-app dialog is used. Unpinning a favorite is a local, non-destructive prefs edit (reversible by re-pinning). Sensitive/password clips are skipped server-side and never reach the phone, so no client-side "are you sure" is needed.

## Interaction Contract

- **Navigation:** hub tile → Apps / Clipboard screen; plain `Navigator` `MaterialPageRoute` push (house rule — no go_router); system back pops. The header chip + banner mount on both screens.
- **Apps live refresh (APPS-03):** the list and favorites re-render from the value-equal `AppsSnapshot` on every `apps.changed` push (Riverpod notifier suppresses no-op rebuilds — house pattern). No spinner, no pull-to-refresh, no manual refresh button; the push is the single source of currency. The client sends `apps.list` once on screen-open to prime it.
- **Apps focus / close / launch:** each fires via `sendReliable` (`apps.focus{id}` / `apps.close{id}` / `apps.launch{path}`); failures return through the `ErrMsg` `_onFrame` arm and raise a toast. Focus is best-effort on the server (foreground-lock) — the client never asserts success; the window simply comes forward or the taskbar flashes.
- **Pin / unpin (D-01/D-02):** long-press a window row pins it (local `PrefsKv`, no wire) if its `path` resolved; UWP rows (`path==null`) show the non-pinnable toast. Long-press a favorite unpins it. Favorites store the resolved path + cached icon so relaunch needs no live window.
- **Clipboard send / fetch / reuse (CLIP-01/02/04):** Send reads the phone clipboard (`Clipboard.getData`) and `clip.set`s it; Fetch `clip.get`s and writes the reply to the phone clipboard (`Clipboard.setData`); tapping a history entry `clip.set`s it back to the **PC** (reuse pushes to the PC, D-06). All via `sendReliable`.
- **Auto-sync (CLIP-03 / D-03/D-04/D-05/D-08):** the toggle is a local persisted bool, default OFF. When ON, incoming `clip.changed` pushes apply to the phone clipboard (echo-suppressed by value/hash, D-05); when OFF, pushes are received but ignored (client-gated apply, RESEARCH A4). Phone→PC syncs only on `AppLifecycleState.resumed` (Android 10+ blocks background reads, D-08) and only when auto-sync is ON. The persistent honesty note states this plainly and is never hidden.
- **History (CLIP-04 / D-06):** last-5, most-recent-first, consecutive duplicates collapsed, persisted across restart. Tapping an entry pushes to the PC and adds a snackbar.
- **Haptic tick:** fires on Send, Fetch, favorite launch, window focus, window close, and history-reuse taps — press-down, not release (Phase-4 rule). The auto-sync switch uses the default Material toggle feedback. Ticks default on; the global toggle is Phase 7.
- **Reliable path only:** every Phase-6 C→S command (`apps.list/focus/close/launch`, `clip.set/get`) goes through `sendReliable`; nothing this phase touches the volatile move path or the 500ms chip/banner throttle.
- **Touch targets:** every favorite tile, window row, close button, Send/Fetch button, history entry, and the switch row ≥48px hit area.
- **Motion budget:** pressed accent flash is immediate (no easing); the switch uses the default Material toggle animation; list/favorites updates from pushes use Flutter's default implicit reordering (or none) — no bespoke animation. Nothing else animates.

Out of UI scope (server/implementation, noted for the planner): the apps thread, clipboard thread, `apps.changed`/`clip.changed` watch seams, icon extraction/PNG encode, sensitive/large-clip server-side skip, and the `WindowInfo` `icon`/`path` protocol `1.2` amendment carry no visual contract — the UI consumes `sendReliable`, the pushed snapshots, and the decoded `WindowInfo.icon`/`path` only.
