## Phase Goal

**As a** person controlling my PC from my phone, **I want to** see and manage my open windows and apps and move copied text between the two devices, **so that** I can switch apps, launch favorites, and share clipboard text without touching the laptop.

<objective>
Replace the no-op `StubClipboard` with a real `WinClipboard` on a dedicated clipboard thread, and add the authed-gated `clip.changed` push seam — the server body of the Clipboard slice. After this plan the PC clipboard is readable/writable over the wire, PC changes push live to authed phones, and sensitive/oversized/echo clips are filtered server-side so secrets never leave the PC.

Purpose: Provides the server capability the send/fetch screen (06-05) and auto-sync (06-06) drive. clip.set/clip.get router arms already exist (Phase 1) — this plan makes them real and adds the live push.

Output: `ClipState` + `ServerDeps.clip`; `session.rs` clip.changed branch (NO after-auth snapshot); `clip_thread.rs` (arboard poll + pure sensitive/large gate + echo fingerprint); `WinClipboard`; main.rs wiring; arboard/sha2 deps + DataExchange feature.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PC clipboard → wire | Clipboard text (potentially secret) must not cross to a pre-auth or off-policy peer |
| clip thread → session push | Sensitive/oversized/echo content filtered before it can be pushed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05 | Information disclosure | clip.changed push branch (session.rs) | mitigate | Branch carries `ctx.auth_state == AuthState::Authed`; and NO after-auth clip snapshot is emitted (Pitfall 8) — `clip_no_push_preauth` + `clip_no_snapshot_after_auth` assert both. A connecting phone never receives the PC clipboard implicitly |
| T-06-06 | Information disclosure | sensitive/password clips | mitigate | `should_skip_clip` skips any clip with `ExcludeClipboardContentFromMonitorProcessing` present (KeePassXC/Credential Manager/Chrome incognito set it) — the password never leaves the PC even if the phone's auto-sync is on. Fail-open residual risk (a source app that sets no exclusion format) documented in RESEARCH A3 |
| T-06-07 | Tampering / DoS | echo/sync loop | mitigate | The thread records `clip_fingerprint` of every value it `Set` from a `clip.set` and suppresses a `clip.changed` whose fingerprint matches (Pitfall 5, D-05) — no bounce-back loop |
| T-06-08 | Information disclosure | clipboard text in logs | mitigate | server-core is log-free; the binary logs lifecycle/counts only. clip.set/get/changed text is never logged (extends the SPEC §12 no-payload rule to clip.*) |
| T-06-16 | DoS | oversized clip frame | mitigate | `should_skip_clip` caps auto-sync push at 16 KiB; all clip.* frames ride under the 64 KB tungstenite cap |
| T-06-SC | Tampering | `arboard 3.6` + `sha2` install | mitigate | RESEARCH Package Legitimacy Audit: arboard (1Password org) and sha2 (RustCrypto, already in-tree) both verdict OK/Approved — no [ASSUMED]/[SUS], no blocking checkpoint required |
</threat_model>
