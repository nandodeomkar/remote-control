## Phase Goal

**As a** person controlling my PC from my phone, **I want to** see and manage my open windows and apps and move copied text between the two devices, **so that** I can switch apps, launch favorites, and share clipboard text without touching the laptop.

*(Derived faithfully from ROADMAP Phase 6 goal + SC1–SC5; this plan is the Apps-track contract slice.)*

<objective>
Amend the already-locked wire protocol for the Apps feature and stand up the `apps.changed` server push seam — the interface-first foundation the real apps thread (06-02) and the Apps screen (06-03) build against. This is the Apps vertical slice's contract layer: after it, the protocol carries window icons + launch paths, failed window commands surface an error to the client, and authed sessions receive live window-list pushes.

Purpose: Every downstream Apps artifact (WinApps executor, apps thread, Flutter Apps screen) consumes this contract. Defining it once, with fixtures, prevents the executors from guessing field shapes or error codes.

Output: `WindowInfo` gains optional `icon`+`path`; server version bumps to `1.2`; `Apps::focus/close/launch` return `bool`; router emits `err{windowGone|launchFailed}`; `session.rs` gains an authed-gated `apps.changed` branch; `ServerDeps` gains an `apps` watch receiver wired through a placeholder channel; golden fixtures + integration push test prove it.
</objective>
