## Phase Goal

**As a** person controlling my PC from my phone, **I want to** see and manage my open windows and apps and move copied text between the two devices, **so that** I can switch apps, launch favorites, and share clipboard text without touching the laptop.

<objective>
Add the live Clipboard slice: opt-in auto-sync. With it on, a PC copy appears on the phone live (clip.changed apply) and a phone copy syncs to the PC on app resume (Android 10+ honest limit), with content-value echo suppression so nothing loops. Builds on the 06-05 send/fetch/history screen and the 06-04 server push + server-side sensitive/echo filtering.

Purpose: Completes CLIP-03 — the last Clipboard requirement — turning the manual screen into a live two-way sync within platform limits.

Output: `AutoSyncStore` (default OFF) + apply-gate + client echo suppression in `ClipNotifier`; the auto-sync switch row + persistent honesty note + `AppLifecycleListener` resume hook on `ClipboardScreen`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| clip.changed → phone clipboard | Applied only under the local toggle; text still crosses the LAN to an authed phone |
| resume read → clip.set | Only the foregrounded app may read the phone clipboard (Android 10+) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-10 | Information disclosure | clip.changed applied to a phone whose auto-sync is off | mitigate | Client applies ONLY when its local toggle is on (A4); sensitive clips were already skipped server-side (06-04) so a password never crosses even with auto-sync on. Residual: non-sensitive text crosses the LAN to an authed+paired phone even when its toggle is off — accepted per RESEARCH Open Q1 (authed + LAN-only), documented |
| T-06-07b | Tampering / DoS | client-side echo loop | mitigate | `_lastSyncedText` value-equality suppresses re-applying/re-sending a value that just crossed (D-05, Pitfall 5) — complements the server fingerprint suppression (06-04) |
| T-06-18 | Information disclosure | background clipboard read | mitigate | phone→PC reads happen ONLY on `AppLifecycleState.resumed` (foreground) — never from the background (Android 10+ limit surfaced honestly via the persistent note, D-08) |
| T-06-SC | Tampering | package installs | accept | No new packages — AppLifecycleListener + Clipboard are flutter built-ins; existing riverpod/shared_preferences reused |
</threat_model>
