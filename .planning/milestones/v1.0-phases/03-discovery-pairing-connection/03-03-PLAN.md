<objective>
The multi-PC memory locked by D-07: a GUID-keyed DeviceStore where raw auth tokens live ONLY in flutter_secure_storage under `token.<deviceKey>` and non-secret metadata (name, host, port, lastConnectedAt) lives in shared_preferences as a JSON map under `devices` plus a `lastDeviceGuid` pointer. Replaces the Phase-2 in-memory token (D-10, spec-locked). Storage seams are constructor-injected (latency_probe.dart style) so tests run against fakes, including a fake secure store that throws PlatformException on demand.

Includes the manual-connection identity story: connections made by IP before any beacon is seen get the synthetic key `manual:<host>:<port>` (the wire protocol is frozen and carries no GUID, so the beacon is the only GUID source); `adoptGuid` migrates a manual entry (token + metadata) to its real GUID key once a beacon from the same host identifies the PC (supports D-03 "a successful manual connection is remembered like a discovered one").

Purpose: CONN-03's "paired phone reconnects silently" requires the token to survive app restarts; every reconnect this phase reads through this store.
Output: device_store.dart + full fake-backed test suite; flutter_secure_storage 10.3.1 and shared_preferences 2.5.5 added to pubspec.
</objective>

## Phase Goal

**As a** phone owner, **I want to** have my phone find the PC on the LAN, pair once with a PIN, and from then on connect and recover silently, **so that** connectivity is a solved problem for every later screen.

(Derived verbatim from the ROADMAP Phase 3 Goal line. This plan delivers the "pairs once" persistence half of the silent-reconnect slice.)
