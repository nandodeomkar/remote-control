## Phase Goal (slice)

**As the** owner, **I want to** my paired phones remembered across restarts and re-pairable on demand, **so that** I stop re-pairing every launch and the server pairs more than one device per run (closes the folded one-pairing-per-run todo). This wires the 07-01 auth store to a real config.toml and reworks main.rs pairing lifecycle (D-01/02/03/05).

<objective>
Give the server persistent, fail-safe config: a `config.rs` module (serde Config + `[[paired]]` records over `toml`+`dirs`) and the main.rs rework that loads it at startup, seeds `AuthManager::from_paired`, resolves device-name/port/clip-sync from it, implements smart startup + on-demand pairing (replacing the permanent re-pin loop), and re-serializes on every paired-set change (subscribing to `AuthManager.changes()`), so revoke and multi-device become durable. All file I/O stays in server-windows (server-core keeps zero-Windows-deps).

Purpose: SRV-03 persistence/multi-device/revoke depend on config.toml being the source of truth; this closes `.planning/todos/pending/2026-07-09-server-one-pairing-per-run.md`.
Output: `config.rs` + main.rs config/startup/pairing rework + config-save subscription + revoke_tx wiring.
</objective>
