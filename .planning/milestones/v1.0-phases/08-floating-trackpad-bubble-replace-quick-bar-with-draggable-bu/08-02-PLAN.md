<objective>
Extract the trackpad hot-path engine out of `_TrackpadScreenState` into a new, reusable `TrackpadCore` widget, and slim `TrackpadScreen` into a thin composition of `TrackpadCore` + its existing chrome. This is decision D8-04 — the load-bearing, highest-risk task of the phase. Because both the full Trackpad screen and the new floating window (08-04) mount the *same* `TrackpadCore`, "cursor input in the window is behavior-identical to the full screen" (SC2) is true by construction. No new REQ-IDs are mapped to Phase 8; this plan preserves the shipped PAD-01..05 hot-path and the CONN-07 held-input release contract during relocation.

Purpose: The relocation must be behavior-neutral. The risk is not "what to build" but "moving the hot path without changing its behavior" — so this plan authors the safety-net tests FIRST (there is no `trackpad_screen_test.dart` today — RESEARCH Pitfall 7), then relocates the machinery, then slims the screen as a separately verifiable step.

Output: `lib/trackpad/trackpad_core.dart` (new), a slimmed `lib/trackpad/trackpad_screen.dart`, the core + screen safety-net tests, and an extended keep-awake test.
</objective>
