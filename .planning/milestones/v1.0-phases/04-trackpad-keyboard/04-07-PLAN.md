<objective>
Close verification gap CR-01 (04-VERIFICATION.md gap 1, blocks roadmap SC2 / KEY-01;
open security threat T-04-03): the one-sided `_imeProducer.reset()` on the
disconnected transition (trackpad_screen.dart:136) desyncs the diff producer's
committed text (reset to the sentinel) from the HiddenTextInput's
TextEditingController (still holding the pre-disconnect text). `needsReseed()`
never triggers because the controller text still STARTS with the sentinel. The
first post-reconnect keystroke then replays ALL previously typed text — possibly
a password — through the guaranteed-delivery sendReliable queue, and a
post-reconnect backspace becomes an insert.

Fix (verification "missing" option 2, chosen over option 1): reset BOTH sides
atomically. The panel (which already owns the D-12 disconnected-transition
detection) fires a reset signal; the HiddenTextInput answers by writing
`producer.reseed()` back into its controller under the existing `_reseeding`
guard — producer committed text and controller text become `kImeSentinel` in the
same synchronous callback. The screen's one-sided `_imeProducer.reset()` call is
deleted. Option 2 is chosen because it also PURGES the pre-disconnect plaintext
(potentially a password) from the controller buffer — the stronger T-04-03
(Information Disclosure) closure — and because the regression test lands in the
existing keyboard_panel_test fake-changes-stream harness (option 1 would need a
new screen-level ConnectionService fake).

This preserves the D-08 locked decision (typing rides the hidden system-IME
field + computeDiff — no new diff engine, no wire change) and restores the D-12
guarantee (no phantom input survives a drop) for the text path.

Purpose: KEY-01 typing fidelity holds ACROSS disconnects, not just in the steady
state; closes security threat T-04-03 so 04-SECURITY.md can be signed off.
Output: atomic IME reset seam + two regression tests; full Flutter suite green.
</objective>
