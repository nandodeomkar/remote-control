<objective>
Fill the stubbed real Windows input executors: the `EnigoMouseKeys` methods for
click / button_down / button_up / key_down / key_up / key_tap / type_text /
backspace are currently `// Phase 4: fills this` no-ops. Wire each to a new
`Cmd` variant handled on the dedicated input thread that owns `&mut Enigo`, and
add the `keymap.rs` table that maps the wire `key.code` vocabulary to enigo
`Key` variants (KEY-02). This is the server half of clicks, drag-hold,
autorepeat, combos, and IME typing.

## Phase Goal

**As a** laptop owner, **I want to** use my phone as a precise mouse and full
keyboard for my Windows laptop, **so that** it replaces a real trackpad and
keyboard — not a toy.

_Slice framing:_ Completes the OS-injection layer so that any client producer
(the trackpad L/M/R + tap in Wave 2's client slice, the key rows + modifiers in
the keyboard slices) actually executes on Windows. The dispatch/routing/held-input
machinery already exists and is fixture-proven (router.rs) — this plan supplies
the real execution behind the `MouseKeys` trait.

Purpose: Every input family the router already routes now has a real Windows
executor; the `key.code` vocabulary is locked once so client and server agree.
Output: Extended `Cmd` enum + input-thread arms, filled `mouse_keys.rs`, new
`keymap.rs` with a coverage test.
</objective>
