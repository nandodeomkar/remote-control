# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: the interim **Remote hub screen** (D-01/D-02 — the Phase-7 dashboard skeleton, NOT throwaway) plus four new tool screens: **Media** (transport buttons + absolute volume slider + mute, MED-01/02), **Power** (four slide-to-confirm tracks + red countdown dialog for restart/shutdown, PWR-01..03), **Presenter** (full-screen split tap zones + bottom bar + manual elapsed timer, PRES-01/02), and **Browser** (macro button grid, BROW-01). This phase **extends the Phase 3/4 design system verbatim** — all tokens (spacing, type, color roles, motion) are inherited from `03-UI-SPEC.md` / `04-UI-SPEC.md` and referenced, not restated. The full 8-tile dashboard identity and its polish remain Phase 7 (UI-01/UI-02); the hub is deliberately slim but structured so Phase 7 grows it in place.

## Spacing Scale

Inherited from `03-UI-SPEC.md` verbatim (8-point scale, multiples of 4). No new tokens. Phase-5 usage of the existing tokens:

| Token | Value | Phase-5 usage |
|-------|-------|---------------|
| xs | 4px | Icon–label gap inside hub tiles and macro buttons; gap between slider and % readout |
| sm | 8px | Gap between browser macro buttons; gap between transport buttons; countdown-dialog internal spacing |
| md | 16px | Screen edge padding (hub grid, media, power, browser); gap between hub tiles; gap between slide-to-confirm tracks |
| lg | 24px | Vertical gap between the transport row and the volume block on the Media screen; section gap between the power action groups (lock/sleep vs restart/shutdown) |
| xl | 32px | Top padding above the first content block on tool screens |
| 2xl | 48px | **Minimum touch target** (carried hard rule from Phase 4) — every tile, transport button, macro button, mute button, slider thumb hit area, dialog button, and the timer tap area is ≥48px in its smallest tappable dimension |
| 3xl | 64px | Slide-to-confirm track height; presenter bottom-bar height; primary transport (play/pause) button diameter |

Exceptions: none. Hub tiles are larger than 64px (grid cells, aspect ~1.4:1) but all dimensions land on multiples of 4.

Source: Phase 3 scale; 48px floor elevated to a hard rule in Phase 4 and carried forward.

## Color

Inherited from `03-UI-SPEC.md` / `04-UI-SPEC.md` verbatim. **No new hex values are introduced.** This phase is the first to put the destructive color on interactive controls (restart/shutdown) — everywhere else stays two-tone neutral + reserved accent.

| Role | Value | Phase-5 usage |
|------|-------|---------------|
| Dominant (60%) | `#0E0F12` | Scaffold background on hub + all tool screens; presenter full-bleed surface; presenter bottom bar |
| Secondary (30%) | `#16181D` fill, `#2A2D34` 1px borders | Hub tiles, transport buttons, browser macro buttons, mute button at rest, slide-to-confirm track fill, countdown dialog surface, inactive slider track (`#2A2D34`) |
| Accent (10%) | `#4C8DFF` | Reserved list below only |
| Destructive / Error | `#FF6B6B` | **Restart and Shut down surfaces only**: their slide-thumb + label + completed-fill, the countdown dialog's confirm button (`FilledButton` tinted `#FF6B6B`, label `#0E0F12`), and the dialog heading icon. Never used for lock/sleep, media, presenter, or browser |
| Reconnecting amber | `#E8A33D` | Inherited header chip/banner only — no new use |

Text colors (neutrals, not part of the 10%):
- Primary text / labels: `#E6E8EB`
- Muted text: `#6B7280` — tile icons at rest, presenter tap-zone chevrons + captions at rest, slide-track label before drag, stopped timer, pre-snapshot volume hint, all controls in the not-connected gated state

Accent `#4C8DFF` reserved for (Phase-5 additions to the inherited list):
1. Volume slider **active track + thumb** (the one continuously-accented control — it is the live state readout of MED-02).
2. Transport / browser-macro / presenter-control button **pressed flash** (`#4C8DFF` 1px border + accent icon while finger is down — the exact Phase-4 key-cap pressed pattern).
3. **Lock and Sleep** slide-to-confirm thumb + label + progress fill (the non-destructive pair; restart/shutdown use `#FF6B6B` instead).
4. **Blank toggle active state** on the presenter bar: `#16181D` fill + `#4C8DFF` border + accent label/icon (the Phase-4 "armed chip" outline pattern).
5. **Mute engaged** state: solid `#4C8DFF` fill + `#0E0F12` icon (the Phase-4 "locked chip" solid pattern — glanceably different from rest).
6. **Running timer** text on the presenter bar (`#4C8DFF` while running; `#E6E8EB` paused; `#6B7280` stopped) — the at-a-glance running/paused read.

Accent is NOT used for: hub tile fills/borders/icons at rest, screen titles, slide tracks at rest, the countdown dialog surface, dialog "Cancel", or any decorative fill. A control at rest is always `#16181D` + `#2A2D34`; accent (or destructive red) appears only to signal live state, press, or confirm progress.

Gated (not-connected) state (carried Phase-3/4 rule — muted, never red): all tool controls render at `#6B7280` on `#16181D` and sends are gated by SendPolicy; hub tiles stay tappable (RESEARCH open question 2 resolution — the header chip + banner carry the status, no per-tile disabled states this phase).

## Component States

### Slide-to-confirm track (D-05/D-06 — the power contract)

| State | Track | Thumb | Label |
|-------|-------|-------|-------|
| Rest | `#16181D` fill, `#2A2D34` border | action color icon on `#16181D` (accent for Lock/Sleep, `#FF6B6B` for Restart/Shut down) | "Slide to {action}" 14/400 `#6B7280` |
| Dragging | progress fill = action color @20% opacity behind thumb | follows finger, action-color border | fades out with progress |
| Completed | full fill flash, then resets to Rest after effects fire | snaps to right edge, haptic tick | — |
| Cancelled (released early) | fill drains | springs back 200ms ease | fades back in |
| Disabled (not connected) | `#16181D` + `#2A2D34` | icon `#6B7280` | `#6B7280`; track inert |

Completion effects: **Lock/Sleep** → send `power {action}` then `confirm {action}` back-to-back (single gesture, two wire messages — D-05). **Restart/Shut down** → send `power {action}` only, open the countdown dialog (D-06). There is NO path that sends `confirm` for restart/shutdown without the dialog button press.

### Mute button (MED-02)

| State | Fill | Icon |
|-------|------|------|
| Unmuted (rest) | `#16181D`, `#2A2D34` border | `Icons.volume_up` `#E6E8EB` |
| Muted (engaged) | solid `#4C8DFF`, no border | `Icons.volume_off` `#0E0F12` |
| Pre-snapshot / not connected | `#16181D`, `#2A2D34` border | `#6B7280`, inert |

Solid-fill engaged state reuses the Phase-4 locked-chip pattern — muted must read at a glance. Tap sends `media {mute}`; the rendered state follows the next `vol.changed` push (server-authoritative), not an optimistic flip.

### Volume slider (MED-02, D-04)

| State | Treatment |
|-------|-----------|
| Live (snapshot received) | active track + thumb `#4C8DFF`, inactive `#2A2D34`; % readout tabular follows the thumb |
| Dragging | finger position wins; incoming `vol.changed` ignored; throttled `setvol` every ~50ms; % readout follows the finger |
| Released | next `vol.changed` push is authoritative; thumb snaps to pushed value (Pitfall-7 rounding means at most ±1) |
| Pre-snapshot (connected, no push yet) | slider disabled at `#6B7280`, readout "--" — resolves in <1s (push arrives right after auth) |
| Not connected | disabled `#6B7280`, readout "--"; store drops (never queues) `setvol` while unauthed (RESEARCH Pitfall 12) |

### Transport / browser-macro / presenter-control button (carried Phase-4 key-cap pattern)

| State | Border | Icon/Label |
|-------|--------|-----------|
| Rest | `#2A2D34` 1px | `#E6E8EB` on `#16181D` |
| Pressed | `#4C8DFF` 1px flash | `#4C8DFF`; haptic tick on press-down |
| Disabled (not connected) | `#2A2D34` 1px | `#6B7280`, sends gated |

### Presenter timer (D-08)

| State | Text color | Behavior |
|-------|-----------|----------|
| Stopped (00:00) | `#6B7280` | starts on "Start show" tap |
| Running | `#4C8DFF` 28/600 tabular | ticks 1s (widget-local `Timer.periodic`, cancelled in dispose) |
| Paused | `#E6E8EB` | tap resumes |

Tap = pause/resume; long-press = reset to 00:00. Client-local only — never a wire message.

### Blank toggle (presenter bar)

| State | Treatment |
|-------|-----------|
| Off (rest) | `#16181D` fill, `#2A2D34` border, `#E6E8EB` icon+label |
| On | `#16181D` fill, `#4C8DFF` 1px border, `#4C8DFF` icon+label (armed-chip outline pattern) |

Toggle is optimistic client state (the wire has no blank-state readback); tapping either state sends `present {blank}` and flips locally. Leaving the screen does not auto-send.

## Interaction Contract

- **Navigation (D-01/D-02):** device-row tap → hub (both call sites via one helper — Pitfall 14); hub tile tap → tool screen; plain `Navigator` pushes, system back pops. Trackpad is reached through its hub tile and is otherwise unchanged. The header chip + banner mount on the hub and every tool screen.
- **Volume drag policy (D-04):** while dragging, the finger always wins — `setvol` sent via `sendReliable` on a ~50ms throttle (tunable constant, one place), incoming `vol.changed` ignored; on release the next push is authoritative. The store drops `setvol` entirely when unauthed (drop, never queue — volume is continuous state, not a replayable command).
- **Server-authoritative volume state:** slider position and mute state render from the pushed `vol.changed` snapshot (value-equal, Riverpod notifier suppresses no-op rebuilds — house pattern), except during an active drag.
- **Power gestures (D-05/D-06):** lock/sleep = one completed slide → `power` + `confirm` back-to-back. Restart/shutdown = completed slide → `power` + dialog; dialog button → `confirm`; dialog auto-dismiss at 0s sends nothing. The client NEVER offers a single-tap path to any power action.
- **Post-confirm disconnect is expected:** after a confirmed sleep/restart/shutdown, the socket drops by design; the ReconnectFsm + banner own the recovery UX. The power screen must not surface this as an error.
- **Presenter (D-07/D-08/D-09):** tap zones send `present {next/prev}` with a haptic tick per advance; Start/End/Blank send their macros; the timer is manual, client-local, tap = pause/resume, long-press = reset. `WakelockPlus.enable()` in initState / `disable()` in dispose (trackpad precedent) — the wakelock must never leak past the presenter screen.
- **Haptic tick:** fires on transport buttons, browser macros, presenter zone taps and bar buttons, slide-to-confirm completion, and the dialog confirm — press-down, not release (Phase-4 rule). Ticks default on; the global toggle is Phase 7.
- **Reliable path only:** every Phase-5 C→S command (`media`, `power`, `confirm`, `present`, `browser`, throttled `setvol`) goes through `sendReliable`; nothing this phase touches the volatile move path or the hot-path invariant (chip/banner stay on the 500ms throttle).
- **Touch targets:** every tile, button, slide thumb, dialog button, toggle, and the timer ≥48px hit area.
- **Motion budget:** slide-thumb spring-back 200ms ease; countdown dialog uses the default Material dialog transition; pressed accent flash is immediate (no easing); tile ripple is Material default; timer color change 200ms ease. Nothing else animates. Countdown ticking is a text update, not an animation.

Out of UI scope (server/implementation, noted for the planner): the audio thread, `vol.changed` watch seam, power executors/privileges, and the protocol 1.1 amendment carry no visual contract — the UI consumes `sendReliable` and the pushed volume snapshot only.
