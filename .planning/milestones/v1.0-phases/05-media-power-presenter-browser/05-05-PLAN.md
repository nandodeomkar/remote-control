## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authed session → OS power/audio control | Post-auth commands now reach real Win32 APIs that can lock, suspend, reboot, or power off the host |
| server process → Windows privilege model | The process enables SeShutdownPrivilege on its own token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-08 | Elevation of Privilege | power.rs enable_shutdown_privilege | mitigate | Enable ONLY SE_SHUTDOWN_NAME, only inside the power executor, only when a gated action fires; ERROR_NOT_ALL_ASSIGNED checked so silent partial grants are treated as failure |
| T-05-09 | Denial of Service (self) | blocking Win32/COM calls | mitigate | Every Power method thread-spawns (SetSuspendState can block until resume — A1); all COM lives on the dedicated audio thread with recv_timeout; session/tokio workers never touch either |
| T-05-10 | Tampering (data loss) | ExitWindowsEx flags | mitigate | EWX_FORCEIFHUNG only (force-closes HUNG apps only); EWX_FORCE forbidden; non-zero planned dwReason avoids unplanned-shutdown state capture |
| T-05-11 | Elevation of Privilege | single-message power path | mitigate | Executors are ONLY reachable through the existing router `power`→`confirm` 10s single-shot gate (Phase-1 tested); this plan adds no new call path into the Power trait |
| T-05-SC | Supply Chain | Cargo.toml feature flags | accept | No new packages — only feature flags on the already-vetted, spec-locked windows 0.62 dep (RESEARCH Package Legitimacy Audit: none installed) |
</threat_model>
