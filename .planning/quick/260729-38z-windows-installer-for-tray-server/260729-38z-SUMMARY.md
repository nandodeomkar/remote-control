# Quick Task 260729-38z — Windows installer for the tray server

## Problem

The server only ever ran out of `server/target/release/server-windows.exe`.
Quitting from the tray left no launcher anywhere on the system, and the HKCU
`...\Run` autostart value pointed at that same build directory — so a
`cargo clean` or a repo move broke autostart silently, with no error and no
symptom until the next boot.

## What shipped

**Task 1 — single-instance guard** (`4005683`)

`single_instance.rs`: a named mutex (`RemoteControl.SingleInstance`) acquired in
`main` right after the tracing subscriber and before any config load, thread
spawn, or bind. A second launch logs, toasts, and returns `Ok(())`.

Needed because the installer creates three ways to start the same exe (Start
Menu, desktop icon, autostart). Previously a duplicate launch walked the entire
composition root and only failed at step 7's `bind()`, producing a misleading
"another app is using port 17777" toast — the other app being itself.

Unprefixed mutex name (per-logon-session, so two Windows users can each run
their own copy). Every failure path except a confirmed `ERROR_ALREADY_EXISTS`
fails open.

**Task 2 — installer** (`9015d9e`)

`installer/RemoteControl.iss` + `installer/build-installer.ps1`. Per-user, no
UAC. Start Menu entry always; desktop shortcut and start-with-Windows as
default-checked tasks. The extension ships inside the setup exe with its own
Start Menu shortcut to the folder. Uninstaller removes exe, shortcuts, and Run
value, then asks about `%APPDATA%\RemoteControl`.

Autostart migration lives in `[Registry]`: the Run value is written
unconditionally under the same `Remote Control` name auto-launch uses (so a
stale build-directory path is overwritten), any Task Manager "disabled"
override is cleared, and declining the startup task deletes the value instead
of leaving it dangling.

**Task 3 — docs** (`9b10180`)

DISTRIBUTION.md build/install/upgrade/uninstall flow; README's user-facing
install section rewritten around the wizard, plus a troubleshooting entry for
"I closed the program and can't find it again".

## Not done (deliberately)

The produced installer was **not run** on this machine. Installing would
relocate the exe and rewrite the owner's live HKCU Run value — an owner-driven
step, not something to do unannounced. Everything up to and including the
compiled artifact is verified.

## Surprises / notes

- `{app}` inside a Pascal `{ }` comment closes the comment at the first brace;
  the `[Code]` section uses `//` comments throughout for that reason.
- Windows PowerShell 5.1 promotes any native-exe stderr to a terminating error
  under `ErrorActionPreference = 'Stop'`, and cargo writes progress to stderr —
  `build-installer.ps1` wraps native calls in an `Invoke-Native` helper.
- Git Bash's MSYS path conversion mangles ISCC's `/DName=value` switches into
  Windows paths. Build the installer from PowerShell, not bash.
- `IsTaskSelected` is deprecated in favour of `WizardIsTaskSelected`, which is
  why the build needs Inno Setup 6.3 or newer.
