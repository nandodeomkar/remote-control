<objective>
Add `server/Cargo.lock` to `$BumpedFiles` in `tools/release.ps1` so the lockfile is staged into the release commit.

Purpose: the build stage runs `installer/build-installer.ps1`, which runs `cargo build`, which rewrites the tracked file `server/Cargo.lock` (its `server-windows` package entry is pinned at the version being bumped). The release commit stages only `$BumpedFiles`, so today that rewrite is never committed. Two consequences, both real: (1) the pushed tag names a tree whose lockfile is stale, so `cargo build --locked` from that tag fails; (2) the lockfile stays dirty afterwards, so the NEXT `release.ps1` run trips its own clean-tree preflight and dies.

Output: ONE commit touching ONE file — a single array entry plus a comment.
</objective>
