# Size the tray flyout to its measured content

`flyout.rs:21` pins the window at `(344.0, 398.0)`, `.with_resizable(false)`, and
nothing in `render` scrolls. But `flyout.rs:244-274` draws the connected-device
card only `if conn > 0` — `add_space(10)` + a card (8px inner margin, a 34px
tile, 1px stroke) ≈ 60 logical px. So 398 fits the disconnected panel and
overflows the connected one, and egui clips the remainder.

What gets clipped is the bottom: `Settings` (`:298`) is sliced in half and
`Quit` (`:311`) is gone entirely. **While any phone is connected there is no way
to quit from the tray** — which is every UAT session.

The fix is to read the height egui actually used and resize the window to it.
A second magic number keyed on `conn > 0` is explicitly out: it re-encodes the
assumption that broke, and breaks again on the next row.

## Verified against the source before planning

Four claims the approach rests on. All checked, two of them corrected:

1. **`egui::Context::used_size()` does not exist in egui 0.35.** The 0.35 name is
   `globally_used_rect()` (`egui-0.35.0/src/context.rs:2824`).
2. **No `glwin.rs` change is needed at all.** `EguiGlow::run` in 0.35 takes
   `impl FnMut(&mut egui::Ui)` (`egui_glow-0.35.0/src/winit.rs:69`), and that
   `Ui` is egui's *root* ui, built with `max_rect(ctx.viewport_rect())`
   (`context.rs:788-794`). `globally_used_rect()` is literally
   `root_ui.min_rect()` recorded at `context.rs:804`. So the flyout can read
   `ui.min_rect()` inside its own `render` closure and get the identical number
   — no new accessor, no return-value plumbing through the shared window type,
   no risk to the other three shell windows.
3. **`.with_resizable(false)` does not block a programmatic resize.** winit
   0.30's Windows `request_inner_size` never consults the resizable flag; it
   calls `WindowFlags::set_size` → `SetWindowPos`
   (`winit-0.30.13/src/platform_impl/windows/window.rs:236`,
   `window_state.rs:465`). The constraint stays as-is.
4. **That `SetWindowPos` passes `SWP_NOMOVE`** (`window_state.rs:475`) — the
   window keeps its top-left corner and therefore grows *downward*. For a
   bottom-anchored flyout that lands the new rows under the taskbar. **The
   re-anchor is not polish, it is half the fix.**

Also relied on: `render` never reads `ui.available_height()` (only
`available_width`, at `:305` and in `style::hairline`), and egui only clips
*painting*, not layout — so `min_rect` reports the full ~458px even while the
window is 398px. That is what makes the overflow measurable in the first place.

`request_inner_size` returns `None` on Windows (async). The new size arrives as
`WindowEvent::Resized`, which `mod.rs:474-479` already routes to
`Flyout::resize`. That is where the re-anchor belongs — it is the one place the
new outer size is truthful.

## Task 1 — the pure geometry, with tests first

All of it in `shell/flyout.rs` beside the code that uses it; inline
`#[cfg(test)] mod tests` is the house pattern here (`shell/settings.rs`,
`shell/tray.rs`, and 16 other modules). None of these functions touch a window,
a GL context or egui, so `cargo test` runs them with no display.

Constants:

- `const WIDTH: f64 = 344.0;` and `const INITIAL_HEIGHT: f64 = 398.0;` replacing
  the `SIZE` tuple. Keep 398 as the initial value deliberately: it is the
  *correct disconnected* height, so the common open needs no correction and only
  a connected open costs one frame of catch-up.
- `const HEIGHT_EPSILON: f64 = 1.5;` — the anti-oscillation tolerance.
- `const MIN_HEIGHT: f64 = 200.0;` — the floor.

```rust
fn next_height(content_h: f64, current_h: f64, max_h: f64) -> Option<f64>
```

Returns the inner height to request, in logical px, or `None` to leave the
window alone.

- Bail with `None` unless `content_h.is_finite()`. A frame that allocated
  nothing yields `Rect::NOTHING` (`max.y == -inf`), and a NaN would sail through
  `clamp` into `request_inner_size`.
- Upper bound is `max_h.max(MIN_HEIGHT)`, **not** `max_h`. `f64::clamp` panics
  when min > max, and a tiny work area would otherwise supply one.
- `target = content_h.clamp(MIN_HEIGHT, upper)`.
- `Some(target)` only when `(target - current_h).abs() > HEIGHT_EPSILON`.

The tolerance guards a real loop, not a hypothetical one: at 125% scale a
458.0-logical request becomes 572.5 physical, rounds to 572 or 573, and reads
back as 457.6 or 458.4. Without the guard that 0.4px is a fresh resize every
frame, each resize forces a redraw, and the shell thread spins. 1.5 sits far
above that wobble and far below the ~60px signal.

```rust
fn anchor_bottom_right(
    size: PhysicalSize<u32>, right: i32, bottom: i32, gap: i32,
) -> PhysicalPosition<i32>
```

`(right - size.width - gap, bottom - size.height - gap)` — the arithmetic
currently inlined at `flyout.rs:134-137`, lifted out so the invariant is
assertable.

Extract the work-area read too, since two call sites need it now:

```rust
struct WorkArea { right: i32, bottom: i32, height: i32 }
fn work_area(window: &Window) -> Option<WorkArea>
```

Same `SPI_GETWORKAREA` call and same `current_monitor()` fallback as today; add
`height` (`work.bottom - work.top`, or the monitor height in the fallback).
Keep the existing SAFETY comment.

Tests — name each for the behaviour, not the function:

| test | assertion |
|---|---|
| `connecting_grows_the_flyout` | `next_height(458.0, 398.0, 900.0) == Some(458.0)` |
| `disconnecting_shrinks_it_back` | `next_height(398.0, 458.0, 900.0) == Some(398.0)` |
| `sub_pixel_wobble_requests_nothing` | `next_height(398.4, 398.0, 900.0)` and `next_height(397.6, 398.0, 900.0)` are both `None` |
| `never_taller_than_the_work_area` | `next_height(2000.0, 398.0, 700.0) == Some(700.0)` |
| `a_tiny_work_area_does_not_panic` | `next_height(458.0, 398.0, 100.0) == Some(200.0)` |
| `an_unmeasured_frame_is_ignored` | `next_height(f64::NEG_INFINITY, 398.0, 900.0) == None` |
| `the_bottom_edge_never_moves` | anchor at heights 398 and 458 against `right=1920, bottom=1040, gap=12`: `y + height` is equal for both **and** equals `1040 - 12`; `x` is equal for both and `x + 344 == 1920 - 12` |

The last one is the whole bug in one assertion — a version that resizes without
re-anchoring fails it.

## Task 2 — measure, resize, re-anchor

Still `shell/flyout.rs`.

**Measure.** `render` returns the used height: its final statement becomes
`ui.min_rect().max.y`. Use `max.y`, not `height()` — the required window height
is the distance from the window top, and the two only agree while `min.y` is 0.
The full-panel border at `:154-160` paints against `ui.max_rect()` and allocates
nothing, so it cannot inflate the measurement.

**Decide.** In `Flyout::redraw`, capture it the same way `actions` is already
captured by the closure:

```rust
let mut used_h = 0.0f32;
self.gl.redraw(glass_clear(), |_window, ui| {
    used_h = render(ui, ctx, paused, &ip_text, &mut actions);
});
```

Then, before returning `actions`:

- `let win = self.gl.window();` `let scale = win.scale_factor();`
- `current_h = win.inner_size().height as f64 / scale`
- `max_h` = `work_area(win)` mapped to `height as f64 / scale - 2.0 * EDGE_GAP`,
  defaulting to `f64::INFINITY` when the read fails (the clamp is a safety net,
  not a layout rule — at every plausible DPI the ~458px panel clears it easily).
- On `Some(h)`: `let _ = win.request_inner_size(LogicalSize::new(WIDTH, h));`
  Discard the return — it is `None` on Windows because the resize is async.

Calling this from inside the `RedrawRequested` handler is safe: `SetWindowPos`
carries `SWP_ASYNCWINDOWPOS`, so `WM_SIZE` is queued rather than dispatched
re-entrantly. If a redraw beats the `Resized` event, `current_h` is still stale
and the same size is requested again — idempotent, and the guard stops it dead
once the size lands.

**Re-anchor.** `Flyout::resize` (`:73`) gains the second half:

```rust
pub fn resize(&self, size: winit::dpi::PhysicalSize<u32>) {
    self.gl.resize(size);
    position_above_tray(self.gl.window());
}
```

with a comment stating why: the window is bottom-anchored and `SWP_NOMOVE` keeps
the top-left pinned, so a taller window extends under the taskbar and clips the
same rows as before. No loop — `set_outer_position` is a move, and a move emits
no `Resized`.

`position_above_tray` keeps its name and signature and becomes: read
`work_area`, compute `gap = (EDGE_GAP * scale) as i32`, call
`anchor_bottom_right(window.outer_size(), area.right, area.bottom, gap)`,
`set_outer_position`. Early-return unchanged when the work area is unreadable.

Out of scope, do not touch: `glwin.rs` (finding 2), anything under `app/` or
`.planning/phases/`, and every version-bearing file — the repo is mid-release at
v1.7.0.
