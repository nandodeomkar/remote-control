Create `tools/gen_icons.py` (Python 3.12, Pillow only: `from PIL import Image, ImageDraw`). Repo root resolved from the script's own location (`Path(__file__).resolve().parents[1]`) so it runs from anywhere. ASCII-only print output (Windows cp1252 console).

Constants (locked design):
- `REF = 140.0` reference tile.
- `TILE_FILL = (14, 15, 18, 255)` (#0E0F12), `TILE_BORDER = (42, 48, 60, 255)` (#2A303C, the "subtle border"), border width 3 units in REF space.
- `ARROW = [(48,36),(48,108),(66,92),(78,118),(90,112),(78,87),(100,85)]`, `ARROW_FILL = (59, 130, 246, 255)` (#3B82F6).
- Corner radius = 28 units in REF space (20% of tile).

`render_tile(size)` — supersample 4x then downscale: canvas `W = size*4`, scale `k = W/REF`; new RGBA fully transparent; `draw.rounded_rectangle([0, 0, W-1, W-1], radius=28*k, fill=TILE_FILL, outline=TILE_BORDER, width=max(1, round(3*k)))`; `draw.polygon([(x*k, y*k) for (x,y) in ARROW], fill=ARROW_FILL)`; return `img.resize((size, size), Image.Resampling.LANCZOS)`.

`render_tray_glyph(size=32)` — arrow ONLY, white, transparent background (a dark tile would vanish on the dark taskbar; white glyph is the tint mask for tray states). Arrow bbox in REF space is x[48,100] (w=52), y[36,118] (h=82). On the 4x canvas: uniform scale `s` so glyph height = 82% of canvas, centered: `px = (x-48)*s + (W - 52*s)/2`, `py = (y-36)*s + (W - 82*s)/2`; fill `(255,255,255,255)`; LANCZOS downscale to `size`.

Outputs (create `server/server-windows/assets/icon/` dir):
1. `icon_{16,24,32,48,64,128,256}.png` — `render_tile(s)` each.
2. `icon.ico` — each frame rendered INDEPENDENTLY at its own supersample (crisp small sizes; do NOT let PIL auto-downscale from 256): `tiles = {s: render_tile(s) for s in SIZES}`; `tiles[256].save(ico_path, format="ICO", sizes=[(s, s) for s in SIZES], append_images=[tiles[s] for s in SIZES if s != 256])` (Pillow >= 9.1 uses append_images as exact-size ICO frames — 12.2 supports this).
3. `tray_arrow_32.png` — `render_tray_glyph(32)`.
4. Android launcher: `{"mdpi": 48, "hdpi": 72, "xhdpi": 96, "xxhdpi": 144, "xxxhdpi": 192}` — overwrite `app/remote_control/android/app/src/main/res/mipmap-{d}/ic_launcher.png` with `render_tile(px)`.

All images must be mode RGBA before save (the tray glyph especially — the Rust decoder expects PNG color type RGBA).

Create `server/server-windows/build.rs`:

```rust
//! Embeds the Windows exe icon + VERSIONINFO (branding, quick 260716-ns1).
//!
//! Gated on the TARGET os (`CARGO_CFG_TARGET_OS`, not `cfg!(target_os)` —
//! build scripts compile for the HOST) so a hypothetical cross-compile of
//! the workspace never trips rc.exe. `server-core` has no build.rs and is
//! untouched; CI Linux compiles server-core only.

fn main() {
    println!("cargo:rerun-if-changed=assets/icon/icon.ico");
    if std::env::var("CARGO_CFG_TARGET_OS").as_deref() == Ok("windows") {
        winresource::WindowsResource::new()
            .set_icon("assets/icon/icon.ico")
            .set("ProductName", "Remote Control")
            .set("FileDescription", "Remote Control")
            .compile()
            .expect("winresource: failed to embed exe icon/VERSIONINFO");
    }
}
```

Notes: `set_icon` path is relative to the crate root (build scripts run with cwd = package dir) — `assets/icon/icon.ico` from Task 1. `.set("FileDescription", ...)` is what Task Manager displays for the process. winresource fills FileVersion/ProductVersion from CARGO_PKG_VERSION automatically.
