# Age the reliable queue out with a 5s TTL

Reverses the option chosen in quick `260812-uge` (commit `991860f`) in favour of
the alternative it rejected. That task closed the phase-04 UAT item by making a
reliable frame sent with no socket a hard DROP. This one restores the queue and
bounds it in time instead.

## Why the swap

The hard drop bought correctness by retiring blip-tolerance outright: the
phase-3 rule that a sub-second outage is lossless died with it, and the queue
was left doing nothing but the millisecond-long socket-open → auth-complete
handshake window.

A TTL keeps both halves. Reconnect backoff is 1/2/4/8s ±20% jitter, so a blip
that recovers on redial #1 re-auths ~0.8–1.25s after the drop and on redial #2
at ~2.4–3.6s. **A 5s TTL therefore covers a blip that needs up to two redials
and nothing beyond it** — redial #3 lands at ~5.6–8.4s and is already past the
cutoff. Owner's decision, 2026-08-12.

Accepted cost: a frame may now be replayed up to 5s late. Judged tolerable
because within 5s the user is still holding the phone in the same context, and
because the outage case the UAT actually reported — a frame surfacing *minutes*
later into whatever window happened to be focused — is still impossible.

## Task 1 — SendPolicy ages frames out

`lib/net/send_policy.dart`

- Add the injected clock, matching the house seam (`LatencyProbe`,
  `VolumeStore`, `PresenterTimer` all take `int Function() nowMillis`):
  `required this.nowMillis`. Required, not defaulted — SendPolicy is a pure
  collaborator and a hidden `DateTime.now()` would make it untestable by
  accident.
- Add `Duration ttl = const Duration(seconds: 5)`.
- The queue holds `_Pending(frame, queuedAt)` records rather than bare frames.
- **Delete `channelUp`.** It is the no-socket gate; keeping it would make the
  TTL unreachable, because the frames a TTL exists to preserve are exactly the
  no-socket ones. `260812-uge`'s "do not simplify the two flags into one" note
  was about not *inferring* channelUp from authed — it does not survive the
  removal of the rule it protected.

```
if (authed) { send(frame); return; }
_expire();                                  // BEFORE the bound check
if (_queue.length >= maxQueue) { onOverflow?.call(); return; }
_queue.add(_Pending(frame, nowMillis()));
```

Expiry must run before the `maxQueue` comparison. Otherwise a long outage fills
the queue with 10 corpses and the next *live* frame overflows against them —
firing `onOverflow` and dropping the one frame that was still valid.

`flushOnAuthed` expires first, then sends survivors FIFO.

Boundary: a frame is expired when `age >= ttl` (`queuedAt <= now - ttl`), so
exactly-5000ms is dropped. Pinned by a test so it cannot drift silently.

`onOverflow` keeps its single meaning — the queue is FULL. It must not fire for
an expiry, same reasoning as `260812-uge` gave for the no-socket drop.

## Task 2 — ConnectionService: keep across a blip, never across a target

`lib/net/connection_service.dart`

- `late final SendPolicy _policy = SendPolicy(nowMillis: _nowMillis);` — `late`
  because a plain field initializer cannot read `_nowMillis`, which the
  constructor's initializer list sets.
- Delete `_policy.channelUp = true` at channel install (`:865`) and
  `..channelUp = false` in `_teardownChannel` (`:1169`); rewrite both comments,
  which currently document the opposite rule.
- **Remove `..clear()` from `_teardownChannel`.** This is what lets the queue
  outlive a blip — but teardown has five call sites and only two of them are
  blips, so the clear has to be re-added where it is actually correct:

  | call site | teardown reason | queue |
  |---|---|---|
  | `_onTransportLost` `:1107` | socket dropped | **KEEP** — this is the blip |
  | `_onDeadConnection` `:1114` | 3 missed pongs | **KEEP** — same shape |
  | `CloseEffect` `:803` | explicit disconnect | **CLEAR** |
  | `_dial` `:812` | fresh dial | **CLEAR iff the target changed** |
  | `dispose` `:779` | provider teardown | irrelevant, object is dead |

- The target-switch clear is not optional. `disconnectRequested()` emits
  `CloseEffect` **alone** (no `AuthStopEffect`, so nothing else clears), and
  `connectRequested(other)` reaches `_dial` → `_teardownChannel`. Without this,
  a frame typed at PC A while it was in backoff flushes onto PC B when the user
  switches devices inside the 5s window — a *worse* misdelivery than the one
  `260812-uge` set out to fix. Track `String? _queuedForKey` (the target the
  queue belongs to) and clear when it does not match the target being dialed;
  null it on close. Frames sent while never connected therefore also drop,
  since `null != target.key`.

## Task 3 — tests

Both groups below assert the behaviour being replaced. Rewrite, do not delete,
so the diff reads as a behaviour change and not as lost coverage.

1. `send_policy_test.dart` — the `SendPolicy — disconnected` group becomes
   `SendPolicy — TTL`. All 12 constructions gain a fake clock. Cover: a frame
   flushes when re-auth lands inside the TTL; the same frame does not when it
   lands past it; the exact-boundary case; expiry does NOT fire `onOverflow`;
   and expiry-before-bound (fill the queue, age it out, prove a fresh frame is
   accepted rather than overflowed).
2. `connection_service_test.dart:479` — the reversed `sendReliable during a
   reconnect is DROPPED` test becomes a **pair** over the same setup (drop →
   backoff → 12 reliable sends → redial → re-auth), one advancing `h.now`
   inside the TTL and asserting they arrive, one advancing past it and
   asserting they do not.
3. New: switching targets mid-backoff drops the queue rather than flushing it
   onto the second PC — the Task 2 hazard, pinned.
4. Keep the handshake-window test unchanged; it still passes and still proves
   the queue is not dead code.
