<objective>
Wire the update path into the server. Three seams open at once because the compiler
forces them to: a new `Executors` field, a new `ServerDeps` field, and a new relay watch
whose sender `run_ext` owns. All three ripple into `server-windows/src/main.rs` and the
`server-core` test harnesses, so they land together.

This plan adds no behaviour to the router or the session — those arms are 12-13's. It
also adds no `ext.reload` command and no reload guard; those are 12-16's. What it does
is make `exec.update` and `deps.update` exist and be correct, and make the server able
to see which version the extension is running.

Purpose: the composition root gains one more worker thread in exactly the shape it
already has three of, and the extension leg gains the one field `update.status` needs.
Output: two bundle fields, one relay watch, one thread spawn, updated harnesses.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| extension (loopback) -> server | `ext.hello`'s `extVersion` is attacker-controllable by any local process that can open the loopback socket |
| router -> `Executors.update` | The wire's only route into the update path |
| update thread -> `ServerDeps.update` | Server-produced state flowing back to the phone |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Elevation of Privilege | `Executors.update` | mitigate | The server resolves every asset URL and hash itself from a compiled-in repo constant and NEVER accepts, derives, or is influenced by a target supplied over the wire (D-14). This wiring adds exactly one route from the router to the executor, and that route is the unchanged one-string `apply` signature. No new field, parameter or channel in this plan can carry a locator |
| T-12-40 | Spoofing | forged `extVersion` on the loopback leg | accept | Already-accepted residual (SPEC Sec 15): a local process able to open a loopback socket owns the machine. The consequence here is bounded - a forged `extVersion` can only make the phone's extension row read the wrong version or, in 12-16, trigger at most one `ext.reload`, which the in-memory guard caps at once per target version per process run |
| T-12-41 | Tampering | malformed `ext.hello` payload | mitigate | Read with the lenient ext-leg convention: absent or non-string yields `None`, never an error and never a panic. The ext leg has no codec harness by design (SPEC Sec 15) |
| T-12-42 | Information Disclosure | progress pushed pre-auth | mitigate | `ServerDeps.update` is consumed only by the authed-gated session arm added in 12-13, exactly like the `bookmarks.changed` arm. This plan adds the field but no push site, so there is no pre-auth exposure to create |
| T-12-43 | Denial of Service | a dropped watch sender silently disabling a branch | mitigate | Harness senders are kept as struct fields per the `Harness.bm_tx` precedent, and `reset_relay_watches` is the single cleanup site all three relay watches share, so a missed reset is structurally impossible rather than merely unlikely |
| T-12-SC | Tampering | cargo installs | accept | No new dependency in this plan |
</threat_model>
