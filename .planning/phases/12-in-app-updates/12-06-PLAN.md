<objective>
Give the Windows server the two halves of "fetch the truth": a release-feed client that
resolves what the latest version is and which file belongs to it, and a downloader that
streams that file to `%TEMP%` and refuses to let unverified bytes survive on disk.

This is the crate where D-14 becomes physical. `RELEASES_API` and the asset-name
prefixes are `const`s in `server-windows`; `server-core`, which owns the codec that
touches the wire, has no path to them. The only thing that ever crosses from the wire
into this module is a version string.

Purpose: the tier that will execute the installer is the only tier allowed to name the
file it executes.
Output: `ureq` added, `src/update/{mod,feed,download}.rs`, unit tests pinned to the
shared feed fixtures.
</objective>

Constants, all `const` in this file (D-14 — they must not be reachable from
`server-core`):
- `RELEASES_API` = `https://api.github.com/repos/nandodeomkar/remote-control-releases/releases/latest`
- `SETUP_ASSET_PREFIX` = `RemoteControl-Setup-v`
- `APK_ASSET_PREFIX` = `RemoteControl-v`
- `EXT_ASSET_PREFIX` = `RemoteControl-Extension-v`

Types: `Release { version: String, assets: Vec<Asset> }` and
`Asset { name: String, url: String, size_bytes: u64, sha256: Option<String> }`.
`sha256` holds the digest with the `sha256:` prefix ALREADY STRIPPED and lowercased;
`None` means the API returned null or omitted it.

Pure functions, unit-testable with no network:
- `parse_release(body: &str) -> Result<Release, UpdateError>` — serde-deserialises the
  releases API shape, strips a leading `v` from `tag_name`, and maps each asset's
  `name` / `browser_download_url` / `size` / `digest`. A malformed body is
  `UpdateError::Network`. Ignore every other field the API returns; the response is
  large and only these five values matter (D-03: the API is the whole manifest).
- `strip_digest(raw: Option<&str>) -> Option<String>` — accepts `sha256:` followed by
  64 hex characters, lowercases, and returns `None` for null, for a non-sha256
  algorithm prefix, and for anything malformed.
- `resolve_asset<'a>(rel: &'a Release, prefix: &str) -> Result<&'a Asset, UpdateError>`
  — finds the single asset whose `name` starts with the prefix. Zero matches or more
  than one match is `UpdateError::Installer` (the release is malformed, not the
  network's fault). If the matched asset's `sha256` is `None`, return
  `UpdateError::Checksum` — an absent digest is a hard refusal, never a skipped
  verification (D-15).

Network function:
- `fetch_latest(agent: &ureq::Agent) -> Result<Release, UpdateError>` — GETs
  `RELEASES_API`, reads the body with an explicit 1 MiB limit as a DoS belt, and hands
  it to `parse_release`. Send NO `Authorization` header (D-01).
- `feed_agent() -> ureq::Agent` — built with `timeout_global` 10 seconds,
  `timeout_connect` 5 seconds and a `user_agent` of `RemoteControl-Updater`. Add a
  comment citing Pitfall 1: every ureq timeout defaults to None, so without these a
  black-holed socket parks the update thread forever and the busy guard never clears.
- `map_ureq(e: ureq::Error) -> UpdateError` — every transport error and every
  `Error::StatusCode` (including the anonymous rate limiter's 403 and a 429) maps to
  `UpdateError::Network`, because D-11 has no rate-limit code and the vocabulary is
  closed. Emit DIFFERENT `tracing` lines for the status-code case and the transport
  case, including the status number, so the first support question is answerable even
  though the user-facing copy is identical (Pitfall 2).

Never cache a resolved `browser_download_url` across a run: it 302s to a time-limited
signed CDN URL. State this in the module doc and resolve immediately before each
download.

Tests in a `#[cfg(test)]` module: `feed_parse` loads
`protocol/fixtures/update/11-releases-latest.json`, parses it, and asserts the version
and all three assets with their exact sizes and 64-hex digests; a negative test loads
`12-releases-latest-null-digest.json` and asserts `resolve_asset` for the setup prefix
returns `UpdateError::Checksum`; plus `strip_digest` cases for null, a wrong
algorithm, wrong length and uppercase hex.

Create `server/server-windows/src/update/download.rs` with a `//!` header stating that
nothing this module writes is ever executed before it has been verified.

`download_agent()` — a second `ureq::Agent` with `timeout_global` 120 seconds and
`timeout_connect` 5 seconds, because a 5 MB asset over a bad link legitimately takes
longer than a feed GET.

`temp_path_for(target: &str) -> PathBuf` — builds
`%TEMP%\RemoteControl-Setup-v{target}.exe`. The `target` reaching this function has
ALREADY been validated as `^\d+\.\d+\.\d+$` by the caller; add a debug assertion and a
doc comment recording why: an unvalidated target interpolated into a path is a
traversal (`..\..\Startup\x`), and interpolated into the helper script it is a `cmd`
injection. The filename template lives here, server-side; nothing from the wire but
the validated version ever reaches it.

`download_to(agent, url, dest) -> Result<(), UpdateError>` — GETs the url and streams
the body with `as_reader()` plus `std::io::copy` into a `File::create(dest)`. Never
buffer: `read_to_vec` caps at 10 MiB by default and would silently break the day the
setup exe grows. `File::create` truncates any stale partial. Call `sync_all()` before
returning so a buffered tail cannot hash wrong. Map an I/O failure to
`UpdateError::Disk` and a transport failure to `UpdateError::Network`. On ANY error
path, delete the partial file before returning (D-23).

`file_sha256_hex(path) -> io::Result<String>` — `io::copy` from the file into a
`Sha256` (which implements `io::Write`), then `hex::encode`.

`verify_or_delete(path, expected_hex) -> Result<(), UpdateError>` — compares
case-insensitively against the already-stripped digest. On mismatch, delete the file
and return `UpdateError::Checksum`. Document that this runs AFTER `sync_all` and
BEFORE anything is spawned, and that unverified bytes never survive on disk (D-15).

Tests in a `#[cfg(test)]` module, all offline: write a temp file with known content,
assert `file_sha256_hex` matches a precomputed digest; assert `verify_or_delete`
returns `Ok` for the right digest and leaves the file present; assert it returns
`Checksum` for a wrong digest AND that the file no longer exists afterwards; assert
`temp_path_for` produces the expected filename for `1.5.0`.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub API / CDN -> PC server | Untrusted bytes enter the machine here and will later be executed |
| phone -> PC server | Supplies only a version string; this module is what makes that sufficient |
| `%TEMP%` -> execution | A file on disk becomes a running process in a later plan |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Elevation of Privilege | `feed.rs` locator constants | mitigate | The server resolves every asset URL and hash itself from a compiled-in repo constant and NEVER accepts, derives, or is influenced by a target supplied over the wire (D-14). `RELEASES_API` and the three asset prefixes are `const`s in `server-windows`; the codec crate has no path to them, proven by asserting the string does not appear anywhere under `server/server-core/` |
| T-12-13 | Tampering | `target` interpolated into `temp_path_for` | mitigate | The caller validates `^\d+\.\d+\.\d+$` before any use; this function debug-asserts it and documents the traversal it prevents. The filename template is server-side and fixed |
| T-12-14 | Tampering | unverified bytes on disk | mitigate | Verification runs after `sync_all` and before any spawn; a mismatch deletes the file and returns `checksum`. A null or absent digest is a hard `checksum` refusal in `resolve_asset`, never a skipped verification (D-15) |
| T-12-15 | Denial of Service | stalled socket parks the update thread | mitigate | `timeout_global` and `timeout_connect` are set explicitly on both agents; ureq's default is no timeout at all, which would leave the phone on `downloading` forever and the `busy` guard permanently set |
| T-12-16 | Denial of Service | oversized feed body | mitigate | The feed read carries an explicit 1 MiB limit; the asset download streams rather than buffering, so neither can exhaust memory |
| T-12-06 | Information Disclosure | error reporting | mitigate | Every failure collapses into the closed D-11 vocabulary before it can reach the wire; HTTP status numbers and URLs go to `tracing` only |
| T-12-17 | Tampering | MITM of feed or asset | accept | TLS via rustls with the bundled webpki-roots to `api.github.com` and to the CDN, with the digest arriving over an independent TLS connection from the same trust root. Identical to what every package manager does; accepted for this threat model |
| T-12-SC | Tampering | cargo install of `ureq` | mitigate | `ureq` 3.3.0 was audited in 12-RESEARCH.md Package Legitimacy Audit: verdict OK, no reasons, not deprecated, no build-script network activity, repo `algesten/ureq`, 169M downloads, first published 2018. Version re-verified with `cargo search ureq` at execution time rather than trusted from the document |
