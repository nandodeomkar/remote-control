# Phase 12 — UI Design Contract

> Visual and interaction contract for In-App Updates (Updates screen · Settings badge · install-permission sheet · PC settings Updates section). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Design system is LOCKED and inherited.** The seven palette tokens in `app/remote_control/lib/theme/tokens.dart` are the only colors on the phone (`theme_tokens_guard_test` forbids additions); `Symbols.*_rounded` is the only icon family (`icons_guard_test` bans classic `Icons.*`). Spacing, typography, motion and component-state idioms carry forward from the approved 09/10/11-UI-SPECs verbatim. **Nothing here is a redesign.** The Settings screen's six shipped groups keep their look; this contract adds one row to one of them and one new screen built entirely out of shipped idioms.
>
> **User-locked decisions (12-CONTEXT.md D-01…D-26) are the spine of this contract.** CONTEXT grants exactly one discretion area to this document — *"Updates-screen visual composition within the existing dark-minimal tokens"* — and one adjacent one (*"whether the PC settings fallback performs its own feed check or links out"*). Both are exercised **prescriptively** below: the executor implements these values, it does not re-derive them.
>
> **This phase has TWO surfaces with TWO different design systems.** The phone (`app/remote_control/lib/`, `tokens.dart`, accent `#4C8DFF`) and the PC settings window (`server/server-windows/src/shell/style.rs`, accent `#38BDF8`). They share a **copy vocabulary** and nothing else. Cross-importing a token, a hex literal, or a font size between them is a defect.

## Spacing Scale

Inherited from 09/10/11-UI-SPEC (multiples of 4 plus the established component-intrinsic values). **Phase 12 introduces no new spacing value.**

| Token | Value | Phase-12 usage |
|-------|-------|----------------|
| xs | 4px | Group-heading left inset; gap between the footer status line and the check button when the button is inline |
| sm | 8px | Group heading → surface gap; footer status line → button gap; gap between the two lines inside the explainer sheet's body block |
| — | 12px | Row glyph → text gap; group-surface corner radius; sheet-row vertical padding (nav row) |
| md | 16px | Screen edge padding (`ListView(padding: EdgeInsets.all(16))`); row horizontal padding; sheet top radius; sheet inner padding |
| lg | 24px | Gap between the component-row group and the check footer; gap between the footer and the sheet's CTA |
| xl | 32px | **not used in this phase** |
| — | 48px | Row `minHeight`; every touch target (`Update`, `Retry`, `Check for updates`, sheet buttons, the Settings nav row) |

**Phase-12 exceptions (all pre-existing, carried not introduced):**
- **2px** title → subtitle gap inside a two-line row — the shipped `_PairedPcRow` geometry (`:250`). Carried verbatim.
- **16×16** spinner box with **strokeWidth 2** — the shipped `_EmptyState` indicator. Carried verbatim.
- **8px** badge-dot diameter (see § Component 4). This is the token `sm` used as a diameter, not a new value.

**Off-grid rule (binding):** the only off-grid value permitted in phase-12 code is the **2px** title/subtitle gap listed above, and only inside a two-line row that is already a `_PairedPcRow` clone. **Phase 12 may introduce no NEW off-grid spacing, gap, padding, radius, or size value.** Every new measurement an executor writes must come from the token column above (4 · 8 · 12 · 16 · 24 · 48). If a layout appears to need a new off-grid value, that is a signal the layout is wrong — round to the nearest token instead of adding a value.

## Typography

The **Settings-family** roles, taken from the shipped `settings_screen.dart` (`:108-127`). The Updates screen is a Settings-family screen, so it uses the Settings row roles — **not** the Browser-family 14/400 list-row role. Three sizes, two weights. **No new sizes, no new weights.**

| Role | Size | Weight | Line Height | Phase-12 usage |
|------|------|--------|-------------|----------------|
| Heading | 16px | 600 | 1.2 | App-bar title `Updates`; explainer-sheet title; the `Update` / `Retry` row-action labels (see note) |
| Group heading | 14px | 600 | 1.3 | `_GroupSurface` heading `Components`, rendered `kMuted` |
| Row title | 16px | 400 | 1.5 | Component-row titles (`This phone` · `Windows PC` · `Browser extension`); the Settings `Updates` nav-row label |
| Body | 14px | 400 | 1.5 | Component-row subtitles; explainer-sheet body; `Check for updates` button label; sheet `Not now` label |
| Label | 12px | 400 | 1.3 | Footer status line (`Last checked …`) |

**Binding notes:**
- Row-action labels (`Update`, `Retry`) are **14px at weight 600**, matching the shipped `kRevokeLabel` `TextButton` (`settings_screen.dart:257-260`), which is 14/600 by `TextButton`'s theme default plus an explicit `fontWeight: FontWeight.w600`. They are *not* the 16/600 Heading role despite sharing its weight — do not resize.
- Component-row **titles** are `maxLines: 1`, ellipsized. Component-row **subtitles** are `maxLines: 2`, ellipsized — a deliberate divergence from the shipped one-line `_rowSubtitle`, because the D-11 error copy and the version-transition string do not fit one phone line. Declared here so it is not read as drift.
- Every live-updating numeral — the download percentage — carries `fontFeatures: [FontFeature.tabularFigures()]` (`pairing_dialog.dart:274` precedent). A percent that reflows the row on every tick is the exact jitter that feature exists to prevent.
- Weights: exactly `w400` and `w600`. Nothing else.
- The 28/600 Display role is **not used in this phase**.

## Color

**Zero palette changes.** Every color is an existing `tokens.dart` const. No new local color const is created.

| Role | Value | Token | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `#0E0F12` | `kBg` | Scaffold, app bar, sheet scrim backdrop, everything behind the group surface |
| Secondary (30%) | `#16181D` | `kSurface` | The component-row group surface, the Settings group surfaces, the explainer sheet |
| Accent (10%) | `#4C8DFF` | `kAccent` | see reserved-for list |
| Destructive | `#FF6B6B` | `kError` | **NOT USED IN THIS PHASE.** See § No Destructive Confirmation |

**Fixed non-accent:** `#2A2D34` `kHairline` (row dividers, sheet hairline), `#E6E8EB` `kText` (row titles, sheet title, the `Check for updates` label and its glyph), `#6B7280` `kMuted` (row leading glyphs, every subtitle, the footer status line, the spinner, the disabled check button, the sheet body, the `Not now` label).

**Accent reserved for (explicit, nothing else):**
- The row-action label `Update` — the one act that starts an install.
- The row-action label `Retry` and the footer button label when it is in its `Retry` state — the one act that recovers a failure.
- The determinate progress arc of the 16×16 `CircularProgressIndicator` while a component is downloading/verifying/installing.
- The 8px **badge dot** on the Settings gear and on the Settings `Updates` row.
- The explainer sheet's single `FilledButton` fill (theme accent, `kBg` label) — the only filled accent surface in the phase.
- Existing, untouched: `ConnectionHeaderChip` connected state; `ReconnectingBanner`'s `Retry now` label.

**Accent budget check (why this list and not filled buttons per row).** D-04 ships ONE unified `X.Y.Z` across all three components, so when a release lands **all three rows are out of date at the same moment**. Three stacked accent-filled pills would be ~3× the accent area of any shipped screen and three competing focal points on a screen whose whole job is "here is the state of three things". The house already owns the correct idiom for a row-scoped action: a bare `TextButton` with a colored 600-weight label (`Revoke`, in `kError`). Phase 12 uses that shape in `kAccent`. The one `FilledButton` in the phase lives inside the explainer sheet, where it is genuinely the single primary CTA of a single-purpose surface.

**Accent is never** a resting row background, a row border, a divider, or a status colour. Offline / gated / unknown is always `kMuted` — **never red** (house rule). The amber `#E8A33D` reconnecting colour is owned by `ReconnectingBanner` and is not re-used here.

## No Destructive Confirmation

**This phase renders no confirm dialog and uses `kError` nowhere.** Recorded as a decision, not an omission, because the checker's Copywriting dimension asks for one.

- **Update app** — Android's own `PackageInstaller` confirmation dialog is the gate (D-19). Adding an in-app confirm before the system confirm would be a double prompt for one action.
- **Update PC** — the user taps `Update` on a row that already reads `1.4.0 → 1.5.0 · 4.9 MB`. That is informed consent. The action is an *upgrade*, not a removal: nothing the user owns is destroyed, and the socket drop is recovered by the existing reconnect FSM (D-17). `bookmark_confirm.dart`'s header states the house rule — escalation is reserved for **irreversible machine state** (the Power screen's slide-to-confirm) and for **data removal** (`confirmDestructive`). An update is neither. Escalating here would train the owner to click through a gate that must stay expensive where it actually matters.
- **Update extension** — has no tap at all (D-18).

**Do not add** a confirm dialog, a slide-to-confirm, an "are you sure", or a `kError` element anywhere in this phase. If a future change makes rollback impossible in a way that costs the user data, that is when this section gets revisited.

## Screen Layout — Updates

Reached from Settings (D-06). One screen, one group, one footer.

```
Scaffold (kBg)
├─ AppBar: "Updates" 16/600 kText
│           actions: [ ConnectionHeaderChip, 16px right padding ]
├─ ReconnectingBannerSlot(visible: chip == reconnecting, onRetry: retryNow)
└─ SafeArea > ListView(padding: EdgeInsets.all(16))
   ├─ _GroupSurface(heading: "Components")
   │    ├─ UpdateRow — This phone            ← app / APK
   │    ├─ 1px kHairline Divider
   │    ├─ UpdateRow — Windows PC            ← server
   │    ├─ 1px kHairline Divider
   │    └─ UpdateRow — Browser extension     ← extension (no action, ever)
   ├─ SizedBox(height: 24)
   └─ CheckFooter
        ├─ Text(status line)  12/400 kMuted
        ├─ SizedBox(height: 8)
        └─ TextButton.icon(Symbols.refresh_rounded, "Check for updates")
```

**Binding rules:**
- **Row order is fixed: `This phone` → `Windows PC` → `Browser extension`.** It matches the design spec's own ordering and it is control-locality order: nearest surface first. The App row is first because it is the only update the user can complete with no PC in the room.
- The screen renders **all three rows in every state**. A row never disappears — a missing/unknown component is a *state of the row*, not an absent row. A screen whose row count changes with connectivity is unreadable at a glance and breaks the "three components" promise of SC3.
- `ReconnectingBannerSlot` is mounted because two of the three rows depend on a live authed socket, and the PC update path deliberately drops that socket (D-17). The banner is the **only** reconnect surface — **do not build a second "waiting for your PC" indicator** (RESEARCH anti-pattern: *"a second reconnect path for the PC update"*).
- No pull-to-refresh. The footer button is the manual check (D-07); a second gesture-triggered check would spend the 60/hour anonymous budget invisibly.
- No `FloatingActionButton`, no bottom bar, no tabs.

### Focal point

**The screen has exactly one focal region: the `Components` group.** The footer is meta.

Within the group, the focal element is **the topmost row carrying an accent `Update` label**. Because D-04 makes all three go stale together, reading order resolves the tie: `This phone` reads first. That is the intended priority — the phone update is self-contained, and updating the PC deliberately severs the connection the other two rows depend on.

There is **no resting accent anywhere on this screen when everything is up to date.** An all-green Updates screen is entirely `kText`/`kMuted` on `kSurface`. That absence is the signal.

## Component 1 — `UpdateRow`

The workhorse. One widget, three instances, one state enum.

### Anatomy

Geometry is the shipped `_PairedPcRow` (`settings_screen.dart:226-266`) with a leading glyph added.

```
ConstrainedBox(minHeight: 48)
└─ Padding(EdgeInsets.symmetric(horizontal: 16, vertical: 8))
   └─ Row(children: [
        Icon(glyph, size: 24, color: kMuted),
        SizedBox(width: 12),
        Expanded(Column(crossAxisAlignment: start, mainAxisSize: min, children: [
          Text(title,    16/400 kText,  maxLines: 1, ellipsis),
          SizedBox(height: 2),
          Text(subtitle, 14/400 kMuted, maxLines: 2, ellipsis),
        ])),
        <trailing slot>,
      ])
```

| Instance | Title | Leading glyph | Installed version from | Latest version from |
|----------|-------|---------------|------------------------|---------------------|
| App | `This phone` | `Symbols.smartphone_rounded` | `package_info_plus` via the existing `appVersionProvider` (D-05) | release feed, APK asset |
| PC | `Windows PC` | `Symbols.computer_rounded` | `update.status.serverVersion` | release feed, setup asset |
| Extension | `Browser extension` | `Symbols.extension_rounded` | `update.status.extVersion` (absent ⇒ unknown) | release feed tag |

**The row title is static text and never carries a version, a device name, or a status word.** Titles must stay byte-identical across every state so the three rows read as a stable index while their subtitles churn. In particular the PC row is **not** titled with the paired device's name: the Updates screen concerns exactly one PC (the connected one), the device name is already the hub's app-bar title, and a title that changes on reconnect would make the row's identity flicker.

### Trailing slot

Exactly **one** of these, always occupying at least 48px of height so the row never resizes between states:

| Slot | Widget | When |
|------|--------|------|
| Action | `TextButton` label 14/600 `kAccent` — `Update` or `Retry` | An action is available on this row |
| Progress | `SizedBox(16,16) > CircularProgressIndicator(strokeWidth: 2, value: pct/100, color: kAccent)` | `downloading` (determinate — `pct` is present) |
| Busy | `SizedBox(16,16) > CircularProgressIndicator(strokeWidth: 2, value: null, color: kAccent)` | `checking` on this row, `verifying`, `installing`, `restarting` |
| Empty | `SizedBox.shrink()` | Everything else, and **always** on the Extension row |

The download percentage lives in the **subtitle**, not the trailing slot, with tabular figures. The trailing arc is the ambient signal; the number is the precise one. Do not put both in the same place, and do not add a `LinearProgressIndicator` — it would change the row height mid-download.

### Row state matrix

This table is the contract. `{i}` = installed version, `{l}` = latest version, `{s}` = size label, `{p}` = percent.

| State | Applies to | Subtitle | Trailing | Enabled |
|-------|-----------|----------|----------|---------|
| `checking` | all | `Checking…` | Busy spinner | — |
| `upToDate` | all | `Up to date · {i}` | Empty | — |
| `available` (app) | App | `{i} → {l} · {s}` | `Update` | yes |
| `available` (pc) | PC | `{i} → {l} · {s}` | `Update` | yes |
| `available` (ext) | Extension | `{i} → {l} · updates with your PC` | Empty | never |
| `downloading` | App, PC | `Downloading… {p}%` | Determinate arc | no |
| `verifying` | App, PC | `Checking the download…` | Busy spinner | no |
| `installing` | App, PC | `Installing…` | Busy spinner | no |
| `restarting` | PC | `Restarting on your PC…` | Busy spinner | no |
| `failed(code)` | App, PC | see § Error copy | `Retry` | yes |
| `couldNotCheck` | all | `Couldn't check` | Empty (retry lives in the footer — see below) | — |
| `serverDisconnected` | PC, Extension | `Connect to your PC to check` | Empty | — |
| `serverTooOld` | PC, Extension | `This PC needs one more update by hand before it can update itself` | Empty | — |
| `pcDidNotReturn` | PC | `PC didn't come back — start it from the Start Menu` | `Retry` | yes |
| `extensionNeverConnected` | Extension | `Not connected — open your browser` | Empty | — |
| `extensionNeedsBrowserRestart` | Extension | `Restart your browser to finish updating` | Empty | — |
| `unknownVersion` | all | `Version unknown` | Empty | — |

**Binding state rules:**

1. **`available` is never shown for a version at or below installed** (D-26). A malformed or unparseable tag resolves to `unknownVersion`, **never** to `available` (CONTEXT `<specifics>`: an unknown must not trigger an update offer).
2. **The Extension row has no enabled trailing action in any state** (D-18 — "no phone action"). Its `Update` column is structurally absent, not conditionally disabled. Do not render a greyed `Update` there; an affordance that can never fire is worse than none.
3. **APK success is never observed** (RESEARCH Pitfall 7 — the app process is killed by its own install). The App row's observable terminals are `installing` → *(process death)* → a fresh launch that reads `upToDate` from a new `package_info_plus` value; plus `failed(...)` and a decline. **Do not persist an `installing` flag** that a fresh launch would read as stuck.
4. **A declined Android install dialog returns the row to `available`** — same subtitle, same `Update` button, no error copy, no toast, no retry loop (D-19).
5. **PC success is confirmed by reconnection, not by a message** (D-17). The PC row goes `restarting` → the socket drops → `ReconnectingBannerSlot` appears → on reconnect the screen re-checks and the row lands on `upToDate`. No bespoke timer.
6. **`serverTooOld` also blanks the Extension row's version** — a 1.7 server cannot report `extVersion` through a family it does not know. Both rows show the same `serverTooOld` subtitle so the cause reads once, not twice with different words.
7. **`busy` (D-11) is never a row state.** It means "your tap arrived while an apply was already running", which the row already shows. Swallow it: log it, change nothing on screen. A second tap on a disabled button cannot produce it, and surfacing it would blame the user for a race.
8. **`downgrade` (D-11) is never a row state either.** It is a server-side guard against a condition rule 1 already prevents the UI from offering. If it ever arrives, render it as `failed(installer)` copy and log the real code — an impossible state must degrade to a generic honest message, never to a message that implies the user did something.

### The D-22 reading (explicit, so the auditor does not flag it)

D-22 says: *"the row reads 'couldn't check' with a retry button."*

A feed-fetch failure is **screen-scoped, not row-scoped** — one HTTP failure puts all three rows into `couldNotCheck` simultaneously (RESEARCH Pitfall 2 warning sign: *"Couldn't check appearing on all three rows simultaneously"*). Rendering three identical `Retry` buttons for one failure is three affordances for one act.

**Resolution:** every row reads `Couldn't check` (D-22's literal requirement), and the **single** retry button is the footer's, whose label flips to `Retry` in `kAccent`. Row-level `Retry` is reserved for **row-scoped** failures — an apply that failed on the App or PC row — where the retry genuinely targets one component.

## Component 2 — `CheckFooter`

Below the group, separated by 24px. Left-aligned, no card, no border.

```
Column(crossAxisAlignment: start, children: [
  Text(statusLine, 12/400 kMuted),
  SizedBox(height: 8),
  TextButton.icon(
    style: TextButton.styleFrom(minimumSize: Size(48, 48), foregroundColor: <fg>),
    icon: Icon(Symbols.refresh_rounded, size: 20),
    label: Text(<label>, style: TextStyle(fontSize: 14, fontWeight: FontWeight.w400)),
    onPressed: <null while checking>,
  ),
])
```

| Feed state | Status line | Button label | Button foreground |
|------------|-------------|--------------|-------------------|
| never checked | `Not checked yet.` | `Check for updates` | `kText` |
| ok | `Last checked {ago}.` | `Check for updates` | `kText` |
| checking | `Checking…` | `Check for updates` | `kMuted`, `onPressed: null` |
| failed (D-22) | `Couldn't check for updates.` | `Retry` | `kAccent` |

**`{ago}` formatter (deterministic, unit-testable, no `intl` dependency):**

| Elapsed | Renders |
|---------|---------|
| < 60 s | `just now` |
| < 60 min | `{n} minute ago` / `{n} minutes ago` |
| < 24 h | `{n} hour ago` / `{n} hours ago` |
| otherwise | `{n} day ago` / `{n} days ago` |

Singular at exactly 1. No `intl`, no `timeago` package — this is a four-branch pure function and adding a package for it would be the third thing this project rejected a wrapper for.

**Cadence (D-07):** the quiet launch check fires at most once per 24h from the cache, and **never** changes the footer to `Checking…` or produces any visible motion — a background check that animates the screen is an interruption. Only a tap on this button renders `checking`. A failed background check is silent: it leaves the last-good cached result and its `Last checked` line in place.

## Component 3 — Install-permission explainer sheet (D-19)

Shown when the App row's `Update` is tapped and the `canInstall` channel reports the "install unknown apps" grant is missing. **Not** shown pre-emptively, and never on a row that is not `available`.

`showModalBottomSheet(backgroundColor: kSurface, isScrollControlled: true, shape: top-radius 16)` — the shipped `_ConnectByIpSheet` invocation, verbatim.

```
Padding(EdgeInsets.all(16) + viewInsets.bottom)
└─ Column(mainAxisSize: min, crossAxisAlignment: start, children: [
     Text(title, 16/600 kText),
     SizedBox(height: 8),
     Text(body,  14/400 kMuted),
     SizedBox(height: 24),
     SizedBox(height: 48, width: double.infinity, child: FilledButton(...)),   ← the phase's ONLY FilledButton
     SizedBox(height: 8),
     TextButton( "Not now", foregroundColor: kMuted, minimumSize: Size(48,48) ),
   ])
```

- Dismissing by scrim, by back gesture, or by `Not now` all resolve identically: the App row stays on `available`, nothing is downloaded, nothing is logged as an error.
- `Open settings` fires the `ACTION_MANAGE_UNKNOWN_APP_SOURCES` intent through the installer MethodChannel and closes the sheet. **The app does not poll for the grant** and does not auto-resume the download on return — the user comes back and taps `Update` again. Auto-resuming after an app-switch is exactly the kind of surprise 70 MB of data should not have.
- On API < 26 the grant does not exist as a per-app concept (RESEARCH Pitfall 5); `canInstall` returns `true` there and **this sheet never opens**. It is not an error path to render.

## Component 4 — Settings entry and the badge dot

### The Settings entry

A new tappable nav row, added as the **first child of the existing `_AboutGroup`**, directly above the shipped `Version` row.

Rationale: the About group is already the version-identity home ("which version are you on?" is literally why it exists — `settings_screen.dart:22-25`). "Am I current?" is the same question one step further. This adds **no seventh group** and moves no shipped row.

```
_GroupSurface(heading: "About")            ← existing heading, unchanged
├─ UpdatesNavRow                           ← NEW
├─ 1px kHairline Divider                   ← supplied by _GroupSurface
└─ Version row                             ← existing, byte-unchanged
```

`UpdatesNavRow` is the shipped `_AddSwitchPcRow` shape (`Material(kSurface)` + `InkWell`, `minHeight 48`, padding `h16 v12`) with a trailing slot:

```
Row(children: [
  Icon(Symbols.system_update_rounded, size: 20, color: kText),
  SizedBox(width: 12),
  Expanded(Text("Updates", 16/400 kText)),
  if (badge) <8px kAccent dot>, SizedBox(width: 12),
  Icon(Symbols.chevron_right_rounded, size: 20, color: kMuted),
])
```

Tap: `hapticTick()` + `Navigator.push(MaterialPageRoute(builder: (_) => const UpdatesScreen()))`. Default route transition — no custom animation.

### The badge dot

`Container(width: 8, height: 8, decoration: BoxDecoration(color: kAccent, shape: BoxShape.circle))`.

Two placements, one source of truth:

| Placement | Geometry |
|-----------|----------|
| Settings `Updates` row | Inline in the trailing run, 12px before the chevron. Layout **does** shift by 20px when it appears — acceptable inside a row the user is not mid-gesture on. |
| Hub app-bar settings gear | `Stack` over the shipped `IconButton`, dot pinned to the glyph's top-right with `Positioned(right: 10, top: 10)` inside the 48px button box. **The `IconButton` geometry is untouched** — the dot is an overlay, never a layout participant, so the app bar can never reflow. |

**Badge truth rule (binding, and the whole point of the badge):**

> The dot lights when, and only when, **at least one component whose installed version is KNOWN is strictly behind the cached latest version**.

- Never lights on `unknownVersion`, `couldNotCheck`, `serverDisconnected`, `serverTooOld`, or a stale/absent cache.
- Reads from `update_cache` (`shared_preferences`), so it is correct **offline and before the Updates screen has ever been opened** — the app's own version is always knowable without a socket.
- Clears the frame the last out-of-date known component reaches `upToDate`. No dismiss gesture, no "seen" flag: a badge the user can silence while the condition holds is a lie.

**Accessibility:** the dot is a purely visual signal and carries no text. The gear's `IconButton` `tooltip` flips from `Settings` to `Settings — update available` when the badge shows (`IconButton` surfaces `tooltip` as its semantics label, so this costs no extra node and cannot desync). On the Settings row, the row's own `Text("Updates")` supplies the label; wrap the dot in `Semantics(label: 'Update available')` so the state is announced rather than only drawn.

## Interaction / Gesture Map

| Surface | tap | long-press | swipe / drag |
|---------|-----|------------|--------------|
| Settings `Updates` row | push `UpdatesScreen` + `hapticTick()` | — | — |
| Hub settings gear (existing) | push `SettingsScreen` (unchanged) | — | — |
| `UpdateRow` **body** | **nothing — the row is not tappable** | — | — |
| `Update` button (App) | `hapticTick()` → grant check → sheet **or** start download | — | — |
| `Update` button (PC) | `hapticTick()` → send `update.apply {target}` | — | — |
| `Retry` button (row) | `hapticTick()` → re-run that row's last failed action | — | — |
| `Check for updates` / `Retry` (footer) | `hapticTick()` → fetch feed + send `update.check` | — | — |
| Extension row | **no affordance at all** | — | — |
| Sheet `Open settings` | `hapticTick()` → fire settings intent, close sheet | — | — |
| Sheet `Not now` / scrim / back | close, no state change | — | — |
| Updates screen | — | — | **no pull-to-refresh** |

**Row-body inertness is deliberate and load-bearing.** 11-UI-SPEC's Failure-B rule — *"a row whose tap action REPLACES or REMOVES the row must fire on `onTap`, never on `onTapDown`"* — is sidestepped entirely here by giving the row no tap at all. A `UpdateRow` has exactly one recognizer, the `TextButton`'s, so there is no gesture arena, no tap-down deadline, and no way for a mis-tap on the row body to start a 70 MB download. **Do not wrap `UpdateRow` in an `InkWell`, and do not add a press flash** — the flash idiom signals "this fires something", and here it would not.

`hapticTick()` fires on the **send instant** for every action above — the tap for `Update`/`Retry`/`Check`, not on a later completion. Progress ticks, stage changes, and completions produce **no haptic** (a 70 MB download would otherwise buzz the phone continuously).

## Component State Contract

"Gated" = `ChipStatus != connected`. **Layout never shifts between states** — the trailing slot always reserves ≥48px of height and the subtitle is a fixed 2-line box.

**`UpdateRow`:**

| State | Fill | Divider | Glyph | Title | Subtitle | Trailing |
|-------|------|---------|-------|-------|----------|----------|
| Any | `kSurface` | `kHairline` | `kMuted` 24px | `kText` 16/400 | `kMuted` 14/400 | per § Trailing slot |

The row's *chrome* is state-independent by design: only the subtitle text and the trailing slot change. A row that also changed fill or border on failure would put three visual channels on one fact.

**Gated (PC + Extension rows, no live authed socket):** subtitle → `Connect to your PC to check`, trailing → empty. **Muted, never red, never hidden.**

**Gated (App row):** the App row is **never gated by connection state** — its version comes from the package and its feed comes from the internet. It works with no PC in the room. That asymmetry is correct and must not be "harmonised" by greying the App row when the socket is down.

**Footer button:** enabled (`kText`) / checking (`kMuted`, `onPressed: null`) / retry (`kAccent`). No filled variant.

**Badge dot:** present / absent. No intermediate, no animation on appear.

## Accessibility Labels

Every control in this phase carries visible text **except** the badge dot, and every control meets 48px. Labels ship as named consts like every other string.

| Control | Needs `Semantics`? | Label / const |
|---------|-------------------|---------------|
| `UpdateRow` (title + subtitle) | No — `Text` children supply it. A row reads as `"{title}. {subtitle}"`, which is exactly the sentence intended. | — |
| `Update` / `Retry` / `Check for updates` | No — `TextButton` labels are their own semantics. | — |
| Row leading glyphs | No — decorative beside a text title. Do **not** add labels; they would double every row announcement. | — |

| Badge dot (hub gear) | **Yes**, via the button's tooltip | `kSettingsWithUpdateTooltip = 'Settings — update available'`, swapped for `kSettingsTitle` |

### Error copy — the D-11 code → sentence map

`error` is a **fixed seven-value vocabulary** and never reaches the screen as a code, a path, a URL, or an HTTP status. Every failure the user can see is one of these sentences. Each names the problem **and** what is now true, so the user knows whether anything is broken.

| D-11 code | Subtitle copy | Trailing |
|-----------|---------------|----------|
| `network` | `Download failed — check your connection.` | `Retry` |
| `checksum` | `The download didn't match its signature. Nothing was installed.` | `Retry` |
| `disk` | `Not enough space for the download.` | `Retry` |
| `installer` | `The installer didn't finish. Your PC is still on {installed}.` | `Retry` |
| `stale` | `That version is no longer the latest. Check again.` | `Retry` |
| `downgrade` | *(impossible via the UI — render as `installer`, log the real code)* | `Retry` |
| `busy` | *(never surfaced — swallow and log)* | — |

**Copy rules that a plan-check can enforce:**
- **No error code, HTTP status, exception class, file path, URL, or hash ever appears in user-facing copy.** `checksum` becomes "didn't match its signature", not "sha256 mismatch"; a 403 rate-limit becomes "Couldn't check", not "403". The real detail goes to the log (RESEARCH Pitfall 2: the log line must distinguish 403 from a socket failure even though the user copy cannot).
- **No jargon:** no "APK", no "sha256", no "GitHub", no "endpoint", no "protocol", no "manifest", no "PackageInstaller", no "%APPDATA%".
- **No blame:** no "you must", no "invalid", no "failed to" pointed at the user. The `busy` and `downgrade` swallow rules exist for exactly this reason.
- **`{size}` formatter:** bytes ÷ 1 048 576, one decimal below 10, rounded integer at 10 and above, suffix ` MB` — so the real assets render `66 MB` (APK, 69 630 935 B) and `4.9 MB` (setup, 5 177 240 B). Deterministic and unit-testable; no `filesize` package.
- **`{installed}` / `{latest}` are rendered verbatim from the package and the tag**, with a leading `v` stripped if the tag carries one. Never reformatted, never zero-padded.
- **Ellipsis is the single character `…` (U+2026)**, never three periods — the shipped `Checking…` convention.
- The transition arrow is `→` (U+2192).

## PC Settings Window — `UPDATES` section (D-06 fallback)

A **separate design system**. Rendered in egui with `server-windows/src/shell/style.rs` tokens. **Never import, copy, or approximate a `tokens.dart` value here** — the PC accent is `#38BDF8`, not `#4C8DFF`, and the two must not converge by accident.

**Discretion resolved: the PC settings section performs its OWN feed check.** It does not link out to a browser. Rationale: D-06's whole purpose is that *"a broken or unpaired phone does not leave the PC with no update path"* — a section that opens a browser to a releases page leaves the user hand-downloading a file, which is the manual procedure this phase exists to delete. The server already owns `feed.rs`, `download.rs` and `apply.rs` for the phone-driven path (D-14 requires it to resolve its own asset regardless), so the local check reuses that seam and adds no new resolution logic.

**Composition (matching the shipped `GENERAL` / `PAIRED DEVICES` sections):**

```
style::section_label(ui, "UPDATES");      // tracked caps, no leading glyph — matches siblings
ui.add_space(12.0);
field_label(ui, "Version", None);          // sg_sb, MUTED
ui.add_space(7.0);
<version line: mono(14.0) TEXT>            // mono, because it is a version literal
ui.add_space(16.0);
<status line: sg(12.0) MUTED | ACCENT | RED>
ui.add_space(12.0);
<"Check for updates" button>               // then "Update now" once one is available
```

| Rule | Value |
|------|-------|
| Section label | `UPDATES` — caps, via `style::section_label`, **no leading icon** (neither sibling section has one) |
| Version literal | `style::mono(14.0)` in `style::TEXT` — versions are literals, and the window already uses `mono` for the port field |
| Idle / up-to-date status | `style::sg(12.0)` in `style::MUTED` |
| Available / in-progress status | `style::sg(12.0)` in `style::ACCENT` — the same treatment as the shipped `Restart to apply` hint |
| Failure status | `style::sg(12.0)` in `style::RED` — the same treatment as the shipped `Not a valid port (1–65535)` line |
| Progress | A text stage line only (`Downloading… 43%`). **No progress bar widget** — the window has no bar idiom and this section does not introduce one |
| New glyph constants | **none.** `style::icon` gains no members in this phase |

**Copy: identical sentences to the phone**, minus the phone-only rows. `Up to date · 1.4.0`, `1.4.0 → 1.5.0 · 4.9 MB`, `Downloading… {pct}%`, `Checking the download…`, `Installing…`, and the same seven-code error map. The two surfaces describing the same failure with different words is the single most confusing outcome available to this phase — the copy table above is the shared source and both implementations quote it.

**The PC section renders no phone row and no extension row.** It is a fallback for *this machine*, not a second control centre.
