<objective>
Build `tools/release.ps1` — the single command that makes a release exist. It bumps
the three version-bearing files to one `X.Y.Z` (D-04), builds the three artifacts
into `dist/`, prints their sha256 values, tags both repos, and publishes them to the
public mirror repo (D-01, D-20).

This plan is Wave 1 because of D-21: nothing client-side in this phase is testable
end to end until a real published release exists to check against. The script is
written here in full; the *first real publish* (which needs a repo that does not yet
exist) is gated in plan 12-03.

Purpose: version identity becomes a build-time invariant enforced once, instead of
three runtime constants that drift — which is exactly the bug that pinned
`pubspec.yaml` at `1.0.0+1` across four shipped releases (D-05).
Output: `tools/release.ps1`, `tools/verify-release-dryrun.ps1`.
</objective>

Implement preflight in this order, each failing with a `throw` whose message says what to do:

1. **Version format** — refuse anything not matching `^\d+\.\d+\.\d+$`.
2. **Dirty tree (D-20)** — `git status --porcelain`; non-empty output refuses. Note in a comment that `dist/` is gitignored (`.gitignore` line 9 `/dist/`) so the script's own output can never trip this.
3. **`gh` resolution (Pitfall 10)** — three candidates in order: `Get-Command gh -ErrorAction SilentlyContinue`, then the literal `C:\Program Files\GitHub CLI\gh.exe`, then a multi-line `throw` naming both. Never hardcode the absolute path alone. Store the resolved path in `$Gh`.
4. **Release signing** — refuse if `app\remote_control\android\key.properties` is absent, with a message saying a debug-signed APK cannot upgrade a release-signed install. Do not silently produce a debug build.
5. **Mirror reachability + latest-published refusal (D-20, D-26)** — `Invoke-RestMethod $ReleasesApi`. A 404 means the repo does not exist: throw a message naming the exact repo and the exact `gh repo create nandodeomkar/remote-control-releases --public` command. Otherwise read `tag_name`, strip a leading `v`, and refuse when `-Version` is not strictly greater than it, comparing as an integer triple (major, minor, patch) — never as strings, and never with `git describe` (D-20/RESEARCH: `v1.3.x` tags are missing from history, so tag continuity cannot be assumed). Send NO auth header on this call (D-01).

Under `-DryRun`, steps 1–5 all still run; only the reachability call may be skipped when the repo 404s, in which case print a warning and continue so the bump preview is still testable offline.

Add a `Set-VersionField` helper and three call sites. Rewrite by **anchored single-line regex replacement only** — never parse-and-reserialize (Pitfall 9: both `pubspec.yaml` and `Cargo.toml` carry load-bearing comments a YAML/TOML round trip would delete).

Anchors, exactly:
- `server/server-windows/Cargo.toml` — `^\s*version\s*=\s*"([^"]+)"`, **first match only**. New line: `version = "X.Y.Z"`.
- `app/remote_control/pubspec.yaml` — `^version:\s*(\d+\.\d+\.\d+)\+(\d+)$`. Rewrite **both halves** (D-20): the semver becomes `-Version` and the build number becomes `oldBuild + 1`. Refuse if the resulting build number is not strictly greater than the old one — Android refuses an install whose `versionCode` did not increase.
- `extension/manifest.json` — `"version"\s*:\s*"([^"]+)"`. New value `X.Y.Z`. This is the D-04 jump from `1.2.1`.

Each rewrite carries a **post-condition assertion**: read the file back and verify that exactly one line differs from the pre-image, and that the new line contains `-Version`. Throw naming the file if either check fails.

Under `-DryRun`, `Set-VersionField` performs the match and the post-condition arithmetic but **writes nothing**. It prints one line per file in the fixed, machine-parseable form `BUMP <relative-path> <old> -> <new>` so the harness below can assert on it. Print exactly three such lines and nothing else that starts with `BUMP `.

Create `tools/verify-release-dryrun.ps1` — the SC1 harness. It: records `git status --porcelain` before; invokes `tools/release.ps1 -Version 9.9.9 -DryRun` capturing stdout; asserts (a) exit code 0, (b) exactly three `BUMP ` lines, (c) the three paths are `server/server-windows/Cargo.toml`, `app/remote_control/pubspec.yaml`, `extension/manifest.json` in any order, (d) every `-> ` target contains `9.9.9`, (e) `git status --porcelain` is byte-identical to the before value, proving the dry run is genuinely side-effect-free. It writes `OK` and exits 0 on success, prints the failing assertion and exits 1 otherwise.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build machine → public mirror repo | Artifacts leave the owner's control and become anonymously fetchable by every installed client |
| repo working tree → published artifact | Anything committed can end up inside a shipped binary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Elevation of Privilege | the update-apply path this release feeds | mitigate | Not exercised here, but recorded because this plan defines the asset names the server later resolves: the server resolves every asset URL and hash itself from a compiled-in repo constant and NEVER accepts, derives, or is influenced by a target supplied over the wire (D-14). This script's only job is to make the names it resolves predictable |
| T-12-02 | Information Disclosure | `tools/release.ps1` | mitigate | No auth token, no `Authorization` header, no `--token` argument in the script, and no auth header on the anonymous `releases/latest` probe (D-01). Publishing authenticates through the operator's own `gh` login, which never enters an artifact |
| T-12-03 | Tampering | `app/remote_control/android/key.properties` | mitigate | Preflight refuses to build when the release keystore is absent rather than silently emitting a debug-signed APK, which would fail every future upgrade with `STATUS_FAILURE_CONFLICT` |
| T-12-04 | Tampering | version fields | mitigate | Anchored single-line regex rewrites with a one-line-changed post-condition; a rewrite that touches more than its anchor line aborts the release |
| T-12-05 | Spoofing | "what is latest" | mitigate | Latest is read from the mirror's `releases/latest` API over TLS, never from `git describe` (tag history is known-incomplete: `v1.3.x` was never tagged) |
| T-12-SC | Tampering | npm/pip/cargo installs | accept | This plan adds no package-manager dependency. The phase's two new dependencies (`ureq`, `crypto`) are audited in 12-RESEARCH.md § Package Legitimacy Audit with verdict OK and are introduced in plans 12-06 and 12-10 |
</threat_model>
