<objective>
Add the `update.*` codecs to `server-core` and pin them to the shared fixtures, define
the `UpdateExecutor` trait and its plain-data state types, and land the SC6 structural
guard that makes a wire-supplied locator impossible to express.

This plan deliberately does NOT add a field to `Executors` or `ServerDeps` — that
change ripples into `server-windows/src/main.rs` and every test harness, and it is
plan 12-12's job. Here the trait and the types simply come into existence so that
`server-windows`'s update thread (12-11) has something to implement.

Purpose: D-14 becomes a property of the type system rather than a rule people
remember. `UpdateApplyPayload` has exactly one field, the trait method takes exactly
one `&str`, and a guard test fails the build if either grows a locator.
Output: four payload types, four `Msg` variants, one trait, three state types, one
recording mock, one registered fixture family, one guard test.
</objective>

exactly: `#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]`, camelCase via

`#[serde(default, skip_serializing_if = "Option::is_none")]` on every optional field.

`UpdateCheckPayload` - no fields. Copy `ClipGetPayload`'s empty-struct shape so the
canonical form still emits `p` as `{}`.

`UpdateApplyPayload` - **exactly one field**, `target: String`. Add a doc comment
citing D-14: this payload carries a version string and nothing else; the server
resolves the asset URL and its sha256 itself from a compiled-in repo constant and
never accepts, derives, or is influenced by a locator supplied over the wire. Record
that adding any field naming a URL, asset, filename, hash or path to this struct is
remote code execution on the PC, and that `tests/update_guard.rs` fails the build if
one appears.

`version: Option<String>`, `error: Option<String>` (all optional). `stage` and `error`

are validated by the producer and the router, not by the codec.

honouring the module header rule:
- `fn info(&self) -> UpdateInfo` — the data behind an `update.status` reply. Document

Do NOT add a field to `Executors` or `ServerDeps` in this plan — that ripples into

exact strings observed. Follow the interior-mutability style the existing mocks use.
Its whole purpose is the SC6 behavioural assertion in 12-13: a forged `update.apply`
must reach the executor as a bare string and produce no network call.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| phone -> PC server (WebSocket) | Untrusted JSON decodes into these payload types |
| codec crate -> executor crate | The trait signature is the narrowest point the wire can reach |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Elevation of Privilege | `UpdateApplyPayload` and `UpdateExecutor::apply` | mitigate | The server resolves every asset URL and hash itself from a compiled-in repo constant and NEVER accepts, derives, or is influenced by a target supplied over the wire (D-14). Enforced structurally here: the payload has exactly one `target: String` field, the trait method takes exactly one `&str`, and `tests/update_guard.rs` fails the build if a locator-named field or parameter appears in either |
| T-12-10 | Tampering | `target` string content | mitigate | The codec deliberately does NOT validate `target` - per the file-level doc rule, enum-valued and constrained wire fields decode as plain `String` and are validated downstream. The strict `^\d+\.\d+\.\d+$` gate before any use is plan 12-11's first refusal, and 12-13 asserts the behaviour end to end |
| T-12-06 | Information Disclosure | `UpdateProgressPayload.error` | mitigate | Typed as a plain `String` here but constrained to the closed D-11 vocabulary by its only producer (12-11); no path, URL or exception text is ever placed in it |
| T-12-11 | Denial of Service | oversized decoded payloads | accept | Inherited: SPEC Sec 13 per-listener message caps already bound every JSON frame; `update.*` adds no new listener and no larger frame |
| T-12-SC | Tampering | npm/pip/cargo installs | accept | No new dependency in this plan; `sha2`, `serde` and `serde_json` are already in the tree |
</threat_model>
