Add four arms to the router's family routing.

`Msg::UpdateCheck(_)` — the read-with-reply shape. Call `exec.update.info()` once and
map the resulting `UpdateInfo` into a single `Msg::UpdateStatus(UpdateStatusPayload)`:
`server_version` straight through, `ext_connected` straight through, `ext_version` as
the optional, and `last_update` mapped from `LastUpdate` into `LastUpdatePayload`.
Return that one message in the reply vector. Note in a comment that `info()` TAKES the

`Msg::UpdateApply(p)` — the fire-and-forget command shape. Call
`exec.update.apply(&p.target)` and return an empty vector. Add a comment stating D-14:

S-to-C-only ignore chain, not to the `Unknown` arm. A client that sends one is ignored

`matches!` list. Then AMEND the doc comment at the top of that function rather than
silently contradicting it. The existing comment explains why `bm.list`, `apps.list` and
`clip.get` are exempt from executor binding as reads; `update.check` is a read that is
NOT exempt (D-13). Record the reason: it reports state about a machine that is about to
be replaced, so answering it while paused would advertise an action the session has just
been told it may not take.

Extend the two existing test conventions rather than writing new ad-hoc ones: add both
new families to `paused_drops_every_executor_bound_family_silently`, and add an
`update_commands_route_when_unpaused` test in the shape of

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| phone -> router | The dispatch arms are where an authenticated but untrusted client reaches the update path |
| session push -> phone | Server state leaves the machine here |
| pause gate | A session that has been told it may not act must not be able to start an install |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Elevation of Privilege | `Msg::UpdateApply` router arm | mitigate | The server resolves every asset URL and hash itself from a compiled-in repo constant and NEVER accepts, derives, or is influenced by a target supplied over the wire (D-14). The arm passes `&p.target` and nothing else, and `forged_apply_is_refused` asserts the exact string the executor observed, proving no locator can travel through any field because no such field exists |
| T-12-44 | Elevation of Privilege | pre-auth access | mitigate | Inherited unchanged: GATE 1 drops everything from a non-Authed session before family routing is reached. `update.*` gains auth gating for free and adds no new pre-auth surface |
| T-12-45 | Elevation of Privilege | acting while paused | mitigate | Both `update.check` and `update.apply` are added to `is_executor_bound`, so a paused session cannot start an install. The exemption doc comment is amended to record that `update.check` is a read that deliberately is NOT exempt (D-13), so a future reader cannot "fix" it back |
| T-12-42 | Information Disclosure | progress pushed pre-auth | mitigate | The push arm carries the same `ctx.auth_state == AuthState::Authed` gate the `bm.changed` arm carries, and a test asserts a pre-auth connection receives nothing even after the watch advances |
| T-12-46 | Information Disclosure | the idle sentinel leaking | mitigate | The empty-stage default is skipped explicitly; the D-10 vocabulary has no idle value, so publishing it would put an out-of-vocabulary stage on the wire |
| T-12-08 | Spoofing | forward compatibility | accept | An unrecognised `t` answers `unknownType` and the session survives, by design. Proven by `unknown_update_type_keeps_session_alive` rather than assumed |
| T-12-47 | Denial of Service | progress flood | mitigate | `try_send` drops on a full queue and the watch coalesces, so a fast producer cannot back up a slow session; the producer additionally throttles to ~1% or ~250 ms |
| T-12-SC | Tampering | cargo installs | accept | No new dependency in this plan |
</threat_model>
