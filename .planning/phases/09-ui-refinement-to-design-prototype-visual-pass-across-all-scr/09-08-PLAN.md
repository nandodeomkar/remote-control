<objective>
The phase gate: prove on the owner's device that every shipped screen now matches
the approved 09-UI-SPEC prototype — the dot-grid trackpad texture being the
headline — with zero palette drift, no fake cursor, and no tap ripple.

Purpose: this is a visual/interaction refinement phase; widget tests pin the
values, but the honest final proof is human eyes on a real device (the documented
Dimension-8 validation). This gate consolidates that check into one walkthrough so
the on-device session is contiguous.

Output: a fresh release APK installed on the device, a completed per-screen
walkthrough, and a `09-08-SUMMARY.md` recording PASS/FAIL per screen.
</objective>

<execution_context>
Flutter-only (client) plan. Run `flutter` commands from `app/remote_control/`.
Requires the Windows server running and the phone paired on the same LAN so the
connected/authed states can be visually verified.
</execution_context>

<task type="checkpoint:human-verify" gate="blocking-human">
  <name>Task 2: On-device visual walkthrough against the per-screen delta table</name>
  <what-built>
    A fresh release APK carrying: the dot-grid trackpad texture on both the full
    Trackpad surface (24px) and the floating window (22px), the trackpad hint in
    #4a505c, the 56px floating-window mouse bar, the added Keyboard hint copy, and
    confirmed parity across every other screen — all with zero palette change.
  </what-built>
  <how-to-verify>
    With the server running and the phone paired/connected on the same WiFi, open
    the app and check each screen against the 09-UI-SPEC "Per-Screen Refinement
    Deltas" table. Confirm each item:
    1. TRACKPAD (full): the surface shows a subtle dot grid (evenly spaced faint
       dots, ~24px apart) over the dark background; the "Drag to move the cursor" /
       "Not connected" hint is centered and dim (#4a505c); the accent-bordered
       drag-lock pill still appears on long-press; the bottom L/M/R bar is 64px
       (L:M:R ≈ 2:1:2). There is NO glowing blue cursor dot and NO ripple on tap.
       Cursor still moves normally (dots are decorative).
    2. FLOATING WINDOW (tap the bubble on any tool screen): the window surface
       shows the same dot grid but slightly tighter (~22px); the header (drag
       handle + open-full + close + drag-lock pill) is intact; its mouse-button bar
       is a touch shorter (56px). NO fake cursor dot, NO ripple. Cursor moves.
    3. STATUS CHIP + BANNER: chip shows dot + word + "· {n} ms" (latency only when
       connected), color eases ~200ms on state change; drop the WiFi → the amber
       "Reconnecting…" banner slides in with "Retry now".
    4. HUB: uniform 2×4 tile grid, even 16px gaps, muted 32px icons; disconnect →
       tiles grey and stop responding (gear still works).
    5. KEYBOARD: the hint "The system keyboard handles typing. These are the extra
       keys." shows above the panel; Nav/Fn/Num tabs (active = accent underline);
       modifier chips arm (accent outline) and lock (accent fill + lock glyph).
    6. MEDIA: centered Prev(small)/Play(large)/Next(small) circles; mute + slider +
       "{n}%" (or "--" offline) readout.
    7. APPS: favorite squares with the accent pin glyph; open-window rows with a
       close button; empty state reads "No open windows".
    8. CLIPBOARD: two action buttons (Send to PC / Fetch from PC); auto-sync toggle
       + the persistent info caption; Recent history rows.
    9. POWER: safe (blue) vs destructive (red) slide tracks; slide a destructive one
       → the red "{Restart|Shut down} PC?" countdown dialog with the red confirm.
    10. PRESENTER: Prev(narrow)/Next(wide) split by a thin divider; 64px footer with
        Start/End/Blank + the large mm:ss timer (accent while running).
    11. BROWSER: Back/Forward, New tab/Close tab, Refresh (full-width), Zoom out/in;
        buttons flash accent on press.
    12. SETTINGS: grouped cards; Paired PCs + Revoke (red, confirm dialog); scroll
        segments; haptics toggle; the static "Blue" accent chip.
    GLOBAL: nothing on any screen changed color/theme (palette identical to before);
    no visual regressions.
  </how-to-verify>
  <resume-signal>Reply "approved" if every screen matches; otherwise list the screen(s) + exact mismatch so a gap-closure plan can be scoped.</resume-signal>
</task>
