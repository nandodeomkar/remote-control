# Phase 10 — UI Design Contract

> Visual and interaction contract for the Keyboard rethink (full-screen swipeable pads) and the new Shortcuts hub tile. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Design system is LOCKED and inherited.** The seven D-12 palette tokens in `app/remote_control/lib/theme/tokens.dart` are the only colors (palette guard test forbids additions). Spacing, typography, motion, and component-state idioms carry forward from the approved 09-UI-SPEC verbatim; this contract only declares the deltas the two new surfaces need. Nothing here re-derives the design system.
>
> **User-locked decisions (10-CONTEXT.md) are the spine of this contract** — pad set (Type | Arrows | Numpad | Fn), persistent modifier chips, IME-on-Type-only, effect-labeled shortcut buttons with combo subtext, the shortcut catalog, and the no-protocol-change keymap-extension approach. Everything else below exercises the granted discretion prescriptively.

## Spacing Scale

Inherited from 09-UI-SPEC (all multiples of 4 plus the established component-intrinsic values):

| Token | Value | Phase-10 usage |
|-------|-------|----------------|
| xs | 4px | Icon→label gap in tabs, effect-label→combo-subtext gap |
| sm | 8px | Gaps between key caps, chips, shortcut buttons |
| — | 12px | Shortcut-button inner padding, icon→text gap inside shortcut buttons |
| md | 16px | Screen edge padding, chip-row horizontal padding, pad content padding |
| lg | 24px | Gap between shortcut sections; gap between nav row and inverted-T on the Arrows pad |
| xl | 32px | Scroll-content top padding on the Shortcuts screen |
| — | 48px | Minimum touch-target height everywhere (caps, chips, tabs) |
| — | 56px | Bottom tab bar height; Arrows-pad Home/End/PgUp/PgDn cap height |
| — | 64px | Minimum large-cap height on Arrows/Numpad/Fn pads; shortcut button height |

**Phase-10 exceptions:**
- **Type-pad slim extras row:** 7 caps (Esc, Tab, ←, ↑, ↓, →, Del) share one row as equal `Expanded` children — on narrow screens each cap may be ~40–44dp wide (below the 48dp minWidth used elsewhere). Height stays ≥48dp. This is the deliberate trade for the user-locked "one slim row"; the row-local caps relax `minWidth` only.
- **Large pads fill available height:** Arrows/Numpad/Fn caps size by `Expanded` flex so they scale to the screen — the 64px figures above are minimums, not fixed heights. "Dramatically larger than the old ~200px strip" is the acceptance bar (user-locked).

## Screen 1 — Keyboard (full-screen swipeable pads)

### Structure (top → bottom)

```
Scaffold (kBg, resizeToAvoidBottomInset: true)
├─ AppBar: "Keyboard" 16/600 kText + ConnectionHeaderChip
├─ ReconnectingBannerSlot (D-02 house chrome)
├─ Expanded: PageView — 4 pads: Type | Arrows | Numpad | Fn
├─ HiddenTextInput (ALWAYS mounted, outside the PageView — IME connection
│   must survive page switches, Pitfall 6)
├─ Modifier chip row (persistent — visible on every pad)
└─ Bottom tab bar (56px + bottom SafeArea inset)
```

The raised system IME pushes the whole column up (`resizeToAvoidBottomInset: true`), so the chip row and tab bar stay visible above the IME on the Type pad.

### Bottom tab bar

- 4 equal `Expanded` tabs, bar height 56px, `kBg` fill, 1px `kHairline` top border.
- Tab anatomy: icon 24px above label 12/400, 4px gap, centered.
- Selected: `kAccent` icon + label + 2px `kAccent` underline at the tab's TOP edge (visually replacing the hairline segment). Unselected: `kMuted` icon + label.
- Tab tap: `hapticTick()` + animate the PageView 200ms ease to the page. Swipe settle: no extra haptic.
- Tabs are ALWAYS interactive, online or offline — they are navigation, not sends. Caps and chips carry the gating.

| Tab | Label | Icon |
|-----|-------|------|
| 1 (default) | `Type` | `Symbols.keyboard_rounded` |
| 2 | `Arrows` | `Symbols.open_with_rounded` |
| 3 | `Numpad` | `Symbols.dialpad_rounded` |
| 4 | `Fn` | `Symbols.function_rounded` |

Icon names are suggestions bound to "one clearly-evocative rounded Symbol per tab"; if a named glyph is missing from the pinned `material_symbols_icons` version, substitute the nearest rounded equivalent. Sizes/colors/placement are binding.

### Persistent modifier chip row

- The four chips (Ctrl / Alt / Shift / Win) in one row: equal `Expanded` widths, sm (8px) gaps, ≥48px tall, md (16px) horizontal padding, sm (8px) vertical padding. Visible on ALL pads — combos like Ctrl+F5, Ctrl+→, Win+D work from any pad.
- ONE `ModifierFsm` owned at screen level (not per pad). Chips reuse `ModifierChip` verbatim (rest/armed/locked states, 200ms ease).
- Wiring replicates `keyboard_panel.dart` exactly: chip tap/long-press → FSM effects → `key {code: holdCode, action: down/up}`; cap tap with armed mods → `key {action: tap, mods: modsForTap()}` then auto-reset.

### IME raise/lower contract (user-locked: IME on Type only)

- Landing on the Type pad (entry or `onPageChanged` → index 0): `imeFocusNode.requestFocus()` (post-frame on first entry).
- Leaving the Type pad (`onPageChanged` → index ≠ 0): `imeFocusNode.unfocus()` — IME lowers, the destination pad gets the full height.
- `HiddenTextInput` + `ImeDiffProducer` are UNCHANGED (KEY-01 diff path) and mounted outside the PageView so the input connection never detaches on page switches.

### Pad layouts

All pads: md (16px) content padding, sm (8px) gaps between caps, caps reuse the `_KeyCap` visual/press contract (kSurface fill, kHairline border, radius 8, pressed = accent border + face, gated = muted face). Down/up emission model (D-11 server-side autorepeat) and deferred tap+mods (D-10) carry over unmodified.

**Type pad (page 1, default):**
- System IME raised. Page content, top → bottom: `Expanded` canvas with the centered hint copy (`kKeyboardHint`, verbatim, 13/400 `#4A505C`), then ONE slim extras row docked at the page bottom.
- Slim extras row: `Esc | Tab | ← | ↑ | ↓ | →  | Del` — 7 equal `Expanded` caps, height 48px, labels 14/400, arrow icons 20px. (Row-local minWidth relaxation — see Spacing exceptions.)

**Arrows pad (page 2):**
- IME down. Top row: `Home | End | PgUp | PgDn` — 4 equal `Expanded` caps, 56px tall, labels 16/600.
- lg (24px) gap, then the large inverted-T centered in the remaining height: `↑` above `← ↓ →`. Arrow caps ≥64px square (size up with available height via flex; cap the width at ~96px so they stay finger-shaped), 28px arrow icons, sm gaps.
- Hold-to-repeat retained: press-down sends `down`, release sends `up`, Windows autorepeats (KEY-04) — identical to today.

**Numpad pad (page 3):**
- IME down. Calculator layout filling the page height:
  - Left block (flex 3): 4 equal-height rows — `7 8 9` / `4 5 6` / `1 2 3` / `0 .` (the `0` cap spans two columns of the bottom row, `.` takes the third).
  - Right block (flex 1): one `Enter` cap spanning the FULL block height (the "big Enter", user-locked).
- Digit faces 28/400 (Display); `Enter` and `.` labels 16/600. All caps ≥64px tall (rows flex to fill).
- Codes: existing `Num0`–`Num9`, `NumEnter`, `NumDot` — no new numpad codes.

**Fn pad (page 4):**
- IME down. Top: full-width `Esc` cap, 56px tall, label 16/600 (user-locked: Esc on this pad too).
- sm gap, then a 4-column × 3-row grid of `F1`…`F12` (F1–F4 / F5–F8 / F9–F12 — the physical-keyboard grouping), rows flex to fill remaining height, caps ≥64px tall, labels 16/600.

### Pad persistence

- Last-open pad persists under a NEW prefs key `keyboard.pad` (values `type` | `arrows` | `numpad` | `fn`, default `type`), following the `KeyRowGroupStore` pattern (PrefsKv seam, corrupt/unknown reads degrade to default, fire-and-forget save on change).
- `keyboard.rowGroup` stays untouched — the trackpad-docked `KeyboardPanel` (D-07, out of scope) still owns it.

### Stuck-key invariants (sacred — carried from keyboard_panel.dart)

These are behavior contracts the redesign MUST preserve; the checker/auditor should treat them as interaction states:

1. **CR-01 cap-dispose release:** switching pads disposes the outgoing page's caps (PageView default child lifecycle — do NOT add keep-alive); every disposed cap mid-hold releases its key. `allowImplicitScrolling: false`.
2. **CR-02 held-set tracking:** the screen-level owner keeps the `_heldCodes` set; `up` only sends when `remove()` succeeds (idempotent with cap-level dispose release).
3. **IN-04 always-wired releases:** a PageView horizontal drag that claims the gesture cancels the cap's tap (`onTapCancel`) — a non-deferred press still releases. Only press ENTRY is auth-gated.
4. **D-12 disconnect reset:** transition into disconnected → `ModifierFsm.disconnected()` (zero effects), held-set wiped without ups, CR-01 IME reset tick fired (no pre-disconnect text replay).
5. **Screen dispose flush:** popping the screen with keys/locked mods held on a LIVE socket flushes every owed `up` + `releaseAll()` (never into a dead/new session).

## Screen 2 — Shortcuts (new hub tile + tool screen)

### Hub tile

- New `HubTileSpec(label: 'Shortcuts', icon: Symbols.bolt_rounded)` inserted at position 3 — after Keyboard, before Media (keyboard-domain adjacency). New reading order: Trackpad, Keyboard, **Shortcuts**, Media, Apps, Clipboard, Power, Presenter, Browser (9 tiles; the odd tail renders as the existing half-width-beside-empty-slot pattern).
- Standard tile visual (kSurface, kHairline, radius 16, 32px muted icon + 16/600 label) and D-08 offline gating — no deltas.
- Opened via `HubScreen._open` so it gets `BubbleScaffold` (floating trackpad bubble + UIPI banner) centrally — the screen itself knows nothing about the bubble.

### Screen layout

```
Scaffold (kBg)
├─ AppBar: "Shortcuts" 16/600 kText + ConnectionHeaderChip
├─ ReconnectingBannerSlot
└─ SingleChildScrollView — md edge padding, xl (32px) top padding
   └─ 4 sections, lg (24px) gaps between sections:
      section header (16/600 kText) + sm gap + 2-column button grid (sm gaps)
```

### Shortcut button anatomy

- 2 columns, equal `Expanded` widths, sm (8px) horizontal + vertical gaps. Odd section tail: half-width button beside an empty slot (hub-grid pattern).
- Button: `kSurface` fill, 1px `kHairline` border, radius 12, min height 64px, 12px inner padding.
- Content: `Row[ icon 24px, 12px gap, Expanded Column(left-aligned): effect label 14/600 kText (max 2 lines, ellipsis), 2px gap, combo subtext 12/400 kMuted ]`.
- Press behavior (house `_TransportButton` pattern, press-DOWN not release): send ONE `KeyMsg(code, action: 'tap', mods: [...])` on the reliable path + `hapticTick()` + accent flash (border + icon + effect label → `kAccent`) relaxing after 100ms.
- Gated (unauthed / disconnected): icon + labels `kMuted`, border stays `kHairline`, press entry null — muted-not-red, layout stable (user-locked house pattern).
- Buttons never show optimistic result state — fire-and-forget macros, exactly like the Browser screen.
- The button SHOULD be a single reusable widget (`ShortcutButton` or similar); sharing it with the keyboard pads is optional — pads may keep the `_KeyCap` lineage since their press model (down/up hold) differs from the tap-only shortcut model.

## Wire / Keymap Vocabulary (no protocol change — user-locked)

`keymap.rs` `CLIENT_KEY_CODES` stays the single source of truth; the Dart mirror `kClientKeyCodes` extends byte-for-byte; both coverage tests (`keymap_covers_all_codes`, the Dart vocabulary test) grow in lockstep.

**New codes (terse style, matching the existing `T`/`W`/`B` router precedent):**

| New `key.code` | enigo mapping | Note |
|---|---|---|
| `A` `C` `D` `E` `F` `I` `R` `S` `V` `X` `Y` `Z` | `Key::Unicode('<lowercase>')` | Letters ride `Key::Unicode` — VkKeyScanW resolves the layout VK so Ctrl/Win chords work (existing `T`/`W` precedent) |
| `0` | `Key::Unicode('0')` | Main-row zero for Ctrl+0 zoom reset — distinct from `Num0` |
| `PrintScreen` | `Key::PrintScr` (VK_SNAPSHOT) | Both bare and Win-modified screenshot paths |

**Promoted from `ROUTER_MACRO_CODES` into `CLIENT_KEY_CODES`:** `T`, `W`, `Plus`, `Minus` — the client now emits them directly.

**Zoom code naming (discretion resolved):** reuse the existing `Plus` → `Key::Unicode('=')` and `Minus` → `Key::Unicode('-')` mappings verbatim — the `'='` resolution is the locked Pitfall-11 fix (Shift-flag VkKeyScanW drop) and Ctrl+`=` is the universal browser zoom-in chord. Do NOT introduce `Equal`.

No `SERVER_PROTO_VERSION` bump — the `key {action: tap, mods}` message shape is unchanged; only the accepted vocabulary grows (unknown codes still drop silently server-side, T-04-02).

## Component State Contract

"Gated" = chip status ≠ connected. Layout NEVER shifts between states.

**Key cap (all pads) — existing `_KeyCap` table:**

| State | Fill | Border | Face |
|-------|------|--------|------|
| Rest | `kSurface` | `kHairline` | `kText` |
| Pressed (held) | `kSurface` | `kAccent` | `kAccent` |
| Gated | `kSurface` | `kHairline` | `kMuted`, press entry null |

**Modifier chip:** rest / armed (accent border + text) / locked (solid accent fill + `kBg` text + lock glyph) / gated (muted) — existing `ModifierChip`, unchanged.

**Bottom tab:** selected (accent icon + label + 2px accent top underline) / unselected (`kMuted`) — always interactive, no gated variant.

**Shortcut button:**

| State | Fill | Border | Icon + labels |
|-------|------|--------|---------------|
| Rest | `kSurface` | `kHairline` | icon + effect label `kText`, combo `kMuted` |
| Press flash (100ms) | `kSurface` | `kAccent` | icon + effect label `kAccent`, combo `kMuted` |
| Gated | `kSurface` | `kHairline` | everything `kMuted`, press entry null |

**Disconnected:** additionally triggers the D-12 keyboard reset (chips → rest with zero effects, held-set wiped, IME reset tick). The hub tile itself follows D-08 (offline = muted label, onTap null).
