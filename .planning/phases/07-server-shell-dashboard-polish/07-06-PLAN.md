## Phase Goal (slice)

**As the** owner, **I want to** the server to live quietly in the tray with a status tooltip, a pause toggle, and quit — and to warn me loudly if the firewall is blocking it, **so that** it's a real background daemon (SRV-01 + SRV-04). This is the NOVEL winit/tray topology slice, sequenced first among shell work to retire the loop-sharing risk (RESEARCH Open Q2) before the settings window (07-08) depends on it.

<objective>
Wrap the headless `#[tokio::main]` binary in a tray-daemon shell: a dedicated `std::thread` runs a winit 0.30 event loop (`with_any_thread(true)`), creates the `tray-icon` on `StartCause::Init`, and drives tooltip (from `conn_count`), pause (existing pause seam), and quit. Wire the composition root (main.rs) to create the real channels, assemble a full `ShellCtx`, spawn the shell thread, run the firewall self-test at startup, and connect the input thread's UIPI detection to the `blocked` watch. This is the de-risking slice — it proves tray + winit loop coexist with `#[tokio::main]`; the on-demand egui settings window (07-08) then shares this loop.

Purpose: SRV-01 (tray lifecycle) + SRV-04 (startup firewall warning) + the SRV-05 server push are wired here on the proven shell thread.
Output: `shell/{mod,tray}.rs`, main.rs integration (channels/ShellCtx/spawn/firewall/input-thread blocked_tx), Explorer-restart survival.
</objective>
