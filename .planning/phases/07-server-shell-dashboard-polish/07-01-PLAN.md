## Phase Goal (slice)

**As the** owner, **I want to** have my paired phones remembered as revocable records with names, **so that** the PC can persist them across restarts, list them, and revoke any one — the foundation SRV-03 (config persistence, multi-device, revoke) is built on.

<objective>
Extend `AuthManager` (server-core, zero-Windows-deps) from an in-memory `Vec<[u8;32]>` of hashes into a persistable, revocable, named paired-device store with a change-signal — WITHOUT breaking any existing method signature (server-core must stay green after this plan alone). This is a pure server-core slice: file I/O (config.toml) lands in server-windows (07-07); this plan owns only the auth model.

Purpose: revoke (D-05), multi-device (D-04), and cross-restart persistence (D-01) all require paired state to be named records that can be seeded, enumerated, individually removed, and observed for change.
Output: additive `AuthManager` API + `PairedDevice`/`PairingResult` types + a `watch::Sender<u64>` change-signal, all unit-tested.
</objective>
