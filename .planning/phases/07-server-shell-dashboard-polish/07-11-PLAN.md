## Phase Goal (slice)

**As the** owner, **I want to** a clear, transient banner when I try to control an elevated window, **so that** I understand why nothing happened instead of thinking the app is broken (SRV-05 / D-07). This is the phone-side surface of the input.blocked push.

<objective>
Build the client surface for the `input.blocked` proto-1.3 push: park the decoded message in `connection_service.dart` (cloning the `ClipChangedMsg` arm) and expose it, then render a `UipiBanner` that slides in on a blocked event and auto-dismisses after ~4s (D-07). The wire contract (07-02) and tokens (07-09) already exist; the dashboard quick-bar (07-13) composes this banner so it appears on whatever tool screen is active.

Purpose: honest failure surfacing — the user sees a contextual advisory instead of silent input loss.
Output: connection-service parking + provider + `UipiBanner` widget + widget test.
</objective>
