## Phase Goal (slice)

**As the** owner, **I want to** the wire contract to describe an "input blocked by an elevated window" event, **so that** the PC can tell my phone honestly why a click did nothing (SRV-05) — using the exact minor-amendment discipline that shipped `vol.changed`/`apps.changed`/`clip.changed`.

<objective>
Add the `input.blocked` (proto 1.3) S→C message to BOTH codecs and a shared golden fixture, cloning the `vol.changed` precedent (07-PATTERNS SHARED-A). This is the wire-contract slice: no session push and no version bump yet (both land in 07-05, which owns session.rs); no detection and no banner yet (07-04 / 07-11). After this plan a byte-identical fixture proves Rust and Dart agree on the message shape.

Purpose: locking the wire shape first (contract-before-consumers) lets the server push (07-05) and the client banner (07-11) be built against a fixed, tested contract instead of a moving target.
Output: `InputBlockedPayload` + `Msg::InputBlocked` (Rust), `InputBlockedMsg` (Dart), one fixture, round-trip tests both sides.
</objective>
