## Phase Goal (slice)

**As the** owner, **I want to** the server to KNOW when an elevated window is silently eating my input, **so that** my phone can eventually tell me why nothing happened (SRV-05). SendInput cannot report a UIPI drop, so detection must be proactive — this plan builds that detection primitive; 07-06 wires it to the `input.blocked` push.

> Wave note: placed in Wave 2 (not 1) only because it shares `server-windows/Cargo.toml` with 07-03 (a `windows`-crate feature-flag edit) — no logical dependency on 07-03's code, just Cargo.toml serialization.

<objective>
Add proactive UIPI detection primitives to `input_thread.rs` — a pure, unit-testable integrity-level comparison predicate plus a Win32 helper that reads the foreground window's process integrity RID — WITHOUT changing `run_input_thread`'s signature or loop (07-06 threads the blocked-watch sender and calls these with debounce). Reactive detection is impossible: `SendInput` returns the injected count and `GetLastError` never reports a UIPI drop (RESEARCH Pitfall 6), so we compare the foreground window's integrity level to ours.

Purpose: isolating detection from wiring keeps server-windows compilable after this plan (the wiring that touches main.rs is 07-06) and makes the RID-comparison logic testable without any OS window.
Output: `is_blocking_il(foreground_rid, our_rid) -> bool` (pure), `foreground_integrity_rid() -> Option<u32>` (Win32), `foreground_blocked() -> bool` (helper), a unit test for the predicate.
</objective>
