<objective>
Teach the Tab Bridge extension to read the PC's bookmark tree and push it as a single
breadth-first `bm.state` snapshot, under a byte-accurate 56 KB budget, on the same debounce that
already drives the tab snapshot.

Purpose: D-06 puts the whole tree in one frame, so the frame-size discipline becomes load-bearing
rather than theoretical. The shipped budget loop measures `frame.length` — a UTF-16 code-unit
count — which is wrong for non-ASCII text by up to 4x. Tab titles are mostly ASCII so it never
fired; bookmark titles are user-curated, longer, and far more often non-ASCII across a 10x larger
node count. An oversize frame kills the ext session and silently flips the phone to the install
hint with the extension visibly running.

Explicitly in scope and NOT scope creep: fixing the existing `tabs.state` budget loop the same
way. It is the same bug, in the same function, in a file this plan already edits.

Output: the `bookmarks` permission, the caps consts, `bytesOf`, the import-storm guard, top-level
bookmark listeners, `buildBmSnapshot`, the module-level `bmUrlSet`, and both budget loops
measuring UTF-8 bytes.
</objective>

1. `const tree = await chrome.bookmarks.getTree();` inside a try/catch. On ANY failure (or when
   `chrome.bookmarks` is absent) return a sentinel meaning "unreadable": the caller must set
   `bmUrlSet = null` and send NO `bm.state` frame at all. Do NOT send an empty snapshot on failure —
   that would tell the phone "you have no bookmarks", which is a lie. With no frame ever sent, the
   server's `BookmarksState` stays `connected:false` and the phone shows the shared install hint,
   which is honest.
2. Seed a BFS queue with `tree[0].children` — root `"0"` is NEVER emitted as a node (Pitfall 5).
   BFS (level order), not DFS: a pre-order walk can exhaust the entire budget inside the first
   root's first deep subtree, leaving "Other bookmarks" and "Mobile bookmarks" absent entirely,
   which directly violates D-08. Put that rationale in a comment — it is the reason the walk order
   is load-bearing.
3. For each dequeued node build an element with exactly these keys and no others:
   `id` (the node's id), `parentId` (the node's `parentId`, defaulting to `"0"` for a root),
   `title` (the node's title or empty string, sliced to `MAX_BM_TITLE`), plus
   `folder: true` and `count: <children.length>` when `node.children !== undefined`,
   plus `locked: true` when `node.unmodifiable` is truthy. Never add a `url` key and never add an
   `icon` key. Collect `node.url` into a `Set` for the star truth (D-11) — that set never leaves the
   extension. Push `node.children` onto the queue when present.
4. Stop emitting at `MAX_BM_NODES`; every node dropped for the cap records its `parentId` in a
   `dropped` set.
5. Serialize `{t:"bm.state", p:{nodes}}` and, while `bytesOf(frame) > MAX_FRAME_BYTES`, `pop()` the

6. If `dropped` is non-empty: set `truncated: true` on every emitted node whose `id` is in

## Trust Boundaries

| Boundary | Description |

| Chrome bookmark database → extension | The owner's full browsing collection, including every URL, is readable here |
