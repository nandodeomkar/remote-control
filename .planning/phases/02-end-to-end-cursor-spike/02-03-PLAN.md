<objective>
Wire the Flutter client half of the cursor spike into a runnable end-to-end
vertical so all four Phase-02 hard-gate criteria (PAD-05) become testable on
real hardware. This plan assembles ONLY existing, already-built pieces — the
`remote_protocol` codecs (`encodeMessage`/`decodeText`/`authProof`/`hexDecode`),
`connectNoDelay` (02-02), and `MoveSender` (02-02) — plus the connective tissue
that was never built: the client handshake FSM, a `Listener`-based trackpad
screen, and the interleaved-ping latency HUD.

Purpose: The `<30ms` transport risk (the reason Phase 02 exists) remains
unretired because the two halves (02-01 server, 02-02 client seams) were never
connected. `main.dart` is a static placeholder; `MoveSender`/`connectNoDelay`
are unit-tested but never called by the app. This plan turns them into a real
app that can pair, authenticate, move the cursor, and show live latency.

Scope discipline: NO protocol change, NO server change, NO new crypto. The wire
contract is frozen (SPEC.md). Token storage is in-memory for the spike
(`flutter_secure_storage` persistence is Phase 3, per CLAUDE.md). Manual IP:port
entry replaces discovery (also Phase 3). The physical measurement (finger->cursor
lag over real WiFi) is a MANUAL human gate (see 02-04), not an agent-executable
criterion.

Output: A runnable `flutter run` app that connects to `cargo run -p
server-windows`, completes the real Phase-1 handshake, moves the Windows cursor
from finger drags, and displays live p50/p95 round-trip-under-load.
</objective>
