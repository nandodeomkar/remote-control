## Phase Goal

**As a** person controlling my PC from my phone, **I want to** see and manage my open windows and apps and move copied text between the two devices, **so that** I can switch apps, launch favorites, and share clipboard text without touching the laptop.

<objective>
Replace the no-op `StubApps` with a real `WinApps` backed by a dedicated apps OS thread — the Windows body of the Apps slice. After this plan the server actually enumerates the user's windows (Alt-Tab filtered, with icons and resolved exe paths), pushes the list live via the 06-01 `apps.changed` seam, and executes focus/close/launch with honest success/failure.

Purpose: Turns the Apps contract (06-01) into a working server capability the Flutter Apps screen (06-03) can drive end-to-end.

Output: `apps_thread.rs` (poll loop + `AppsCmd` + pure Alt-Tab filter predicate + DWM cloak check + icon extraction/PNG + exe-path resolution), `executors/apps.rs` (`WinApps`), main.rs wiring replacing the placeholder + StubApps, and the new `windows`/`png` deps.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authed client → apps.launch | An authed+paired peer can launch a program as the logged-in user |
| apps thread → wire (icons) | Server-encoded PNG bytes cross to the phone |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02 | Elevation / Tampering | `apps.launch{path}` → ShellExecuteW | mitigate | The path only ever originates from a window the server itself enumerated + resolved (D-01/D-02); WinApps launches a path string the client echoes back from `AppsSnapshot`. No user-typed paths anywhere (D-01 forbids manual entry). Scope is inherent to the feature (run a program as the logged-in owner); launches logged as lifecycle events (path is not a secret, but never logged with clipboard/PII) |
| T-06-03 | DoS | icon PNG payloads | mitigate | Fixed 32x32 icons, PNG-encoded (0.5–2 KB each), list capped ≤50 → well under the 64 KB frame cap (Pitfall 3); tungstenite enforces the cap both directions |
| T-06-13 | Tampering | HWND recycling between polls (Pattern 4) | accept | Validate-on-use (`IsWindow` on the thread + snapshot presence check in WinApps) + 500ms refresh; a same-tick recycle race is a narrow window, acceptable for a personal LAN tool (RESEARCH A6) |
| T-06-SC | Tampering | `png 0.18` + new `windows` features install | mitigate | RESEARCH Package Legitimacy Audit: `png` is the image-rs org crate, verdict OK/Approved; `windows` already in-tree. No [ASSUMED]/[SUS] packages → no blocking checkpoint required |
</threat_model>
