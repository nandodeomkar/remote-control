# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: the real trackpad gesture surface (velocity move, tap/two-finger-tap clicks, on-screen L/M/R buttons, two-finger scroll with momentum, long-press drag-lock) and the expandable keyboard panel that docks over the trackpad (hidden-IME text capture, toggleable special-key rows, sticky modifier chips, held-key autorepeat). This phase **extends the Phase 3 design system verbatim** — it does not introduce a new one. Only the NEW input surfaces are specified below; the tokens (spacing, type, color roles, motion) are inherited from `03-UI-SPEC.md` and referenced, not restated. The dashboard home + persistent quick-bar identity is Phase 7 — nothing here preempts it; the full-bleed trackpad remains the home surface (D-07).

## Spacing Scale

Inherited from `03-UI-SPEC.md` verbatim (8-point scale, multiples of 4). No new tokens. Phase-4 usage of the existing tokens:

| Token | Value | Phase-4 usage |
|-------|-------|---------------|
| xs | 4px | Key-cap internal glyph gap; gap between a modifier chip's label and its lock glyph |
| sm | 8px | Gap between adjacent key caps and between modifier chips; key-cap corner radius; group-switcher segment gap |
| md | 16px | Keyboard-panel edge padding; padding around the L/M/R button bar; trackpad-hint inset |
| lg | 24px | Vertical gap between the modifier-chip row and the special-key row inside the panel |
| xl | 32px | (unused this phase) |
| 2xl | 48px | **Minimum touch target** — every key cap, modifier chip, L/M/R button, and the panel toggle is ≥48px in its smallest tappable dimension (owner-benchmark requirement: big targets) |
| 3xl | 64px | L/M/R mouse-button bar height |

Exceptions: none. Key caps may be **wider** than 48px to fill a row evenly, but never shorter than 48px in height or width.

Source: Phase 3 scale; the 48px floor is elevated to a hard rule this phase because it is the phase's stated priority (thumb-reachability, big touch targets).

## Typography

Inherited from `03-UI-SPEC.md` verbatim — exactly 4 sizes, 2 weights (400 / 600). No new sizes or weights. Phase-4 role mapping:

| Role | Size | Weight | Line Height | Phase-4 usage |
|------|------|--------|-------------|---------------|
| Caption | 12px | 400 | 1.3 | Drag-lock indicator sub-label; group-switcher segment labels ("Nav"/"Fn"/"Num") |
| Body | 14px | 400 | 1.5 | Key-cap labels at rest (`Esc`, `Tab`, `Home`, `F1`…`F12`, numpad digits) |
| Title | 16px | 600 | 1.2 | Modifier-chip labels (`Ctrl`/`Alt`/`Shift`/`Win`) and L/M/R button labels — the glanceable state-bearing controls carry the heavier weight |
| Display | 28px | 600 | 1.2 | (unused this phase — PIN-only from Phase 3) |

Rules (carried from Phase 3): weights are 400 and 600 only; no text below 12px; single-letter L/M/R button labels and short key labels are acceptable (benchmark-app convention). Icon-only keys (arrows, backspace) carry a semantic label via `Semantics`/`Tooltip` for accessibility, not visible text.

Source: Phase 3 typography; role mapping is Claude-discretion default (user delegated exact constants per CONTEXT).

## Color

Inherited from `03-UI-SPEC.md` verbatim. **No new hex values are introduced** — the keyboard panel and key caps reuse the existing two-tone (`#0E0F12` dominant / `#16181D` secondary / `#2A2D34` hairline) so the panel reads as a continuation of the trackpad.

| Role | Value | Phase-4 usage |
|------|-------|---------------|
| Dominant (60%) | `#0E0F12` | Trackpad surface (unchanged); **keyboard panel background** (continuous with the trackpad above it); L/M/R button bar background |
| Secondary (30%) | `#16181D` fill, `#2A2D34` 1px borders | Key caps, modifier chips, and L/M/R buttons at rest; group-switcher track |
| Accent (10%) | `#4C8DFF` | Reserved list below only |
| Destructive / Error | `#FF6B6B` | **Not used this phase** — input send is fire-and-forget / queued; there are no new error surfaces (drops reuse the Phase 3 reconnecting banner) |

Text colors (neutrals, not part of the 10%):
- Primary text / key labels: `#E6E8EB`
- Muted text: `#6B7280` — disabled keys and modifier chips when not connected, unselected group-switcher segments, the resting L/M/R labels before touch

Accent `#4C8DFF` reserved for (Phase-4 additions to the Phase-3 list):
1. Modifier chip **held state** (tap-armed, until-next-key): `#16181D` fill + `#4C8DFF` 1px border + `#4C8DFF` label (outlined accent).
2. Modifier chip **locked state** (long-press lock): solid `#4C8DFF` fill + `#0E0F12` label + a small `Icons.lock` glyph. Solid-fill vs. outline is the deliberate two-level, glanceable distinction between locked and armed (D-10 "read at a glance").
3. Key cap **pressed/held** state (including a key held for autorepeat, KEY-04): `#4C8DFF` 1px border + `#4C8DFF` label while the finger is down; returns to rest on release.
4. Selected **group-switcher** segment indicator (`Nav`/`Fn`/`Num`): accent label + accent underline; unselected segments are muted.
5. L/M/R mouse-button **pressed** flash (momentary, on tap-down).
6. **Drag-lock active** indicator pill (accent-tinted, with `Icons.lock`).

Accent is NOT used for: key caps at rest, the panel background, the panel toggle at rest, borders at rest, or any decorative fill. A key/chip at rest is always `#16181D` + `#2A2D34` — accent appears only to signal an active/held/selected state.

Gated (not-connected) state: all keys, modifier chips, and L/M/R buttons render entirely at `#6B7280` on the resting `#16181D` surface and are non-interactive — matching the Phase 3 "disconnection is muted, not red" rule.

New/changed UI this phase. Files follow the existing `lib/trackpad/` layout and a new `lib/keyboard/` package. Pure logic seams (gesture classifier, diff-op computer) are listed for traceability but carry no visual contract.

| Component | File (planned) | Contract |
|-----------|----------------|----------|

The raw pointer stream now feeds a client-side gesture classifier (D-04) distinguishing move / tap / two-finger tap / two-finger scroll / long-press-drag. No new chrome on the surface itself except: the muted centered hint, the drag-lock indicator (below), and — docked at the bottom — the L/M/R button bar and the panel toggle. Header chip + reconnecting banner unchanged from Phase 3. |
| Gesture classifier | `lib/trackpad/gesture_classifier.dart` | Pure, IO-free, test-seamed FSM (handshake_fsm house style) — **no visual contract**. | L/M/R mouse buttons | `lib/trackpad/mouse_buttons.dart` | A slim 64px bar docked at the bottom edge of the trackpad surface (PAD-02). Three buttons on the `#0E0F12` bar: **L** (wide, flex 2), **M** (narrow, flex 1), **R** (wide, flex 2), sm gaps, each ≥48px tall. Rest: `#16181D` fill, `#2A2D34` 1px border, 8px radius, label 16/600 muted→primary. Tap-down: accent border flash + `HapticFeedback` tick, sends `click {left/middle/right}` on the reliable path. Visible in both trackpad-only and keyboard-open modes. Muted + inert when not connected. |
| Drag-lock indicator | inside `trackpad_screen.dart` | A small pill, top-center of the trackpad surface, shown ONLY while drag-lock is engaged (PAD-04). `#16181D` fill + `#4C8DFF` border, `Icons.lock` (accent) + label "Drag locked — tap to drop" (12/400). Fades in 150ms on engage; disappears on release. Signals the held-button state so a screen-edge drag is discoverable and dismissible. |
| Keyboard panel toggle | inside `trackpad_screen.dart` | A single circular button, bottom-right, thumb-reachable, above the L/M/R bar. `#16181D` fill + `#2A2D34` border, `Icons.keyboard` (collapsed) / `Icons.keyboard_hide` (expanded), ≥48px. | Keyboard panel | `lib/keyboard/keyboard_panel.dart` | The expandable panel over the trackpad (D-07) — NOT a separate screen. Docks at the bottom; the trackpad surface shrinks above it but stays live for cursor movement. Background `#0E0F12` (continuous with the trackpad), top hairline `#2A2D34`, md edge padding. Slides up/down 200ms ease. Contains, top→bottom: the modifier-chip row, the group switcher, and the active special-key row. ## Component States

### Modifier chip (D-10 — the glanceable sticky-modifier contract)

| State | Fill | Border | Label | Extra |
|-------|------|--------|-------|-------|
| Rest | `#16181D` | `#2A2D34` 1px | `#E6E8EB` 16/600 | — |
| Armed (tap — held until next key) | `#16181D` | `#4C8DFF` 1px | `#4C8DFF` | — |
| Locked (long-press) | `#4C8DFF` solid | none | `#0E0F12` | `Icons.lock` 16px, `#0E0F12`, xs gap after label |
| Disabled (not connected) | `#16181D` | `#2A2D34` 1px | `#6B7280` | non-interactive |

Transitions animate 200ms ease (matches the Phase-3 header-chip color ease). Solid-fill (locked) vs. outline (armed) is the deliberate two-level read required by D-10. Multiple chips may be armed/locked simultaneously (chording); each shows its own state independently. On sending a combo, armed chips auto-reset to Rest (200ms); locked chips stay Locked until tapped off. **All chips reset to Rest on disconnect** (D-12, client-side, layered on the CONN-07 server release-all).

### Special key cap (KEY-02, KEY-04)

| State | Border | Label | Notes |
|-------|--------|-------|-------|
| Rest | `#2A2D34` 1px | `#E6E8EB` 14/400 | on `#16181D` fill |
| Pressed / held (autorepeat) | `#4C8DFF` 1px | `#4C8DFF` | held while finger is down; on press-and-hold, `key {action: down}` is sent and the cap stays accent-bordered until release sends `key {action: up}` (D-11 server-side autorepeat) |
| Disabled (not connected) | `#2A2D34` 1px | `#6B7280` | non-interactive |

`HapticFeedback` tick fires on every key-down (press), not on release.

### L/M/R mouse button (PAD-02)

| State | Border | Label | Notes |
|-------|--------|-------|-------|

| Pressed | `#4C8DFF` 1px flash | `#4C8DFF` | momentary; `HapticFeedback` tick; sends `click` |
| Disabled (not connected) | `#2A2D34` 1px | `#6B7280` | non-interactive |

| Nav-cluster keys | "Esc" / "Tab" / "Home" / "End" / "PgUp" / "PgDn" / "Del" + arrow icons (tooltips "Up"/"Down"/"Left"/"Right") |
| Fn keys | "F1" … "F12" |
| Numpad keys | "0"–"9", ".", "Enter" |

Empty states: none new — the keyboard panel is a control surface, not a data list; the trackpad's "Not connected" is the only gated/empty message (Phase 3).

Error states: none new — input send is fire-and-forget (moves/scroll, volatile) or queued (clicks/keys/text, reliable, flushed on auth). A connection drop is surfaced by the inherited Phase-3 reconnecting banner + the muted/gated controls; no new error dialogs or inline error copy are introduced this phase.

Destructive actions this phase: **none.** Sticky-modifier combos the owner explicitly sends (e.g. `Ctrl+Alt+Del`, `Win+D`) are user-invoked keystrokes, not app-destructive actions, and get **no confirmation dialog** — a confirmation would defeat the purpose of a keyboard. (Double-confirmed power actions are Phase 5.)

## Interaction Contract

- **Gesture classification is client-side (D-04):** one classifier off the raw `Listener` stream distinguishes single-finger move (velocity acceleration, PAD-01), tap → `click left`, two-finger tap → `click right`, two-finger scroll → `0x02` scroll frames with momentum + instant touch-stop (PAD-03), and long-press (~250ms, D-05) → drag-lock (PAD-04). Exact thresholds/curves are on-device tuning (D-06), landed as tunable constants in one place, not hardcoded finals.
- **Hot-path invariant (carried from Phase 2/3):** `onPointerMove` → `service.sendMove` stays a boolean-gated, fire-and-forget route with zero UI rebuild and zero allocation. Clicks, scroll, drag, and key sends go through the reliable path but must NOT trigger a rebuild of the trackpad surface or the header chip.
- **Sensitivity (D-05):** a shared_preferences (non-secret) sensitivity setting tunes the acceleration curve; the move path applies it without touching the hot-path invariant.
- **Haptic tick:** `HapticFeedback` fires on every click (tap, two-finger tap, L/M/R button), key-down, and drag-lock engage (per project stack). This phase INTRODUCES input haptics; a global haptics toggle is Phase 7 (UI-02) — until then, ticks default on.
- **Keyboard panel is a toggle over the trackpad (D-07):** expanding docks the panel at the bottom, shrinks (never hides) the trackpad, and focuses the hidden text input to raise the system IME. Collapsing blurs the field and lowers the IME. The trackpad stays live for cursor movement while the panel is open.
- **Typing rides the system IME (D-08):** all text (autocomplete revisions, emoji, backspace) flows through the offscreen `TextField` → diff-op computer → `text` messages; the app never renders its own alphanumeric keyboard. The special-key rows and modifier chips are the ONLY app-drawn keys.
- **Sticky modifiers (D-10):** tap arms a modifier (visible held state, auto-resets after the next non-modifier key sends a combo); long-press locks it (stays until tapped off); modifiers chord. State must read at a glance (solid=locked vs. outline=armed).
- **Autorepeat (D-11):** holding an app-drawn key sends `key {action: down}` then `key {action: up}` on release — server-side hold/repeat, never client tap-spam. The cap shows the held (accent) state throughout.
- **Reset on disconnect (D-12):** all armed/locked modifier state and any held key clear client-side on disconnect, layered on the shipped CONN-07 server release-all — no phantom input survives a mid-combo drop.
- **Touch targets:** every key cap, modifier chip, L/M/R button, group-switcher segment, and the panel toggle has a ≥48px hit area (phase priority: big, thumb-reachable targets).
- **Motion budget:** keyboard panel slide 200ms ease; modifier/key state color 200ms ease (matches the Phase-3 chip); drag-lock indicator fade 150ms; L/M/R and key press flash is immediate (no easing). Nothing else animates.

Out of UI scope (server/implementation, noted for the planner): the D-01/D-03 absolute-injection normalization math (relative→`Coordinate::Abs`, virtual-desktop vs. primary-monitor coordinate mapping) is a server-windows concern with no visual contract; the UI only supplies the raw deltas it already sends.
