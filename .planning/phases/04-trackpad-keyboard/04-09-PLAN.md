04-VERIFICATION.md's Gaps Summary ("WR-04 (scroll halving) touches PAD-03 feel
and is worth folding into the same gap-closure plan"): `_emitScroll`
(gesture_classifier.dart:457-467) divides every delta by a CONSTANT 2 on the
assumption that two pointers are down and only one moves per event. Valid while
both fingers are down — but in `_Phase.scrolling`, when the first finger lifts,
`onPointerUp` returns `const []` and stays in `scrolling` because
`_pointers.isNotEmpty` (line 398). The remaining single finger keeps streaming
through `_emitScroll` still halved: the scroll rate abruptly drops to half the
finger's travel mid-gesture, and the fling seed built from those halved samples
is half-strength too. The same halving hits the `tapPending2 → scrolling`
transition (line 347-349) when only one tracked finger remains.

Fix (04-REVIEW.md WR-04 reference sketch): scale by the LIVE tracked-pointer
count — `final n = _pointers.length;` — instead of the constant 2. n is
guaranteed >= 1 because `_emitScroll` only runs from a tracked pointer's move
(`_pointers[pointer] != null` at onPointerMove entry). While both fingers are
down n == 2 and behavior is byte-identical, so the STATE.md Phase-04-03 logged
decision ("ScrollIntent carries delta/2 per move event — per-event average of
the two pointers' deltas") keeps its intent: the divisor IS the average across
live pointers; the constant just stops lying when one finger lifts. Per D-04
the classifier stays a pure IO-free FSM (this is a two-line arithmetic change +
doc updates); per D-06 no new constant lands in tuning.dart — n is live state,
not a tunable threshold; per D-05 this directly serves the "at least as good as
Remote Mouse" scroll-feel benchmark the end-of-phase gate measures.

Scope guard: WR-01/WR-02 (connection-layer dial races) and WR-03 (prefs load
race) are OUTSIDE this phase's must-haves per the verifier and are NOT touched
here.

mid-scroll must not cut the scroll rate in half — a real trackpad tracks the
finger that is still moving.
