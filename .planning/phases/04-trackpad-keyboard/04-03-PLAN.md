<objective>
Build the pure client logic of the trackpad slice: the gesture classifier FSM
(D-04 — move / tap / two-finger tap / two-finger scroll / long-press drag with
drag-lock), the velocity acceleration curve with a sensitivity multiplier
(PAD-01, D-05), the ONE tunable-constants file (D-06), and the missing volatile
`sendScroll` on ConnectionService (RESEARCH Open Q4, PAD-03). All of it is
IO-free and unit-tested without a device, in the reconnect_fsm/handshake_fsm
house style.

## Phase Goal

**As a** laptop owner, **I want to** use my phone as a precise mouse and full
keyboard for my Windows laptop, **so that** it replaces a real trackpad and
keyboard — not a toy.

_Slice framing:_ First half of the trackpad vertical slice (04-04 wires it into
the screen for the end-to-end gesture set). This plan is the Wave-0
failing-tests-first step for PAD-01..04: the classifier and curve are the exact
logic the on-device feel depends on, proven deterministic before any widget
exists. Runs in Wave 1 parallel to the server plan 04-01 (zero file overlap).

Purpose: Deterministic, tunable gesture/feel logic with every constant in one
place so D-06 on-device tuning is a constants edit, not a refactor.
Output: `GestureClassifier` + `GestureIntent` family, `accelGain`, `tuning.dart`,
`ConnectionService.sendScroll`, and their unit tests.
</objective>
