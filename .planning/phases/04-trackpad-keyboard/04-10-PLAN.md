## Phase Goal

**As a** laptop owner, **I want to** every held key to auto-release when my phone silently drops off WiFi mid-keypress, **so that** no phantom Shift/Ctrl/Win stays held on my PC until a TCP timeout minutes later.

<objective>
Close the single MAJOR gap from 04-UAT.md (Test 5): an abrupt WiFi kill while a locked modifier is physically held leaves the key held on the PC indefinitely.

Root cause (confirmed by code read): the CONN-07 `release_all` at the end of `run_session` (session.rs) is straight-line code after the read loop, and the loop only exits when `stream.next()` yields `None`/`Err`. A half-open TCP connection (abrupt WiFi loss — no FIN, no RST) never yields either, and `run_session`'s `select!` has NO liveness branch: no application ping deadline, no idle timeout, no TCP keepalive. Held input survives until the OS TCP stack gives up (minutes+). All graceful teardown paths clean up correctly — which is exactly why the 5/5 automated verification passed while on-device UAT failed.

Fix: add a liveness deadline branch to `run_session`'s `select!` — track the last-inbound-frame `Instant`, and when the silence exceeds `LIVENESS_TIMEOUT`, `break 'read` so the EXISTING unskippable CONN-07 cleanup fires. Server-core only; zero wire-protocol, client, or executor changes. This is the server half that D-12 layers on (client-side chip reset already ships; CONN-07 release_all is the ground truth this plan makes reachable under half-open loss).

Purpose: restores phase-4 success criterion "reset safely on disconnect" (KEY-04 / SC5 / threat class T-04-04) under abrupt network loss, the last open UAT gap.
Output: liveness-hardened `run_session` + a paused-clock socket-level regression test.
</objective>
