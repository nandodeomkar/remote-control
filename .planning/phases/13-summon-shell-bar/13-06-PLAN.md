<objective>
Make the one place in the app with a second back handler resolve exactly one thing per
gesture — by predicate, never by ordering.

Purpose: `browser_screen.dart` already carries a back handler for bookmark folders. When
a raised surface adds a second handler to the same route, the framework fires **both**,
in an order that is not a contract, with no veto and no "handled" return. A latch or an
ordering assumption works today and breaks silently the first time the set's iteration
order shifts. The fix is two mutually-exclusive predicates over one shared state.
Output: the predicate guard in `browser_screen.dart` and
`test/browser/browser_back_priority_test.dart`.
</objective>

<assumption_delta_decision>
**Signal:** `pluralization` — the phase scope introduces a *second* back handler on a route
that has had exactly one, and the ROADMAP note states that multiple handlers in one subtree
combine rather than compose.

**The noun that is now primary:** the **back-gesture decision**, not the handler. Until this
phase, "one handler per route" and "one decision per gesture" were the same statement, so the
handler was the identity. With N+1 handlers on the Browser route they diverge, and the
framework guarantees only that every handler runs — never which one, never how many act.

**Decision: promote.** The general representation — one decision per gesture, computed from
one shared piece of shell state — becomes primary, and the individual handler is demoted to a
voter that must independently prove the decision is its own before acting. Milestone research
recorded the old rule as "keep exactly one handler at the summon host"; that rule is not
satisfiable (the browser's handler already exists and the guard is per-route), and correcting
it to "exactly one *decision*" is this promotion. Rationale: the alternative — keeping the old
"first handler wins" identity and adding a consumed latch — encodes an iteration order that is
explicitly not part of the set's contract and re-registers on every route change.

**Invariant test (accepted):** Task 2's three-back sequence is the encoded invariant. It fails
if either handler ever becomes order-dependent, and it is the reason this plan exists as its
own plan rather than a line inside the browser's own future work.
</assumption_delta_decision>
