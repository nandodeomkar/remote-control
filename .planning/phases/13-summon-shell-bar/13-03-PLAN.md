  <action>
    Add a second `AnimationController` to the shell `State`: `_swap`, with
    `duration: kSummonSwapDuration` and an initial `value: 1`.

    **The two lerp endpoints are kinds, not sizes.** The `State` carries exactly two new surface
    fields — `_fromKind` and `_toKind`, both typed `SummonSurfaceKind` — and stores nothing else
    about the surface's size. Inside `build`, and on every build, resolve both endpoints against the
    `available` read from the ancestor query on that same frame:
    `summonSurfaceHeight(_fromKind, available)` and `summonSurfaceHeight(_toKind, available)`, then
    lerp between them curved by `Curves.easeOut` over `_swap.value`. That is how the surface resizes
    to the other surface's height while staying up.

    Do not cache either endpoint as a dp figure in a `State` field, at raise time, at swap time, or
    anywhere else. Plan 13-02 deliberately made the rendered height a build-time derivation of the
    live metrics so that an IME inset change retargets the surface on the very next frame; a cached
    number reintroduces exactly the snapshot RESEARCH §5 files as an anti-pattern. The damage is
    worst in the **resting** case: with `_swap.value` sitting at 1 the rendered height would be a
    frozen figure that no longer tracks `available` at all, and plan 13-04 Task 2's F4 discriminator
    — which raises a surface, changes only the IME inset, and pumps one frame — goes red. If F4 goes
    red after this task lands, the defect is here; do not touch the test.

    The three transitions, exactly:

    - **Raise** — set `_fromKind` and `_toKind` both to the raised kind, `_swap.value = 1`, then
      forward the raise controller. Both endpoints resolve through the same derivation so the lerp
      is an identity — but it is still evaluated in `build`, so the resting surface keeps tracking
      the live `available`.
    - **Lower** — reverse the raise controller from its live value. No queue, no input lockout;
      this is the framework default and the owner left it to discretion. A reverse from a
      half-raised surface settles in roughly half the lower duration because the controller scales
      by the remaining distance.
    - **Swap** — `_fromKind` = the kind currently showing, `_toKind` = the other kind, then
      `_swap.forward(from: 0)`. The raise controller is **untouched and stays at 1**. This is one
      motion, not a 150ms lower followed by a 200ms raise, and there must be no lower-then-raise
      anywhere in the code path. When the swap settles, collapse both fields to the kind now showing
      and put `_swap.value` back to 1, so there is exactly one resting representation.

    Mid-swap there are exactly two taps to serve and they are **different requests**. A tap on the
    **origin** icon — the kind the swap started from — is a swap back; there are only two kinds, so
    serve it by reversing `_swap` from its live value rather than by reassigning the endpoints,
    which keeps the motion continuous without ever needing to capture a size mid-flight. A tap on
    the **destination** icon is not a swap at all: under D-13-10 the showing surface's own icon
    lowers it, and by then the shell is already committed to the destination kind. Serve it as a
    lower — reverse the raise controller from its live value immediately and let `_swap` run on to
    completion underneath. Do not cancel the swap and do not hold the lower until the swap finishes:
    cancelling snaps the rendered height on the tap frame, and holding it is exactly the input
    lockout this plan refuses everywhere else. The seam accounting stays exact across this pair —
    the swap edge already reported the origin kind when the swap started, and this lower reports the
    destination kind once, so each surface that leaves the screen reports exactly once and Phase 15
    releases each surface's modifiers exactly once.

    Wire the dismiss seam. `SummonShellController.onSurfaceDismissed` must be invoked with the
    **outgoing** surface kind from **both** the lower path and the swap path, through exactly one
    call expression each, and its doc comment must state that in one sentence. Phase 14 wires the
    trackpad's drag-lock flush and keep-awake release to this seam; Phase 15 wires the keyboard's
    modifier release to it. If this plan ships two unrelated call sites, Phase 15 will wire to one
    of them and every swap will leave a modifier physically held on the PC with no chip on screen
    to release it. Add a test-visible hook so a widget test can observe the seam firing on both
    edges without needing a surface to exist.

    Curves: `Curves.easeOut` in, `Curves.easeIn` out as the raise controller's reverse curve, and
    `Curves.easeOut` on the swap height lerp. No new curve type — enter decelerates, exit
    accelerates, and that is already the house vocabulary. Do not add a reduced-motion branch: a
    200/150ms translate with no parallax, scale, blur or opacity is already inside every
    reduced-motion guideline, and a conditional path would double the timing surface MOT-01 has to
    pin. Record that as a comment so it is visibly a decision.

    Do not introduce any new animation primitive — no shimmer, skeleton, scrim fade, bounce,
    spring, scale, rotation, or cross-fade between the two surfaces' content.
