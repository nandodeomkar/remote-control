## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server authFail verdicts → client retry engine | Untrusted-timing input that drives retry/stop decisions |
| Beacon sightings → backoff short-circuit | Unauthenticated UDP influences WHEN the client dials |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Denial of Service | server lockout counters | mitigate | Auth-stop policy: authRejected NEVER schedules a retry — retrying badMac would hammer the server's global 20-attempt cap (RESEARCH anti-pattern; D-05 lock). Asserted by "NO StartBackoffEffect for any authRejected reason" test |
| T-03-06 | Spoofing | beaconSighted input | mitigate | A spoofed beacon can only redirect a CONNECT ATTEMPT — the dial leads into challenge-response where a rogue server learns nothing (SPEC §4); FSM additionally ignores beacons whose guid ≠ current target (tested) |
| T-03-07 | Tampering | queued reliable frames | mitigate | Queue bounded at 10 with overflow drop (design spec §8) — no unbounded memory growth during long outages |
| T-03-08 | Information Disclosure | FSM state objects | mitigate | DeviceTarget/effects carry key/host/port only — no token field anywhere in this file (token stays in DeviceStore/driver; secrets-discipline comment in the header) |
