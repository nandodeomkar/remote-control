<objective>
Client half of discovery (CONN-01): a strict fixture-tested beacon decoder, a RawDatagramSocket listener with MulticastLock insurance for the owner's Xiaomi/HyperOS device (carried STATE concern), and the D-10 cleartext swap (scoped network-security-config replacing the app-wide manifest flag). Ends with the phase's EARLIEST on-device checkpoint — RESEARCH Pitfall 2 mandates beacon reception be verified on real hardware FIRST, because emulators cannot receive LAN broadcast and OEM filtering is device-dependent.

Android's network-security-config cannot express IP ranges/CIDR (RESEARCH finding 2), so the XML keeps base-config cleartext permitted and the real "LAN ranges only" scoping is the code-level private-range guard shipped in ConnectionService (03-05). This plan documents that split in the XML comment.

Purpose: the device list (03-06) is only as good as beacon reception on the one physical device that matters; finding a reception problem now leaves the whole phase to adapt (manual IP + remembered devices are the designed fallbacks).
Output: beacon.dart, beacon_listener.dart, multicast_lock.dart, beacon smoke entrypoint, MainActivity MethodChannel, manifest + XML swap, fixture-driven beacon_test.dart.
</objective>

**As a** phone owner, **I want to** have my phone find the PC on the LAN, pair once with a PIN, and from then on connect and recover silently, **so that** connectivity is a solved problem for every later screen.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN → UDP :17778 listener | Unauthenticated datagrams from ANY LAN host enter the app |
| App ↔ Android platform (MethodChannel) | MulticastLock acquire/release |
| App → network (cleartext policy) | ws:// permitted app-wide at XML level until the 03-05 code guard |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Tampering / DoS | beacon_listener input path | mitigate | 512-byte cap BEFORE parse, total parse (no throw escapes), silent drop of malformed frames (ASVS V5); flood produces no unbounded state (dedup/debounce lands in the 03-06 list store) |
| T-03-13 | Spoofing | forged beacon (rogue server advertises a paired GUID) | mitigate | A beacon can only cause a CONNECT ATTEMPT; challenge-response (existing) means a rogue endpoint receives an HMAC over ITS nonce — useless for replay (SPEC §4); beacon NEVER triggers sending secrets |
| T-03-14 | Information Disclosure | cleartext ws:// window between XML swap and 03-05 guard | accept (transient) | base-config cleartext is the documented Android limitation (no CIDR support); the RFC1918 code guard ships next plan; TLS itself is an explicit v1 non-goal (CONTEXT deferred) |
| T-03-15 | Denial of Service | MulticastLock battery drain | mitigate | Lock held only while the listener runs; stop() releases deterministically (Pitfall 8); 03-06/03-07 scope listening to list-visible + backoff states |
</threat_model>
