## Phase Goal

**As a** phone owner, **I want to** have my phone find the PC on the LAN, pair once with a PIN, and from then on connect and recover silently, **so that** connectivity is a solved problem for every later screen.

(Derived verbatim from the ROADMAP Phase 3 Goal line. This plan delivers the visible "finds the PC" and "pairs once with a PIN" experience.)

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-21 | Spoofing | device rows from forged beacons | mitigate | A forged row can only trigger a connect attempt into challenge-response (03-05 T-03-17); paired rows connect via stored-token auth which a rogue endpoint cannot pass — the user sees a failed connect, not a compromised session |
| T-03-22 | Denial of Service | beacon flood → list churn | mitigate | GUID-keyed merge + equal-list no-op behavior (Task 1) bounds state to distinct GUIDs and prevents render thrash |
| T-03-23 | Information Disclosure | PIN handling in the sheet | mitigate | PIN goes only to service.feedPin (→ wire per SPEC); never logged, never in copy strings; field cleared when the sheet closes |
| T-03-24 | Information Disclosure | error rendering | mitigate | pairingErrorCopy whitelists reasons — raw enums/exception strings never reach the user (UI-SPEC tone contract; negative widget assertion) |
</threat_model>
