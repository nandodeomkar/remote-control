# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: device list screen (phase home), PIN pairing flow, reconnecting banner, connection header (status + latency chip, replaces the debug HUD), manual IP:port entry sheet. The dashboard home identity is Phase 7 — nothing in this contract defines dashboard visuals; Phase 3 screens stay minimal and must not preempt the Phase 7 identity.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon–text gaps, chip internal gaps, status-dot gap |
| sm | 8px | Compact element spacing, chip padding vertical, banner internal spacing |
| md | 16px | Default screen edge padding, list-tile horizontal padding, gaps between form fields |
| lg | 24px | Section padding (empty state block, sheet top padding) |
| xl | 32px | Layout gaps (empty-state icon to heading) |
| 2xl | 48px | Minimum touch target (Android Material) — buttons, list rows never shorter |
| 3xl | 64px | Device list row height |

Exceptions: none. (Android's 48px minimum touch target is already on-scale.)

Source: default 8-point scale; 12px chip horizontal padding from the Phase 2 HUD is retired with the HUD widget — the new header chip uses sm/xs.

## Typography

Exactly 4 sizes, 2 weights.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Caption | 12px | 400 | 1.3 | Latency figure in header chip (tabular figures), device IP/last-seen metadata, banner sub-copy |
| Body | 14px | 400 | 1.5 | Error copy, empty-state body, sheet field labels, button labels |
| Title | 16px | 600 | 1.2 | Device name in list rows, screen/app-bar title ("Devices"), sheet headings, empty-state heading |
| Display | 28px | 600 | 1.2 | PIN entry digits only (with `letterSpacing: 8` and tabular figures) |

Rules:
- Weights are 400 (regular) and 600 (semibold, `FontWeight.w600`) — no other weights.
- No text below 12px anywhere.
- Numeric readouts (latency ms, PIN, countdown seconds) always use tabular figures so they don't jitter.

Source: sizes derived from existing code (12px HUD text, w600 status) + Material dark defaults; declared as defaults (user delegated).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0E0F12` | Scaffold background, trackpad surface (locked: UI-02, `main.dart`) |
| Secondary (30%) | `#16181D` surfaces, `#2A2D34` borders/dividers | Device list rows/cards, bottom sheets, banner background, header chip fill (`#2A2D34` border carried from Phase 2 HUD) |
| Accent (10%) | `#4C8DFF` | Reserved list below only |
| Destructive / Error | `#FF6B6B` | Error text (PIN failures, connect failures, auth-rejected explanation), lockout countdown (carried from Phase 2) |

Text colors (neutrals, not part of the 10%):
- Primary text: `#E6E8EB`
- Muted text: `#6B7280` (device metadata, offline/grayed device rows, disconnected state, empty-state body, disabled)

Status semantics (state colors, used ONLY in the header chip dot/text and reconnecting banner icon):
- Connected: `#4C8DFF` (accent doubles as the connected color — matches the Phase 2 HUD)
- Reconnecting: `#E8A33D` (amber — banner icon + chip while in backoff)
- Disconnected / offline: `#6B7280` (muted, not red — disconnection is a normal state, not an error)

Accent `#4C8DFF` reserved for:
1. Primary CTA buttons (`FilledButton`): Connect / Pair / Retry now
2. Connected status dot + status text in the header chip
3. Focused text-field border/label (Material focus color from the seed)
4. The currently-connected device row's leading icon (single row, at most one)

Accent is NOT used for: list-row backgrounds, borders, headings, icons at rest, the "Connect by IP" secondary affordance (that is a `TextButton` in muted/primary text with no fill).

Grayed remembered-offline device rows: entire row content at `#6B7280` (icon, name, metadata) on the same `#16181D` surface — no opacity fade on the surface itself, so rows stay legible.

## Component States

### Header chip (CONN-06 — the D-04 status contract)

| State | Dot/text color | Status word | Latency |
|-------|---------------|-------------|---------|
| Connected (authed) | `#4C8DFF` | Connected | `· {p50} ms` (tabular, 500ms throttle) |
| Reconnecting (backoff/connecting) | `#E8A33D` | Reconnecting | hidden |
| Disconnected (idle, no target) | `#6B7280` | Disconnected | hidden |

Color transitions animate 200ms ease; no other motion in the chip. Latency shows `--` for the first seconds after auth until the probe has samples.

### Device list row

| State | Treatment |
|-------|-----------|
| Discovered + paired | Full-color row, metadata `{ip} · paired`; tap → silent connect (D-02) |
| Discovered + unpaired | Full-color row, metadata `{ip}`; tap → PIN pairing sheet |
| Remembered, not discovered | All content `#6B7280`, metadata `last seen at {ip:port}`; tap → connect attempt to last-known address |
| Currently connected | Leading icon accent `#4C8DFF`, metadata `{ip} · connected` |

Eviction to grayed after ~3 missed beacon intervals (6–8s, RESEARCH) — rows never blink per-packet.

## Copywriting Contract

Tone: plain, device-owner-directed, no jargon, no exclamation marks. Every error names the problem AND the next step. Never expose raw enum values (`badMac`, `noPairing`) or exception strings to the user.

| Element | Copy |
|---------|------|
| Primary CTA (pairing sheet) | "Pair" |
| Primary CTA (Connect-by-IP sheet) | "Connect" |
| Secondary affordance (device list) | "Connect by IP" |
| Banner action | "Retry now" |
| Empty state heading | "Looking for your PC…" |
| Empty state body | "Start the Remote Control server on your PC and make sure both devices are on the same WiFi. Or connect by IP below." |
| PIN sheet body | "Enter the 6-digit PIN shown on your PC" |
| Error — wrong PIN (`pinInvalid`) | "Wrong PIN — {attemptsRemaining} attempts left" (singular: "1 attempt left") |
| Error — PIN expired (`pinExpired`) | "That PIN expired — check your PC for a new one" |
| Error — locked out (`lockedOut`) | "Too many attempts — try again in {retryAfterSecs}s" (live countdown, tabular figures) |
| Error — revoked/stale token (`noPairing`/`badMac`) | "This PC no longer recognizes this phone — pair again" (locked verbatim by D-05) |
| Error — version mismatch (`err versionMismatch`) | "This phone and the PC server need matching versions — update both, then try again" |
| Error — beacon seen but connect timed out | "PC found but connection blocked — check Windows Firewall on your PC" (locked by RESEARCH CONN-05) |
| Error — connect failed (generic transport, manual entry) | "Couldn't reach {ip}:{port} — check the address and that the server is running" |
| Error — invalid manual input | "Enter a valid IP address and port" |
| Error — non-private address (RFC1918 guard) | "Only local network addresses work (like 192.168.x.x)" |
| Reconnecting banner | "Reconnecting…" |
| Trackpad hint (authed) | "Drag to move the cursor" (existing) |
| Trackpad hint (not authed) | "Not connected" |

Destructive actions this phase: **none.** (Device revoke is Phase 7 server-side; token clearing on `noPairing` is automatic and surfaced via the pair-again explanation, not a confirmation.) No confirmation dialogs are introduced this phase.

## Interaction Contract

- **Launch (D-01):** silent auto-reconnect attempt to last device — no splash spinner takeover; land on the device list immediately with the header chip showing Reconnecting; on success, chip flips Connected (navigation to trackpad only on explicit user tap — the device list is home this phase).
- **Reconnect is never modal (D-04):** the banner + gated inputs are the entire drop UX. No blocking dialogs, no full-screen "connection lost" states.
- **Auth failure stops retry (D-05):** on `noPairing`/`badMac` the banner is replaced by the pairing sheet (or device list with the explanation as an inline error row) — never a silent retry loop.
- **Touch targets:** every tappable element ≥48px hit area (rows are 64px; TextButtons get `minimumSize: Size(48, 48)`).
- **Motion budget:** chip color 200ms ease; sheets use default Material bottom-sheet transition; banner slides in 150ms. Nothing else animates. No haptics this phase (haptics toggle is Phase 7, UI-02).
- **Hot-path invariant (carried from Phase 2):** header chip and banner read connection state on throttled providers; the pointer-move path never triggers a rebuild of either.
- **Keyboard:** PIN and IP fields use numeric keyboards; PIN sheet auto-focuses its field on open; "Pair" submits on keyboard done.
